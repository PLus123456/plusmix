## 结论速览

- **菜单逻辑**：参考软件的规则很一致——每个东西就近有齿轮（设置），按钮主体直接干活，右侧小箭头弹快捷菜单，底栏菜单一律朝上开。我们的功能大多都有，但入口几乎全在 mac 菜单栏：主窗口缺工具条、缺齿轮、缺小箭头；转场是"一个按钮 = 一种效果"而不是"四个可配置按钮"；底栏菜单往窗口外弹。大半是 W2-B 写了"留给 W3-E"、而 W3-E 的 prompt 没列的那批入口（01 §2）。合并成 130 条改动，P0 8 条：底栏弹出朝上、录制 / 推流停止前确认、效果链先标"尚未生效"、推流 ⚙ 与 ▴（单路起停）、转场按钮改"转场 1–4"可配置槽（要一份契约提案）。
- **功能缺口**：v1 规格答应了但没做完的 14 条（转场"只选不执行"、音频效果生效、推流单路起停与状态、Bus A / B 出口、tally 服务……）；规格没提、建议补进的 55 条（防睡眠、界面内提醒、录制时长、界面锁、音频文件输入、推流预设、纯色 / 彩条、网络流输入……）；后续方案已有章节的 22 组；不做的 38 行。
- **顺带查出的缺陷 63 条**：最重的是音频效果链"界面能调、声音不变"（S1），一步操作就停掉直播且不确认（5 条，定级待用户定，04 Q68），起不来的推流路让"推流"按钮变成全停，快捷键编辑器把"其他命令"静默存成 Cut，Bus A / B 没有出口、2 声道设备上耳机没声。
- **目视检查**：两处点名问题都找到根因并在临时拷贝里做了改法原型、实测通过——转场列没对齐的主因是 `stack.alignment = .width`（NSStackView 不支持这个值）；"超出边框"的是底栏"外部输出"菜单（伸出窗口 25 pt，子菜单 228 pt）和"叠加…"弹出层（最多伸出 318 pt、内容被裁）。另记 32 条目视问题。

## 资料与引用规则

- **参考截图不入库**：在用户本机 /Users/plus/plusmix/vmix-28-guide/（main checkout 根下，未跟踪）；文中"图 NNN"= 该目录 figures/fig-NNN.png，与其中 截图索引.csv 的图号一致。设计方案 §0：竞品的截图是作品，不能进产品，也不放进这个 Apache-2.0 仓库。建议把这个目录加进 .gitignore，或挪出仓库目录（.gitignore 归 P0 / 检查点）。
- **截图时的值不等于出厂默认**：那台机器被用户改过（分类起过名、加过快捷键），文中凡是参考软件的"默认"都应理解为"截图时的值"。截图里的灰字也不代表禁用（中文 Windows 上不含空格的文字会渲染成灰色衬线字，附录 核对-VF2 §5）。
- **早先的界面稿**：docs/spec/ui-mock/vMix for Mac.dc.html，是产品方当时想要的样子；文中"界面稿 L行号"指它。
- **借逻辑，不借文案**：参考软件的标签只在文档里当证据、放引号里；给 App 的文案一律是我们自己的说法（设计方案 §1.1，铁律 6）。docs/ 不在 `make lint` 的禁词扫描范围内（scripts/lint-rules.sh 的说明），所以文档里可以写竞品名；代码和界面不行。
- **我们 App 的截图**（img/）在测试宿主模式下拍：空节目 + 6 路合成测试源，不含任何用户数据。
