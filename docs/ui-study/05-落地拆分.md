# 05 落地拆分

把 [01a 改动总表](01a-改动总表.md) 的 130 条、[02 功能缺口](02-功能缺口.md) 的缺陷和 [03 目视检查](03-目视检查.md) 的两处点名问题，拆成可以按仓库规矩开工的工作包：每包只动一个归属目录，注明依赖、要不要契约提案、建议补的用例。**本页是建议**，会话怎么开、prompt 谁写，等用户在 [04 待拍板](04-待拍板.md) 定了再落。

## 0. 顺序原则

1. **先止血**：界面说谎（效果链不生效、容器选了没用）、一步就停直播（X01–X05）、用户点名的两处目视问题。都不改契约、S 级为主，0.1.0 候选能收（G5 还卡在 8 小时复验和签名账号，reports/G5.md）。
2. **再改主窗口骨架**：工具条、齿轮、底栏三段式、格子按钮、菜单栏重排——不改契约，0.1.x。
3. **契约提案批了再做**：转场槽、FTB 时长、文件播放控制、推流统计字段。
4. **新功能**按 02 第 3、4 节进后续方案排期，不在这一轮。

## 5. 会话怎么开（待用户定）

仓库的规矩是"每个会话 = docs/plan/prompts/ 里的一个 prompt 文件"，续做 prompt 一般由检查点会话写（docs/OWNERSHIP.md 补充规则 6）。本调研会话没有写 prompt 文件，也没有写契约提案。建议两种做法二选一：

1. 用户先在 04 里定 Q01–Q05、Q66–Q68，然后授权一个会话（检查点，或本会话续做）按上表写 Z1–Z5 的 prompt（每个 prompt 附 03 的截图和 01a 的条目清单）。
2. Z1 这类只动 `App/` 的，直接按 reports/issues/UIA-w3-app-*.md 当任务单开会话，完成后在会话报告里引用单子文件名。
