- 文案 / 状态（BottomBarView.swift:143-166）：只看**第一个**推流输出 `streams.first`（:145；注释写"状态最差的那个"，没实现）。publishing →"● 推流中"，多路时"● 推流中（n 路）"而 n = 目的地总数（:150）；connecting / backoff →"推流 · 重连中（第 n 次）"，首次连接也这么显示（:151-152）；其他 state 原样塞进"推流 · %@"，会显示"推流 · failed"（:153-154；App/Resources/zh-Hans.lproj/Localizable.strings:177）。高亮 = 任一路 enabled（:160）。tooltip = 各路地址换行（:159）。没有目的地时按钮灰掉，tooltip"节目里没有推流目的地：在 输出 › 推流设置… 里添加"（:161-165；Localizable.strings:165）。

### B2 推流设置入口与窗口

### B3 推流页（OutputSettingsPanel.swift:524-557）
- 每个目的地一段，段名"目的地 <全局输出编号> · <名字>"（:527；Localizable.strings:564），新节目第一个推流是"目的地 2 · 推流 1"（输出 1 是 PGM 录制，App/Sources/Show/ShowDocuments.swift:35-41；名字"推流 n"来自 OutputSettingsPanel.swift:198）。
- 段内：地址 TextField（:528）、密钥 SecureField（:529）、重连上限 Stepper 1–300 s（:530-532）、编码器 H.264 / HEVC（:533-535）、分辨率预设（跟节目 / 1920×1080 / 1280×720 / 3840×2160 / 854×480，:79-81、536）、码率 kb/s（:537）、关键帧间隔 N 帧（:538-540）、音频码率 kb/s（:541）、"删除目的地"（:542）。
- 页底"添加目的地"：地址（占位"rtmp:// rtmps:// srt://"）+ 密钥 + 添加（:545-553）；提示"协议由地址的 scheme 决定；每个目的地独立编码、独立重连。"（:554；Localizable.strings:559）。新目的地 enabled = false、编码参数全是契约默认值（:194-200）。
- 编辑即生效：每改一个字符就发一次 setOutputSettings（:92-100）；正在推的路改了地址 / 码率不会生效到下次起（App/Sources/Engine/OutputRuntime.swift:232-234 只看 enabled），页上无提示。删除正在推的路：无确认，运行表随即断开（OutputRuntime.swift:220）——对比 ISO 页录着的路会锁住（OutputSettingsPanel.swift:513）。
- 没有：服务 / 平台预设、质量预设、每路状态、开始 / 停止、画面来源、音频总线、改名。

#### B3a 逐项对照（参考 → 我们）
- 协议：参考 Destination = 服务预设或 "Custom RTMP Server"，无 SRT（图 125）→ 我们 地址 scheme 决定 RTMP / RTMPS / SRT（Packages/SwitcherOutputs/Sources/Streaming/StreamDestination.swift:11-13、37），无预设。
- 地址 / 密钥：参考 "URL" / "Stream Name or Key"（图 124）→ 我们 地址 / 密钥（OutputSettingsPanel.swift:528-529）；RTMP 密钥作发布名、SRT 没写 streamid 时补成 streamid=密钥（StreamDestination.swift:45-53、62-73）。
- 用户名 / 密码 / User Agent：参考 Advanced（图 126）→ 我们无；地址里写的 `user:pass@` 也会被丢（StreamDestination.swift:54-60 重拼 connectURL 时只拷 scheme / host / port / path / query）。
- 视频码率：参考 2500，摘要"2.5mbps"（图 124、127）→ 我们 码率 kb/s，默认 6000（Packages/SwitcherCore/Sources/SwitcherContracts/MixerState.swift:401；OutputSettingsPanel.swift:480-486）。

- 关键帧：参考 "2 seconds"，5 路共享（图 127）→ 我们 每路"关键帧间隔 %d 帧"，默认 120 帧（OutputSettingsPanel.swift:538-540；MixerState.swift:396、401；Localizable.strings:517），节目 24 / 25 / 30 fps 时 = 5 / 4.8 / 4 s。

## E. 需要用户拍板的问题

1. **推流服务预设做不做、列哪些。** 倾向做，短表、自己排序：先"自定义（RTMP / RTMPS）""自定义（SRT）"，再国内常用（微信视频号、抖音、哔哩哔哩、快手——这几家多为每场发"服务器地址 + 推流码"，预设只管标签和"去哪拿"的提示），最后海外（YouTube、Facebook、Twitch——有固定入口，预设直接填好，入口地址实现时按各平台文档核对；YouTube 可一键再加"备用入口"成第二个目的地）。不照参考的列表和顺序，不做登录集成。请确认名单。
2. **底栏推流主体点下去的语义。** 现在"有在跑就全停、否则全起"。倾向保留，但停止前弹一次确认（偏好里可关），单路起停走 ▾ 菜单。另一个选项是"主体只起 / 停勾了'参与全部开始'的目的地"（配合 R7-G16）。
3. **ISO 要不要能单独开始**（参考多路录制有自己的「Start」，和录制是两个按钮）。倾向不要：同一拍起停是我们的 A4 卖点；用 ISO 页"PGM 行可取消"实现"只录 ISO / 只录 PGM"，底栏 ISO 按钮只做入口 + 状态。
4. **播放列表按哪种模型。** 参考 = 切换台层面的"输入序列"；后续方案 §2.5 = "播放列表输入"（一个输入里放多段文件、接缝无黑帧，可测 V12）。倾向 §2.5 模型；"输入轮播"交给 §5.4 宏。过渡期先做 R7-G28 的文件播放命令（要一份契约提案），这版底栏不放播放列表按钮。
5. **新推流目的地的默认质量。** 现在：H.264 6 Mb/s、跟节目尺寸（可能是 1080p60 或 4K）、关键帧 120 帧、AAC 160k；参考默认 720p 2.5 Mb/s。倾向：尺寸封顶 1080p，60 fps 给 6 Mb/s、30 fps 给 4.5 Mb/s，关键帧 2 s，AAC 160k；质量预设里给 720p 档。教会 / 学校上行常见只有 5–10 Mb/s，要不要默认更保守（720p 3 Mb/s），请拍板。
6. **推流状态要不要加 Stats 字段。** 现有 Stats.encoder 只有 state / bitrate / frames / dropped / reconnects（Stats.swift:92-145）。状态窗想显示"已推多久""断了几次""最后一次错误"：UI 自己从 state 变化推算会变成第二份数字，碰铁律 4。倾向写提案 020，在 encoder[] 加 `uptime_s`、`disconnects`（StreamCounters 里已有 disconnects）、`last_error`，API 与 UI 同读；在此之前状态窗只显示现有字段。
7. **密钥放哪。** 现在推流密钥明文存在节目文件里（诊断包会脱敏）。做配置档 / 预设（R7-G03）时，倾向配置档不存密钥，或存进钥匙串。
