### A2 窗口形态（069–103 通用）

- 每路一个独立窗口，标题 "Input: <编号> <名字>"，有最小化 / 最大化 / 关闭（069）。
- 左边一列深色页签，共 11 项，顺序："General"、"Colour Adjust"、"Colour Key"、"Colour Correction"、"Effects"、"Position"、"Layers"、"Triggers"、"Tally Lights"、"PTZ"、"Advanced"。当前页绿底（069 等）。
- 左下角常驻按钮 "Copy From..."，每一页都在（069–103）。
- 右边：上半是这一页的参数，下半是**本路的实时画面**。实时画面右侧有两个小图标（画框、RGB 色条）和一根带刻度的竖滑杆（用途没演示）。有实时画面的页：General、Colour Adjust、Colour Key、Colour Correction、Effects、Position、Layers、PTZ、Advanced；没有的页：Triggers、Tally Lights（081、100）。
- 没有"确定 / 取消 / 应用"按钮（推测改了就生效）。
- 不支持的控件直接灰掉：Blank 这一路的 "Sharpen"、"Mirror"、"Change"（069），没选 PTZ 设备时整块云台控件（101），"Delay" 与 "Apply"、"Properties"（103），没勾 "Colour Key" 时整个色度键框（071）。
- 窗口里没有 tally（在 PGM / PVW）提示；tally 只在主窗口卡片标题条上（068：1 号在 PGM 绿底、2 号在 PVW 橙底）。

### B2 窗口形态

- 每路一个窗口，由 PanelCoordinator 按编号管理：同一路再开只把原窗口提到前面；这一路被删掉，窗口自动关（App/Sources/UI/PanelCoordinator.swift:53-55、61-75）。
- 窗口参数：标题"输入 %d 设置 — %@"，640×520，可缩放，所有输入的窗口共用一个 autosave 名 "InputSettings"（App/Sources/Settings/InputSettingsPanel.swift:297-304；App/Resources/zh-Hans.lproj/Localizable.strings:349）。
- 窗口宿主 PanelWindow 是 titled / closable / resizable / miniaturizable，先 `center()` 再设 autosave 名（App/Sources/UI/PanelWindowController.swift:22-35）。**几个输入的设置窗同时开时会叠在同一个位置**：AppKit 里一个 autosave 名只能给一个窗口用，后开的窗口只能停在居中位置（推测，没实测）。
- 导航：SwiftUI `List(selection:)`，`.listStyle(.sidebar)`，宽 150，右边 `Form { }.formStyle(.grouped)`，切一节换一页（InputSettingsView，App/Sources/Settings/InputSettingsPanel.swift:183-211）。"左侧页签 + 右侧页面"这个结构和参考一样。
- 分 6 节：基本、裁切 / 变换、音频、抠像、效果链、来源（App/Sources/Settings/InputSettingsPanel.swift:12-16；App/Resources/zh-Hans.lproj/Localizable.strings:316-321）。
- 改动即时生效：每改一项就整份发 `setInputSettings`（App/Sources/Settings/InputSettingsPanel.swift:37-45）。有两处例外：名字要回车或点"应用名字"才生效（:216-217），来源要点"应用来源"才生效（:285-289）。
- **没有本路实时画面、没有底部常驻按钮、没有 tally 提示。**

**关于图层（问题 3）**

- 参考的做法：任何一路都能挂最多 10 层其他输入（079、080），每层有自己的位置（078 的层下拉）。挂完的这一路就成了一个"场景"：可以放进 PVW 预演，再用一次转场整体切上 PGM；也能当叠加来源。"Flatten Layers"（069）推测是把各层压成一张图，本路的效果再作用到整张上。
- 我们的做法：
  - Overlay 1–4 是 PGM 上的全局层（Packages/SwitcherCore/Sources/SwitcherContracts/MixerState.swift:206-239），位置跟着通道走、不跟着输入走；转场只换底层，叠加层原样留着。
  - 要搭"主讲 + PPT 双框"，现在得"切底 + 开叠加"两步做。要把双框整体放进 PVW 预演，只能靠叠加的"在 PVW 也显示"（previewOn），可叠加的开关不跟转场走。
  - 所以两者不是一回事，Overlay 1–4 保持现状，不拿它顶替图层。
- 规划对照：
  - §3.5 多画布是同一套 PGM / PVW 画到几块不同分辨率的画布上，构图按画布分，不是按输入嵌套。
  - §3.6 管的是多画面布局和 Aux 路由。
  - 最接近的是 §3.3 虚拟演播室里的"复合输入（布景图）"。
- 判断：v1 不做（不在 §1.2 里）。后续方案新增一节"合成输入"，排在 §3.3 之前，§3.3 可以建在它上面。对教会、学校这类目标用户，双框和画中画是高频需求，后续里排 P1。
- 契约影响（要写提案，下一个编号是 020）：
  - 形态二选一：新增来源类型（背景 + 最多 N 层），或 InputSettings 加 layers。每层 = {输入编号?, 启用, 裁切, 变换}。
  - MixerState 的 tally 推导（Packages/SwitcherCore/Sources/SwitcherContracts/MixerState.swift:695-707）要把"PGM 上那一路里挂的层"也算成在 PGM。这段是契约代码，全系统只算这一处。
  - reducer 要禁止自引用和循环；删掉一路输入时，清掉所有指向它的层。
  - 渲染器按层画，只许一层嵌套，才能保证零分配。
  - Show 加可选字段（缺键给空）；API 文档里 setInputSettings 的说明要跟着改。
  - 每层带不带声音，要单独定。

**关于触发器、tally、云台、高级（问题 4）**

- 触发器归后续方案 §5.4（依赖 §6.1 脚本）。
  - 参考的一行 = 事件 + 动作 + 目标输入 + 时长 + 延时 + 值 + Mix（081），按行存在每一路上，另有全局汇总窗（149）。
  - 我们只有一套 PGM / PVW，"Mix"那一列用不上。
  - §5.4 现有的事件（信号出现 / 消失、切换、定时、MIDI、GPI、数据源）没有"播完 / 播放时刻 / 叠加开关 / 电平超阈"，建议补上（R4-G22）。
  - "播完之后自动切回"这个最常用的场景，可以先随 §2.5 播放列表的"结束动作"来做。现在的 FileEndAction 只有停末帧 / 循环 / 黑场（Packages/SwitcherCore/Sources/SwitcherContracts/Input.swift:32-35）。见 E9。
- Tally 归后续方案 §5.2。我们的模型是设备按输入编号自己取，不需要每路映射；那套串口灯协议不跟（R4-G23）。
- 云台归后续方案 §2.4。放的位置和参考一致，都在每路设置里；建议补 UVC 云台和"数字云台"（R4-G24）。
- 高级页：
  - 视频延迟（帧）未规划，建议放后续（R4-G25）。
  - 采集滤镜属性不适用（R4-G26）。
  - v1 要补的只有一件事：把现有"延迟补偿"的标签写清楚是音频延迟（C R4-M20）。

## E. 需要用户拍板的问题

1. **入口做哪几个，双击要不要开设置？**
   - 倾向：卡片、PVW、PGM 三处齿轮都做（界面稿都画了）。卡片和 PVW 是 P1，PGM 是 P2。
   - 双击卡片**不**开设置：直播中快速点卡片选 PVW，很容易误成双击，弹出的窗口会挡住画面。
   - 菜单栏和右键这两个入口保留。
2. **设置窗里的实时画面从哪来？**
   - A：从多画面纹理里裁出这一格。不动渲染器、不改契约；画质是缩略图级，抠像边缘比 PGM 略糙（已知口径，App/Resources/zh-Hans.lproj/Localizable.strings:309）。
   - B：给渲染器加一种"单路预览"显示目标（DisplayTarget 现在只有 program / preview / multiview，Packages/SwitcherCore/Sources/SwitcherRender/Renderer/MetalRenderer.swift:43-45）。画面清楚，但要改渲染器和显示视图。
   - 倾向先上 A，等做调色时再上 B。
3. **`InputSettings.effects` 归谁？**
   - 现状：App 把它当每路音频效果链用，契约注释却写着"效果链占位，具体定义由音频 / 合成会话给"（Packages/SwitcherCore/Sources/SwitcherContracts/Input.swift:336、390-391）。
   - A：一个列表，按 id 区分音频和视频。
   - B：契约拆成 audioEffects / videoEffects 两个字段（走提案）。
   - 倾向 B：两类效果跑在不同的实时线程上，热路径规则也不同；放在一个列表里，reducer 和两个引擎都得各自过滤。拆开之后界面也好分页。
4. **图层 / 合成输入做不做、什么时候做、做成什么样？**
   - 倾向：v1 不做；后续方案新增一节，排在 §3.3 之前。
   - 形态倾向"专门的合成输入类型"：背景色 + 最多 N 层其他输入，每层有裁切 / 位置 / 开关，只许一层嵌套。不照参考那样让任何一路都能挂层。
   - 理由：只许一层嵌套，渲染器的零分配循环、tally 推导、防环都简单。
5. **亮度键算不算 v1 的"基础抠像"？**
   - 倾向不算，放 v1.x。改动小：KeyerSettings 加模式 + 阈值 / 柔化，渲染器加一个分支。但要走提案。
6. **调色（色彩调整 / 三路色轮 / LUT）要不要写进后续方案？**
   - 倾向写，分两步：第一步做色彩调整（饱和度、黑白电平、不透明度、白平衡偏移），在 8-bit 下就能先做；第二步做色轮和 LUT，依赖 §1.1 float16。
7. **分类颜色标签做不做？** 要在 InputConfig 加一个可选颜色（走提案）。
   - 倾向做，P2，输入超过 10 路的节目用得上。和输入条区域（分类页签、颜色点）一起定。
8. **去隔行进不进 v1？**
   - 有 SDI 1080i 机位的用户，一上手就会看到梳齿。
   - 倾向 v1.x 做"按源的隔行标志自动场混合"，不开放给用户选。
9. **文件"播完之后"的动作什么时候做？**
   - 倾向随后续方案 §2.5 一起，给 FileEndAction 加"播完切回上一个 PGM"（要改契约），不为这一件事提前做触发器。
10. **视频延迟（帧）要不要记进后续方案？**
    - 倾向记下来，放在 §4.3"输出延迟"附近，暂不排期。
