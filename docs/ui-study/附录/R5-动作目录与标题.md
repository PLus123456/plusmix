## A. 参考软件：入口与菜单逻辑

### A1. 操作函数选择窗（"Select Function"，图 083–099）

- **位置**：输入设置窗 → 左栏 "Triggers" → 下方编辑行的 "Function" 框（图 082–083）。（推测）快捷键设置里选函数也是这个窗口，本组截图只截了触发器入口。
- **触发方式**：左键点 "Function" 框右侧的小箭头（图 083，光标在箭头上）。
- **弹出形式**：独立小窗（约 416×530），标题 "Select Function"，只有右上角关闭 ×，没有确定 / 取消按钮（图 084）；出现在 Function 框正下方，压在输入设置窗上（图 083）。是否模态看不出（推测非模态）。
- **菜单项树**（没有分隔线、没有子层级、没有灰掉的项）：
  - 左栏（深色）16 个分类，自上而下："All"、"General"、"Audio"、"Transition"、"Output"、"Title"、"Input"、"Overlay"、"PlayList"、"Scripting"、"Replay"、"NDI"、"PTZ"、"Preset"、"DataSources"、"Browser"；当前类绿底（图 084–099）。

  - 右栏下方是单列函数名列表：每行一个驼峰标识符，没有说明、没有图标、没有参数提示；选中行蓝底（图 084 的 "Fade"）。
  - 排序：类内按字母（不分大小写）。例外：`Transition` 与 `All` 开头先列 19 个转场效果名，按固定顺序 "Fade"、"Zoom"、"Wipe"、"Slide"、"Fly"、"CrossZoom"、"FlyRotate"、"Cube"、"CubeZoom"、"VerticalWipe"、"VerticalSlide"、"Merge"、"WipeReverse"、"SlideReverse"、"VerticalWipeReverse"、"VerticalSlideReverse"、"BarnDoor"、"RollerDoor"、"Cut"，然后才按字母（图 084、085）。

- **默认值与状态反馈**：打开时左栏停在 "Transition"、列表里 "Fade" 蓝底，正是 Function 框里的当前值（图 083–084）。（推测）规则是"定位到当前函数所在类并选中它"；也可能 Transition 本来就是默认类，截图区分不了。点 "All" 后 "Fade" 仍是蓝底（图 085），切到不含它的类（如 "General"）就没有选中行（图 086）。（推测）单击或双击一行即选定、关窗、写回 Function 框。

## B. 我们现在的实现

### B1. 快捷键编辑器（对应 A1 的"选函数"）

- **位置 / 触发**：菜单 切换 › "快捷键…"（App/Sources/AppDelegate.swift:110）→ `PanelCoordinator.showHotkeyEditor`（App/Sources/UI/PanelCoordinator.swift:110）。菜单项没有快捷键；偏好设置（⌘,）里没有入口。
- **弹出形式**：独立普通窗口"快捷键"，760×520、可缩放、非模态（App/Sources/Settings/HotkeyEditorPanel.swift:229–232；App/Sources/UI/PanelWindowController.swift:22–31）。
- **内容**：一张表，每行 = 组合键文本框 + "录键" + 动作下拉 + 一个参数框 + 备注 + "删除"（HotkeyEditorPanel.swift:186–207）；底部"加一条 / 恢复默认表 / 冲突提示 / 保存"（211–218）和表文件路径（220）。
  - 动作下拉是扁平一层 12 项：PVW 选输入 / 直切 PGM / Cut / 按已选转场执行 / Fade（拍数）/ FTB 开关 / 叠加开关 / 静音开关 / 录制开关 / 推流开关 / AFV 开关 / 其他命令（HotkeyEditorPanel.swift:11–14；App/Resources/zh-Hans.lproj/Localizable.strings:259–271）。没有分组、没有搜索、没有说明文字。
  - 参数只有一个整数框，标签随动作变：输入 / 拍数 / 通道 / 输出（HotkeyEditorPanel.swift:15–24、200–201；Localizable.strings:274–277）。Fade 的时长按"拍"填。
  - "其他命令"：从 JSON 读进来的其他命令只显示 Swift 原始描述（HotkeyEditorPanel.swift:170、202–203；Localizable.strings:263 "命令 %@"），不能改；从别的动作切到"其他命令"时行里没有内容，保存后悄悄变成 Cut（HotkeyEditorPanel.swift:54、77）。
  - 默认表：1–0 选 PVW、Shift + 1–0 直切 PGM、空格 Cut、回车按已选转场、F 键 FTB（Packages/SwitcherControl/Sources/SwitcherControl/Hotkeys/HotkeyTable.swift:56–70；docs/user/快捷键.md:9–15）。
- **派发**：一个组合键解析成恰好一条命令（Packages/SwitcherControl/Sources/SwitcherControl/Hotkeys/HotkeyDispatcher.swift:38–42；ControlAction.swift:17–38），发两条命令的组合动作做不了。

### B2. MIDI 映射

- **位置**：菜单 切换 › "MIDI 映射…"（AppDelegate.swift:111）→ 独立窗口 820×520（App/Sources/Settings/MIDIMappingPanel.swift:285–291）。
- **每行两层**：第一行 触发下拉（CC / 14-bit CC / Note）+ 通道 + 号 + "Learn" + 触发文字 + 删除（MIDIMappingPanel.swift:200–212）；第二行 动作下拉（T-bar / 输入增益 / 总线增益 / 动作 / 命令，215–225）+ 该动作的参数（248–281）。选"动作 / 命令"后再出一个下拉，项目 = 快捷键的 12 项去掉"其他命令"（263–272），外加一个整数参数（273–279）。
- JSON 里写了其他命令的映射，在这里动作下拉显示空白（kind 是"其他"却被过滤掉，MIDIMappingPanel.swift:270）。

### B3. 命令目录与可绑动作

- 契约里 34 条命令（Packages/SwitcherCore/Sources/SwitcherContracts/Command.swift:8–85）。`CommandCatalog` 按 7 组给一句说明和样例：切换 / 叠加 / 音频 / 输出 / 输入表 / 输出表 / 节目（Packages/SwitcherControl/Sources/SwitcherControl/CommandBus/CommandCatalog.swift:62、79–149），参数说明是纯文字（66–67）；`GET /api/v1/commands` 返回它（docs/api.md:54）。编辑器没有用这份目录。
- 快捷键 / MIDI 能绑的是 `ControlAction`：任意一条 Command + 6 个看状态的开关（FTB / 叠加 / 静音 / 录制 / 推流 / AFV）（ControlAction.swift:7–15）。`setOutputEnabled`（NDI / 外部显示 / 虚拟摄像头 / 多画面）、每路跟随视频、总线静音、路由、独听都没有开关动作；带输入的叠加、选转场类型只能走"其他命令"（手写 JSON）。

### B4. 兼容层（VMixCompat）的函数表

- 已实现：`FunctionCatalog.implemented`（Packages/SwitcherControl/Sources/VMixCompat/FunctionCatalog.swift:18–82）+ 翻译 `FunctionTranslator.plan`（FunctionTranslator.swift:18–180）；已知未做：名单 `knownUnimplemented`（FunctionCatalog.swift:91–125）+ 前缀族（128–134）→ 501 NotImplemented；名单和前缀都没有 → 400 UnknownFunction（FunctionTranslator.swift:176–179）。
- 用截图里看得见的 247 个有名字的函数逐个跑这套判定（脚本 `$SP/r5-compat-check.py`，按 FunctionCatalog 的规则复刻）：**已映射 47、501 已知未做 169、400 不认识 31**（逐项见 D2）。
- 兼容层文档把 AudioAuto 列为不做的理由是"AFV 在这里是全局的"、把 External / Fullscreen 列为不做的理由是"外部输出没有开关命令"（docs/integrations/vmix-compat.md:128–131）。两条理由都过时了：每路 `afv` 已进 `InputAudioSettings`（Input.swift:296–300），`setOutputEnabled` 已有（Command.swift:56–59）。

### B5. 标题 / 字幕现状（对应 A2）

- Add Input 只有 8 种来源：合成 / 摄像头 / DeckLink / 屏幕 / 文件 / 图片 / NDI / 音频（App/Sources/UI/AddInputSheet.swift:17–18；InputKind 见 Packages/SwitcherCore/Sources/SwitcherContracts/Input.swift:4–5），**没有标题 / 文字类输入**。
- 下三分之一的做法：1920×1080 带 alpha 的 PNG 作图片输入 → 放进叠加通道，矩形用"整幅"或叠加面板的"下三分之一"预设（x 0 / y 0.75 / 宽 1 / 高 0.25，App/Sources/UI/OverlayPanel.swift:10–23）+ 进出动画 cut / fade / slide / zoom（MixerState.swift:128–130）（docs/user/概念.md:66–70；docs/user/输入.md:57–60）。输入格子上的 1–4 按钮把这一路放上 / 撤下叠加 N（App/Sources/UI/InputCellView.swift:34、225–233）。
- 样例：教会"歌词字幕"（叠加 1，从底边滑入）、教室"课程标题"、活动"标题字幕"，都是 PNG（Samples/README.md:8–10）；PNG 由 Samples/tools/make-assets.swift 画（`lowerThird` 50–57 行，写文件 101–107 行）。换文字 = 换 PNG（Samples/README.md:82）。
- 局限：图片只解码一次（Packages/SwitcherInputs/Sources/SwitcherInputs/Image/ImageInput.swift:8），同一路径的文件改了不会重载，因为来源不变就不重建（App/Sources/Engine/InputRuntime.swift:43–46）；Add Input 选图片一次只能选一张（AddInputSheet.swift:683–685）；界面上的时钟只给操作员看，不上 PGM（App/Sources/UI/ClockView.swift:1）。
- 现有的"动态字幕"旁路：文件输入认 ProRes 4444 / HEVC alpha（Packages/SwitcherInputs/Sources/SwitcherInputs/File/FileInput.swift:27），可以放预渲染的动画字幕片；NDI 输入认带 alpha 的源（Packages/SwitcherInputs/Sources/NDI/NDIInput.swift:37），外部图形软件可以经 NDI 送字幕进来。

- 参考的"标题"分两层：① 模板浏览器（Add Input → Title，12 个页签，图 048–059）；② 模板里的字段（文字 / 图片 / 颜色 / 可见性 / 预设组 / 倒计时 / 滚动速度 / 命名动画）由 Title 类的 24 个函数改（图 089），这些函数又能被快捷键、触发器、API 调用，字段还能挂数据源（DataSources 类 9 个，图 098）。
- 我们两层都没有。设计方案 §1.3 明确第一版不做标题设计器；后续方案 §3.1（标题 = CALayer 树 + CARenderer 渲进 Metal；模板 JSON、字段、"一个模板多组预设"；内置模板包：下三分之一、全屏名单、计分板、倒计时、滚动条、时钟）、§3.2（实时字幕写进 3.1 的字幕条字段）、§2.6（数据源 + 内置计分板）已经覆盖参考的全部形态；只有"竖屏版式"还要等 §3.5 多画布，"社交评论卡"的数据来源是竞品自家服务。
- 结论：区域 B 整体归"v1 明确不做（§1.3）→ 后续方案 §3.1 / §3.2 / §2.6 / §3.5"，不建议在 v1 做模板浏览器。现在的下三分之一靠"PNG 图片输入 + 叠加通道"（B5），教会歌词、讲员名条这类高频需求要靠提前做好一堆 PNG。

**最小可行替代（按成本从低到高）**

1. 现在就能用（写进用户手册即可，不改代码）：
   - 每条字幕一张 1920×1080 带 alpha 的 PNG = 一路图片输入；叠加面板选"下三分之一"或"整幅"，配从底边滑入；上 / 下字幕用输入格子上的 1–4 按钮（InputCellView.swift:225–233）或 Stream Deck 的 Overlay 按钮（docs/integrations/stream-deck.md:28）。
   - 要动画：预渲染 ProRes 4444 / HEVC alpha 的字幕片，当文件输入用（FileInput.swift:27）。
   - 要实时改字 / 计分 / 时钟：外部图形软件经 NDI 带 alpha 送进来（NDIInput.swift:37）。
2. 小改（不改契约，各 S）：
   - 图片输入监视文件修改时间，改了下一拍换上（ImageInput.swift:8 现在只解一次）。这样任何能写 PNG 的东西（脚本、表格导出、演示软件导出）都能当简易数据源。
   - Add Input 的图片页允许多选、一次建多路（AddInputSheet.swift:683–685）。
   - 把 Samples/tools/make-assets.swift 的 `lowerThird` 升格成小工具：读一个 CSV（姓名, 头衔）批量出 PNG。
   - 快捷键 / MIDI 能绑"叠加 N 换成输入 X 并开"（R5-M02），一键换讲员名条。
3. 中改（要改契约，M–L；建议当作 §3.1 的第一步来做，不做一次性的临时方案）：
   - 新输入类"标题"：模板用 §3.1 定的模板 JSON，只做文字 / 图片 / 色块三种层，进出动画沿用叠加通道已有的；先带 4 个内置模板：两行下三分之一、居中大字、角标、时钟 / 倒计时；渲染走 §3.1 定的 CARenderer 路线，输出预乘 alpha，直接当叠加用；不做所见即所得编辑器，字段在输入设置里填。
   - 契约：InputSource 加标题类的 case，另加"改标题字段"的命令（或复用 setInputSource 整体替换），先写提案。
   - 模板浏览器（R5-G27）等内置模板超过一屏再做。

## E. 需要用户拍板的问题

1. **选择器里要不要列"整条替换"类命令**（addInput / removeInput / setInputSettings / setOutputSettings / loadShow）？倾向：默认不列，放进"高级：手写 JSON"。理由：参数是整份设置，按错一个键能把一路输入删掉或把节目整个换掉；参考软件虽然全开放，但它的函数都是小动作。
2. **快捷键表里的时长怎么存**？倾向：新加一种按毫秒存的 Fade 动作（按下时按当前帧率换成拍，兼容层已经这么换：FunctionTranslator.swift:258–271），界面按秒填；旧的按拍存的照读。理由：按拍存的话，节目从 30p 换到 60p，同一条"Fade 30"从 1 秒变成 0.5 秒，操作员不会想到。不改契约。
3. **标题要不要在 §3.1 之前先出一个最小版**（D 节"最小可行替代"第 3 条：4 个内置模板、字段在输入设置里填、没有编辑器）？倾向：做，但直接按 §3.1 的内核（模板 JSON + CARenderer）做，不做一次性临时方案；要改契约（InputSource 加标题类、加改字段命令），先写提案。在它之前先落第 2 条的三个小改（图片自动重载、多选添加、CSV 批量出 PNG）。
4. **四个转场槽**（界面稿的 Fade▾ Merge▾ Wipe▾ Fly▾；参考的 SetTransitionEffect1–4 / SetTransitionDuration1–4）要不要做？倾向：只在界面层做"四个可配的转场按钮"（每个按钮自己存类型 + 时长，按下 = setTransition + autoTransition），状态里仍一个槽，不改契约。这一条和负责转场列的调研员有重叠，合并时对一下。
5. **兼容层要不要补映射 + 改错误码**（R5-G25）？倾向：要。AudioAuto → 每路 afv、Fullscreen / External → setOutputEnabled、SetOutput2–4 / SetOutputFullscreen → 改 source、NDISelectSourceByName → setInputSource，全是现有命令；31 个真名从 400 改回 501。不改契约，但兼容层发布前本来就要问律师（docs/integrations/vmix-compat.md:3–11），多映射几个函数不改变法律面。
6. **"界面动作"要不要进快捷键表**（显示 / 隐藏调音台、多画面窗口、全屏监看）？它们不走命令总线，API 也用不了。倾向：进，放"界面"组，只在 App 里派发，不进 CommandCatalog。
7. **输入内图层**（参考 "MultiViewOverlay" 一族：每路输入自带若干层）要不要进规划？倾向：不做。全局 Overlay 1–4 加后续方案 §3.3 的复合输入已经够用，每路再加图层会让"PGM 上到底叠了什么"难以一眼看清。
