## A. 参考软件：入口与菜单逻辑

### A1. 底栏 "Add Input" 分体按钮（图 001、023）
- 位置：主窗口底栏最左。分体：左边主体 "Add Input"，右边一条窄的 "▴"（图 001，放大后看得清两段是分开的按钮）。
- 左键主体：弹出独立窗口 "Input Select"（图 023：鼠标停在主体上，主体有悬停高亮，窗口已打开）。
- 右侧 "▴"：**截图里没有它的菜单**。（推测）向上弹出的小菜单：同一底栏的 Stream "▴" 就是向上弹一个小菜单（"Start All Streams"，图 133）。Add Input 的 ▴ 里放什么看不出，推测是输入类型或最近添加的快捷项，点了直接到对应类型页。
- 状态反馈：悬停时主体高亮（图 023）。没看到快捷键提示。

### A2. "Input Select" 窗口的整体形态（图 023–047）
- 形式：独立的模态窗口，有标题栏 "Input Select" 和右上角 ×，盖在主窗口中下部，约 1085×669（图 023、024）。
- 左栏：深色底，21 项，每项一个大图标加文字。单击某项，右边换成它的参数页；选中项是绿底（图 024–047 每张鼠标都停在左栏的某一项上）。没有分组，也没有分隔线。顺序是："Video" "DVD" "List" "Camera" "NDI / Desktop Capture" "Stream / SRT" "Instant Replay" "Image Sequence / Stinger" "Video Delay" "Image" "Photos" "PowerPoint" "Colour" "Audio" "Audio Input" "Title" "Virtual Set" "Web Browser" "Video Call" "Zoom" "Telestrator"（图 024 左栏）。
- 默认：窗口打开时选中第一项 "Video"（图 023、024）。
- 右边：白底的参数页。文件类页面顶部有一条深色说明条，用一句话说明该选什么（如 "Select the Video file to open."，图 024）。有子页的类型在页顶放两个页签，当前页绿底（"NDI" / "Local Desktop Capture"，图 028、029；"Host a Call" / "Connect to Call"，图 045）。
- 底部：一条深色条，所有页都一样："Number" 下拉 + "OK" + "Cancel"。26 张截图里 "Number" 全部显示 "1"，而当时主界面已经有 1、2 两路（图 023）。（推测）"Number" 是新输入要占的编号或插入位置。默认值的口径看不出，见 E1、F。
- 前置条件不满足时怎么提示：在页顶放红色横幅。Zoom 插件没装时横幅写"点这里下载"（图 046）；Telestrator 要先去 Settings › Web Controller 打开（图 047）。Video Call 一进页就去连自家服务器，连不上弹错误对话框 "vMix Error"（"Send Error Report" / "Close" + 详情框，图 044）；关掉后页面照常可见（图 045）。

## B. 我们现在的实现

### B1. 入口
- **底栏"添加输入…"**：底栏最左一个普通按钮，只有一个动作，没有箭头和菜单（App/Sources/UI/BottomBarView.swift:40, 51, 193）。⌘I 挂在这个按钮上（:63-64）。
- **菜单栏**：输入 › 添加输入…（⌘I），下面是输入设置…（⇧⌘I）（App/Sources/AppDelegate.swift:100-103, 196）。没有按类型分的子菜单。
- 两个入口都走 `presentAddInput()`（App/Sources/UI/MainWindowController.swift:145, 258-268）。面板已经开着时不会再开第二个（:259），所以 ⌘I 挂了两处也不会重复弹。
- **输入条**：只按 `state.inputs` 建格子，没有界面稿里那张虚线"添加输入"占位卡（App/Sources/UI/InputStripView.swift:84-116；界面稿见 docs/spec/ui-mock/vMix for Mac.dc.html:295-298）。空节目一路输入都没有（App/Sources/Show/ShowDocuments.swift:34-41），这时输入条完全空白。不支持把文件拖进来加输入（全仓库没有 registerForDraggedTypes）。
- **输入格右键**：只有设置… / 重命名… / 删除，没有"加一路"或"换来源"（App/Sources/UI/InputCellView.swift:184-189）。
- **API**：`addInput`，编号已存在就拒绝（Packages/SwitcherCore/Sources/SwitcherContracts/Command.swift:67-68；Packages/SwitcherControl/Sources/SwitcherControl/CommandBus/CommandValidator.swift:43-46；docs/api.md:632）。兼容层把上游的 AddInput 列在"明确不做"里（Packages/SwitcherControl/Sources/VMixCompat/FunctionCatalog.swift:90-91, 106）。

### B2. 面板形态
- **Sheet**：贴在主窗口上，NSPanel 760×520，只有标题栏"添加输入"，不能缩放，没有关闭钮（App/Sources/UI/AddInputSheet.swift:743-748）。Esc = 取消，回车 = 添加（:719-720）。
- **左栏**：SwiftUI `List(.sidebar)`，宽 170，只有文字，没有图标和分组（:699-704）。八项的顺序是 合成测试源 / 摄像头 / 采集卡 / DeckLink / 屏幕 / 窗口 / 视频文件 / 图片 / NDI / 音频设备（:18；文案在 App/Resources/zh-Hans.lproj/Localizable.strings:69-76）。这个类型列表是 W3-E 有意按设计方案 §6 定的，没有照截图里的 Windows 列表（docs/plan/prompts/54-W3E-界面二期.md:3）。
- **默认选中"合成测试源"**（AddInputSheet.swift:55）。测试钉住了这个默认（App/Tests/ShortcutAndShowTests.swift:358, 376）。每次打开都是一张新表单，不记上次的类型和参数（MainWindowController.swift:260；AddInputSheet.swift:316-323）。
- **右边**：grouped Form，每种类型一个 Section，带标题和一行灰字说明（:482-496, 706-707）。
- **底部**（:710-722）：
  - "编号" Picker：只列空号，默认最小空号（:225-228, 307, 316-320, 711-714）。
  - "名字"：占位字是默认名，比如"摄像头 3"、文件名、NDI 源名（:156-168, 715）。
  - 红字错误：缺必填项时出现（:443-452, 717）。
  - "取消" / "添加"：点"添加"后发 `addInput` 并关面板（:756-760）。
- **编号上限**：引擎输入表的容量是 max(16, 节目里最大编号)，开节目时就定死（App/Sources/Engine/SwitcherSession.swift:134-135；Packages/SwitcherCore/Sources/SwitcherEngine/Engine/Engine.swift:101）。16 个号用满后编号下拉是空的，默认号仍是 16，照样能点"添加"，面板也照样关。命令被 CommandValidator 拒掉，拒绝原因走底栏提示（App/Sources/Engine/ControlRuntime.swift:14-20, 155）。
- **输入设置 › 来源**：复用同一套参数页，类型用 Picker 切换，有"应用来源 / 改回"，发 `setInputSource`（App/Sources/Settings/InputSettingsPanel.swift:276-293）。编号加完就改不了（:215 只读）。

### B3. 八种类型的参数页（都在 App/Sources/UI/AddInputSheet.swift）
- **合成测试源** :498-527：帧率、尺寸、底色（纯灰 / 渐变 / 灰底噪声）、灰度、噪声幅度 / 种子、图案 ID、到达抖动、丢帧、时钟漂移、合成音频、音频漂移。
- **摄像头 / 采集卡** :545-554：只有设备 Picker（AVCaptureDevice 列表 :231-235，默认第一台 :321）、台数、权限提示、"设备自带麦克风也会接进来"。
  - 分辨率和帧率按节目自动协商，界面上看不到协商结果（Packages/SwitcherInputs/Sources/SwitcherInputs/Camera/CameraFormatNegotiation.swift:3-7）。
  - 音频只能用设备自带的麦克风（Camera/CameraInput.swift:14）。
- **DeckLink** :556-573：卡（第一项是"第一台有输入的卡"）、设备标识手填、输入接口（不改 / SDI / HDMI…）、内嵌音频声道映射。
- **屏幕 / 窗口** :575-604：
  - 抓取方式：整块显示器 / 单个窗口 / 某个应用。
  - 对应 Picker：窗口显示成"应用 — 标题"（:411）；窗口和应用列表要等切到那一种时才去取（:403-420）。
  - 帧率：跟节目，或 24–60 里选。
  - 同时抓系统音频。
  - 一行固定的权限提示（:602）。
  - 没有缩略图。
- **视频文件** :616-628：
  - 路径 + "选择…"。NSOpenPanel 只收视频类型（:684）。
  - 播完：循环 / 停在末帧 / 黑场。
  - 播放速率。
  - 透明通道自动识别（Packages/SwitcherInputs/Sources/SwitcherInputs/File/FileDecoder.swift:8, 82-84；File/FileInput.swift:27）。
  - 没有隔行处理，也没有最近列表。
- **图片** :630-638：路径 + "选择…" + 一行说明。
- **NDI** :640-663：
  - "网络上的源" Picker：找到源才出现。
  - 源名手填框、状态字、"重新找"。进页只搜一次，最多等 1.5 s（:422-441, 662）。
  - 带宽模式：最高 / 最低 / 只要音频。
  - 抖动缓冲 0–2 帧。
- **音频设备** :665-680：
  - 设备 Picker：第一项是"系统默认输入"，插拔会自动刷新列表（:342-344, 360-367）。
  - 一行设备说明：声道数、是否支持 48 kHz、连接方式。
  - 设备超过 2 声道时，选取哪几路（声道映射）。

## D. 功能缺口

21 种参考类型逐一对照：G01–G21 按参考左栏的顺序，G22–G24 是参数层面的缺口。结论：我们对上 5 种（视频文件、摄像头、NDI / 屏幕采集、图片、音频设备），缺 16 种。这 16 种里，DVD、PowerPoint 不适用 macOS；Zoom 是竞品自家服务或插件；7 种在后续方案里已有章节（§2.2、§2.3、§2.5 ×2、§3.1、§3.3、§3.4）；6 种规格里没提（网络流、图片序列、延时、纯色 / 彩条、音频文件、画笔批注）。

## E. 需要用户拍板的问题

1. **"Number" 的语义**：截图里所有页都显示 "1"，当时已经有 2 路（图 023），看不出它是"新输入占第几号（默认末尾）"、"插到第几号、后面顺延"，还是别的意思。
   - 请在 Windows 上补两张图：有 2 路时展开 "Number" 下拉；选 1 加一路之后，看原来的 1、2 号是否变成 2、3。
   - 倾向：不管参考是哪种，我们保持"只选空号、已有输入不挪位"（C-M08）。编号是快捷键、MIDI、API、叠加的锚点，挪位代价太大。
2. **网络流输入（SRT / RTSP / RTMP 拉流）要不要写进后续方案、排第几批**：规格里没有（G06）。
   - 倾向：写进去，排第一批，SRT 呼叫 / 监听和 RTSP 先做。教会、学校的 IP 摄像机基本都出 RTSP，异地回传用 SRT 最多。
   - 需要一份契约提案（新 InputKind + InputSource 分支），工作量 L。
3. **纯色 / 彩条 / 透明输入**（G13）：界面稿的样例节目里已经有"彩条""空白"两路，但规格没写。
   - 倾向：做，放在第二版第一批，也可以作为 0.1.x 的小功能。渲染器直接填色，工作量 S–M，要一份契约提案。
4. **音频文件**（G14）：有两条路。一是放宽"视频文件"输入，让它接受纯音频文件，不改契约；二是等后续方案 §2.5 的媒体播放器。
   - 倾向：先放宽，工作量 S–M，背景音乐是每场的刚需。
5. **合成测试源在正式版里放哪**（C-M05 / M20）。
   - 倾向：保留，挪到列表最后单独成"测试"组，不作默认。不建议藏进偏好设置：没设备时搭节目、给别人演示都要用它。
6. **输入上限 16 够不够**（G24）。图片、纯色、标题都各占一路，素材多的节目很快会用满。
   - 倾向：提到 64，或者让引擎在拍点边界动态扩容。
7. **底栏小箭头菜单放什么**（C-M01）。参考的菜单没截到。
   - 倾向：八种类型直达 + "最近添加的来源"一键再加，两样都放。
8. **英文界面的"Add Input…"和参考按钮是同一个词**（App/Resources/en.lproj/Localizable.strings:123, 159, 362）。
   - 倾向：保留。这是通用说法，§1.1 的用词本来就是 Input，界面稿也这么写。如果要避嫌，可以改成"New Input…"。
