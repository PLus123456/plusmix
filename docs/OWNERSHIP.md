# 目录归属（会话 → 只准动的目录）

照 docs/plan/导播台落地方案.md §2 的表抄，并把各会话 prompt 里"只准动"一行落成可机器检查的路径。
`scripts/check-ownership.sh <分支>` 读**下表的"允许的路径"列**，检查该分支相对 `main` 的改动是否越界；`make lint` 会自动带上当前分支。

## 表格格式（脚本按这个解析，别改列顺序）

- 第 3 列是分支名，反引号包住。第 4 列是路径 token，每个反引号包住、空格分隔：
  - `dir/`（以 `/` 结尾）= 该目录下全部文件；`path/file` = 单个文件；可以带 `*`（bash 模式匹配，`*` 也能跨 `/`）。
  - `!path` = 排除（即使被更宽的 token 覆盖也不许动）。
  - `~prefix:N` = 胶水额度：`prefix` 下的改动本来不许，但检查点会话允许每个子目录（`Packages/*` 按包、`App/` 整体）改动 ≤ N 行（增 + 删）。
- 所有分支另外都允许：`reports/<分支名>.md`（分支名里的 `/` 换成 `-`）、`reports/issues/`、`docs/contract-changes/`。这三条写在脚本里，不用写进表。
- `main` 只有 P0 用，不检查。

5. 脚本只看**已提交**的改动：功能分支 = merge-base(main, 分支) → 分支顶；检查点分支（有合并提交）= 沿第一父链逐提交结算，合并提交只算相对自动合并结果的手改。其中**自动合并结果里带冲突标记的文件**（两个功能分支改了同一处，G4 合 W3-C / W3-E 时 App/ 有 8 个），它在合并提交里的改动是冲突解决，脚本单独列出、不计胶水额度（解决冲突不是检查点在写功能）；合并提交里改的其它文件（删重复实现、改调用点）照常计胶水额度。逐提交结算会把"一个提交改了、后一个提交又改回"的路径算成两次改动，所以结算完再按相对 `main` 的净差过滤一遍：净差为零、且没有任何被合入分支动过的路径只列出来、不算改动（G4 的 .gitignore：加了 `__pycache__/` 又按归属撤掉；G4 自己建了又改名的 prompt 文件同理）。被合入分支动过的路径不在此列——检查点删掉合进来的文件、或把合进来的改动改回 main 的样子，相对 main 也是净差为零，但那是对合入内容的手改，照常计胶水额度（G4 删 W3-E 的 AuxWindows.swift 就是这样算的）。加 `--include-working-tree` 可以把未提交的也算上，方便会话提交前自查。
