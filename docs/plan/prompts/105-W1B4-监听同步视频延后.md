## 105 W1-B4 监听同步：按总线效果链的实测延迟把视频延后同样的毫秒数（用户 2026-10-03 定；G6 合入后可开，不等 102）
分支：w1-core-4（从 G6 合入后的 main 开）。只准动：Packages/SwitcherCore/Sources/SwitcherEngine/、Packages/SwitcherCore/Tests/SwitcherEngineTests/、Packages/SwitcherAudio/Sources/Integration/（只做补偿方式的开关与把延迟值交给引擎）、Packages/SwitcherAudio/Tests/IntegrationTests/、Tools/switcher-headless/（只加参数）。App 的接线归检查点胶水或 97。
先读：reports/w5-audio-bus-effects.md §1.3（效果链延迟现在补在音频 PTS 侧：`EffectLatencyTimeline` + `ConsumerPump`；"不补的：监听"）；docs/contract-changes/024-dynamics-ratio.md"批后的附加要求"第 3 条（用户原话与 2026-10-03 的决定）；设计方案 §3（线程与时钟、§3.2 挑帧、§3.4 派发）、§3.5；docs/CONTRACTS.md §3 关键口径（PTS = 拍点时刻）；测试标准 §1 A2 / A5、§3 对应行；reports/w1-core-3.md（渲染完成线程、派发队列现在的样子）。

背景：总线效果（压缩 / 限幅的前瞻）让 Master 的声音比画面晚 L（AU 限幅器起音 1–30 ms、AU 压缩 5.3 ms；102 的自写压缩器按设计 0）。W5-C 把这段延迟补在音频 PTS 侧，录制 / 推流 / NDI 的文件与流是对齐的，但扬声器 / 耳机监听没有 PTS、补不到——操作员听到的比看到的晚 L。用户 2026-10-03 定：**监听也要同步，办法是把视频延后同样的毫秒数**（接受 PGM 端到端多 L 的延迟）。

交付（每条先写红测试；函数名带 ID）：
1. 引擎加"视频延后 L"：渲染完成的帧不立刻派发给消费者（显示、编码器、NDI、虚拟摄像头、外部显示），按 pts + L 到期再派；L 由音频引擎给（Master 当前效果链的实测延迟：W5-C 量 AU 的值、102 自测的值），运行中 L 变了平滑切换（不丢帧、不重复、PTS 单调）；渲染线程与派发线程零分配（延迟队列预分配，深度按最大 L 算：35 ms @ 60 fps = 3 帧 + 1）。
2. 补偿方式一处开关（AudioEngine / ConsumerPump）：`videoDelay`（新，默认）= 音频 PTS 不再前移、视频延后 L；`audioPTS`（W5-C 现状，保留给 headless 对照）。两种方式下录制文件里的 A/V 偏移都要 ≤ 1 ms，不许双重补偿。
3. 监听同步的量法：A5 那套回环（音频接口线路输出 → 线路输入；BLOCKED-硬件时用空设备 + 显示呈现时间戳模拟）：Master 开着限幅起音 30 ms 时，监视器呈现时刻 − 扬声器出声时刻 ≤ 1 帧（有硬件再填数）。
4. 当前视频延后的毫秒数是运行量，要给界面 / API 看就进 Stats——先放 `EngineCounters`，字段归提案 022 顺带（P5 / prompt 99），不自己加契约。
5. headless：`--av-compensation videoDelay|audioPTS`（默认 videoDelay）；gate4 场景不带效果，结果应与改前一致。

测试：`testAV_videoDelayFollowsBusEffectLatency`（Master 加限幅起音 12 ms → 派发时刻比渲染完成晚 12 ms ± 1 拍；关掉效果回 0；过渡期无丢帧 / 重复 / PTS 倒退）、`testAV_videoDelayQueueZeroAllocation`（AllocationProbe）、`testA2_videoDelayMode_recordingStaysAligned`（录制文件 frameprobe av 整秒配对 ≤ 1 ms，与 audioPTS 模式结果相同）、`testA5_monitorSync_loopback`（BLOCKED-硬件时 XCTSkip 并写步骤）；`make gate4-run` 一次 V1–V7 / A1–A4 不变（场景不带效果）。
不做：契约字段（022 顺带）、App 界面（显示延后值归 97 / 检查点）、每路效果与自写压缩器（102）。
