## 45 W1-E2 录制器收尾 / 编码器崩溃（编码录制续做）
分支：w1-outputs-2（从 G3 合入后的 main 开）。只准动：Packages/SwitcherOutputs/Sources/SwitcherOutputs/、Packages/SwitcherOutputs/Tests/SwitcherOutputsTests/。
先读：reports/issues/W2E-w1-outputs-recorder-drift-check-before-stop.md、G2-w1-outputs-stop-with-live-audio.md、W2D-w1-outputs-audioencoder-finish-empty.md；
reports/issues/W2E-g3-pending-changes-checklist.md 的 3-6…3-8；reports/G3-notes.md §6 第 2、9 条（E5 音轨长 24–169 ms）；Tools/switcher-headless/Sources/switcher-headless/HeadlessRun.swift 第 8 步（组装方现在怎么绕）。

背景：`Recorder.drainAudio` 先查漂移后查 stopTime——边界之后还在到达的块触发补静音，`appendPCM` 每 4096 帧等 200 ms，封口能拖到分钟级；组装方只能"封口前先摘消费者"绕开，
音轨仍比名义时长多 24–169 ms（E5 的 ≤ 20 ms 不过）。`AudioEncoder.finish()` 没喂过块时 host time 减 priming 变负会崩。

交付：
1. `drainAudio`：`blockStart ≥ stopNs` 的块直接跳过，不参与漂移 / 补静音；截断的那块之后不再改 `audioFramesAppended` 的期望。
2. `finishRequested` 之后 `appendPCM` 立即返回并计数（`RecorderCounters.audioFramesDroppedAfterStop` 之类），不再等 200 ms；G2 提的 `appendPCM` 超时丢样本也要计数。
3. 预告停止拍：`stop(atTick:)` 允许在边界之前调（或加 `setStopTick(_:)`），录制器自己把音轨截到边界；组装方不用赌时序。
4. `AudioEncoder.finish()` 空喂不崩：没有输入就只置 finishing、不发包。
5. `EncoderCounters.statsEntry` 若 P2 已落地 001 / 002 的字段，这里补齐 frames / dropped / disk_free_mb / state。

测试（函数名带 ID）：
- testE5_recorderStopBoundary_audioTrackWithin1Block：按拍喂视频到 T，`stop(atTick: T)` 后继续按实时喂 PTS > T 的音频块 5 s——封口 ≤ 1 s 完成，音轨长度 = 名义时长 ± 1 块（≤ 5.3 ms）。
- testE5_announcedStopTick_beforeBoundary：边界前 2 s 调 `setStopTick`，越界块一个都不进文件；两轨时长差 ≤ 20 ms（必须）/ ≤ 1 帧（目标）。
- testE6 仍过（崩溃恢复 ≤ 2 s）；testE2 / testE3 仍过。
- testAudioEncoder_finishWithoutInput_doesNotCrash。
- 整包 `swift test`（约 7 分钟）绿。
