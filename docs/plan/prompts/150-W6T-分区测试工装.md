分支：w6-testkit（**叠在 `p6-contracts` 上开**）。只准动：Packages/SwitcherTestKit/、Tools/frameprobe/、Tools/switcher-headless/、scenarios/。模型：**Opus 5.5，推理档位 max**。
先读：批过的 docs/contract-changes/036（测试口径一节）；docs/spec/大屏与时间线方案.md §3.4 用户场景表、§3.9、§8（V16 / V17 / V21 / L6）；docs/spec/导播台测试标准.md §2（工装）、§3（测法）、§7（stats.jsonl）；SwitcherTestKit 里合成源（烧帧号 / 输入号）、帧号解码、`ScenarioRunner`；Tools/frameprobe 与 Tools/switcher-headless 的入口；scenarios/README；reports/w1-testkit-5.md、reports/w1-testkit-6.md 的 §5（frameprobe 的坑：开录黑帧、拍号按 PTS、平局）。

背景：大屏做出来以后，要能用机器判"几个分区是不是同一拍换的""没变的分区是不是一个像素都没动""映射到输出口以后像素变没变"。现有工装只会解整幅画面里的一个帧号。本会话把工装补到能按矩形解，并让无界面工具能跑配了大屏的节目。渲染和状态机由别的会话并行在做，本会话只对着契约写，合起来以后由检查点跑。

交付（每条先写红测试；工具自己的用例放各自的 Tests）：
1. **按矩形解帧号**：frameprobe 接一组矩形（分区或屏幕在画面里的位置，从节目文件的舞台或命令行给），逐矩形解帧号和输入号，输出每个矩形每一帧的结果。自证不许拿被测画面当真值（沿用现有口径）。
2. **分区判据**：V17（一次切换里各矩形换内容的拍差，必须 0）、V21（布局不变的切换里，内容没变的矩形帧号连续、输入号不变）、V16（输出口录下来的画面里，每块屏的矩形逐值等于画布上对应那一块；1:1 时）。每条有合成数据的自测用例（造一段已知对错的帧序列）。
3. **switcher-headless**：读节目文件里的舞台；能录 PGM 也能录"输出口 n"；场景里能发 036 / 037 的新命令（`ScenarioRunner` 认它们）。
4. **场景文件**：scenarios/stage-20x9.json = 方案 §3.4 的用户场景表（墙 2460×1080，布局"整屏"和"中间 + 两耳"；视频 → PPT → 主视觉 → 视频 → 耳屏 B → 调预设），每一步在固定的拍上；scenarios/stage-3screens-1080p.json = 三块分开的屏挤进一路 1080p（方案 §3.9 最后一段）。README 补一节怎么跑、怎么判。
5. **L6 的量法**：同一路输入到 PGM 和到输出口画面的拍差，工具给出数。
6. `swift test`（SwitcherTestKit 与两个工具的用例 0 红）；`make test-tools`；`make lint BRANCH=w6-testkit`，归属检查带 `--base p6-contracts`。渲染和状态机还没合进来之前，端到端跑不出真结果：用例用合成帧自测，报告里写明"端到端等检查点"。

不做：渲染、状态机、输出、App；改现有判据的口径或阈值。
