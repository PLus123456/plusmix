背景：C 混音器每条总线已有 EQ → 动态 → 限幅三格，Swift 侧 BusEffectChain 也有装 AU / 设参数的接口，集成层就是没把 MixerState.audio.buses[].effects 映射过去；界面能编辑 3 段 EQ、阈值到 −60、增益 ±24，对不上 AU 的范围（单段 ParametricEQ、−40、±20）。每路效果格要动 C 热路径，是 102，不在这里。

第一步（先出结论再写代码，铁律 10）：写探针量 AUNBandEQ（kAudioUnitSubType_NBandEQ）在我们的线程里 AudioUnitRender 的可行性、每段的频点 / 增益 / Q 范围、3 段时的处理延迟；对照 AUParametricEQ 单段。结论进报告 §1；选 AUNBandEQ 时 BusEffectChain 的 EQ 格换成它（一个格 = 最多 N 段），选不了就退回"多装几格 ParametricEQ"（Q09 (a)，同样不改契约）。

交付（先写红测试，函数名带 ID）：
1. `AudioEngine.applyBuses` 按 `BusState.effects` 逐格 installEffect / setEnabled / setParameter：链顺序 = 处理顺序，enabled = false 旁路（AU bypass 属性，不拆链），参数超出 AU 范围时钳位并记一次日志（不在回调里）；拓扑（装 / 拆格）只在非实时线程、且只在快照里 effects 的格数或 id 变化时做（设计方案 §3.5：运行期不改拓扑——所以装拆时那一条总线短暂旁路，写清楚做法与时长）。
2. 效果链的处理延迟（AU 的 latency + tail）计入 A/V 对齐（写清补在哪一侧），A2 不因开效果而漂。
3. App 侧：`AudioEffectsSupport.busChainsApplied = true`（87 的止血标签对总线撤掉，每路仍标）；EffectChainView 的范围收进 AU 的范围（阈值 −40…0、增益 ±20、段数 ≤ 探针得到的 N）；压缩简单模式"阈值 + 比例 + 输出增益"的比例 → Headroom 换算用探针量（Q61），换算不准就写提案加 ratio 键，不要硬凑。
4. 手册 docs/user/概念.md:78 那句由 103 改回"已生效"，本会话只在报告里写明改法。
