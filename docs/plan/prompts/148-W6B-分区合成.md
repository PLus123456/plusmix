## 148 W6-B 分区合成：PGM / PVW 按布局画分区、转场按分区做、输出口打包、对位图（第六波 · 第二层；P6b 做完后开，和 149 / 150 / 151 并行）

先读：批过的 docs/contract-changes/036（转场作用范围、`RenderedFrame` 的形状、适配方式这几节）；docs/spec/大屏与时间线方案.md §3.2、§3.3、§3.6、§8（V16 / V17 / V19 / V20 / V21）；docs/spec/导播台设计方案.md §3.2（渲染线程规则）、§5（合成顺序）；SwitcherRender/Renderer/ 的 CompositorPasses.swift（`encodeProgram` / `encodeTransition` / `encodePreview` / `drawInput` / `scissor`）、Placement.swift、MultiviewLayoutTable.swift（定长表的做法）、MetalRenderer.swift、LabelRenderer.swift、Shaders/Compositor.metal（Wipe 遮罩按屏幕坐标算的那一段）、Offline/OfflineRenderer.swift；reports/claude-large-screen-preview-timeline-af075d.md §5"合成里写死整幅的地方"。

背景：现在的 PGM 是四步：画底（PGM 那一路铺满画布）→ 转场（把 PVW 那一路按进度盖上来）→ 叠加 → FTB。配了大屏之后还是这四步，只是前两步的目标从整幅换成分区的矩形。没配大屏时必须走原来的路径，画出来一个字节都不能变。

交付（每条先写红测试，函数名带测试 ID；渲染线程每帧零分配，查法沿用现有用例）：
1. **定长布局表**：换快照时把屏幕、布局、分区、输出口解析成定长数组（照 `MultiviewLayoutTable` 的做法），上限按 036；渲染线程只读它。
2. **适配方式**：`Placement` 加填满（裁边）、拉伸、点对点；现有"适应"的结果逐值不变。
3. **画底按分区**：清黑，按节目墙面当前布局的分区从下到上画，每个矩形一个裁剪框；跨屏（一个矩形铺一幅）和各放一份（每个矩形一份）两种铺法；空分区透明。`testV20_noStageByteIdentical`：没配大屏、和"配了一个盖满画布的分区"，PGM / PVW 逐值相同；现有参考图用例一条不改。
4. **转场**：布局没变时只对内容变了的分区，把新的那一路按进度盖在它的矩形里（Cut、Fade；清空的分区盖一层按进度变黑的底）；布局变了时把预监墙面整幅盖上来；Wipe / Zoom / Stinger 第一版整幅做。`testV21_unchangedZonesUntouched`：布局不变的 Fade 全程，没变的分区每个像素逐值不变。`testV17_zonesSwitchInSameFrame`：一次切换里几个分区在同一帧换。
5. **PVW** 按预监墙面画；画布很大时按缩小的尺寸画的开关（有输出要 PVW 全幅时不缩）。
6. **输出口打包**：清黑，把每块屏幕在画布上的那一块画到它在输出口里的矩形（位置、旋转 90° 的倍数、镜像）；产物怎么交出去按 036。`testV16_rasterMappingExact`：1:1 时逐值相同；带缩放时对参考图 SSIM ≥ 0.99。
7. **对位图**：每块屏显示名字、像素尺寸、边框、对角线（名字用 `LabelRenderer`）。
8. **离线渲染器**同样支持，出参考图：20.5:9 的墙两个布局（方案 §3.9）、三块分开的屏挤进一路 1080p、对位图。参考图按现有口径比（PSNR）。
9. **耗时**：`testV19_stageRenderTimeSmall`：3 个分区 + 一路 1080p 输出口，不超过现有 V1 的阈值。大档（8 块屏 + 两路 4K 输出口）只量不判，报实测，阈值等用户定。
10. `swift test`（SwitcherCore 整包 0 红）；`make lint BRANCH=w6-render`，归属检查带 `--base p6-contracts`。
