现象（Codex 在 main 1f9be64 实测；g11 树这两处没变）：
- N05：`InputChannelMap.requiredSourceChannels` 对映射里的原始下标 `+ 1`（`[Int.max]` → 溢出 SIGTRAP；`[999]` → 1000 正常），DeckLink 的 16 路封顶在它之后；SDK 编进来时 `attempt` 在查驱动 / 枚举设备之前就算 `cfg.audio_channels`，App 默认给 audioRing，主 API / validate 不查这个 source 参数——不插卡也能崩。契约说越界映射钳到源声道范围。
- N09：`pause()` 只置请求标志，`anchorMedia` 要等推帧线程下一次醒来才冻结；这之前 `resume()` 无条件把 `anchorTick` 换成将来的拍、沿用旧 `anchorMedia` → 位置回到旧锚点（1.5 s → 0）、随后 0.5 s 最多多推 1 帧（解码器队首在旧播放点之后，要重新追）。App 每 1/60 s 轮询把 paused 变化转成 pause/resume，30 fps 节目两次里一次复现、60 fps 八次没撞上（看相位）；等暂停落实（100 ms）再恢复的对照正常。D13 修的是 pause/seek，不是这条。

做（先写红用例再改；用例名带 ID `testN05_…` / `testN09_…`）：
