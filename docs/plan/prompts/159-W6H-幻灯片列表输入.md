## 159 W6-H 幻灯片列表输入：一路输入里装一串页（一组图片或一份 PDF），可分段，上一张 / 下一张不黑不卡（第六波 · 第三层；P7b 做完后开，和 158 / 160 并行）
分支：w6-inputs-slides（**叠在 `p7-contracts` 上开**）。只准动：Packages/SwitcherInputs/。模型：**Opus 5.5，推理档位 max**。
先读：批过的 docs/contract-changes/040 全文；docs/spec/大屏与时间线方案.md §4.4；docs/spec/导播台设计方案.md §3（线程与时钟：每路输入自带线程、只往自己的帧槽写、帧在入口打 host time）；Packages/SwitcherInputs/Sources/SwitcherInputs/ 的 Image/（图片输入怎么出帧）、File/（文件输入怎么按节目时钟定位、解码线程的自动释放池，见 reports/w2-inputs-6.md §5）、Common/；docs/contract-changes/032（输入上限 16）。

背景：用户做大屏时素材主要是 PPT，一场 20–30 张，分几段。一张图占一路输入的话 16 路不够用，所以做一种输入：一路里装一串页。来源两种：一组图片（拖一个文件夹或多选），或一份 PDF（PPT / Keynote 导出，一页一张）。它就是一路普通输入：有自己的上屏位置，能当叠加，时间线的提示点可以让它翻到第几张。

交付（每条先写红测试，函数名带 `testSlides_`；铁律 10：先探针）：
1. **探针**：macOS 27 上把 PDF 的一页渲染成位图：渲染到多大（按节目画布还是按页面自身）、色彩（sRGB / 显示 P3 的页怎么处理）、一页要多久、几十页的 PDF 占多少内存。结论写进报告，再写正式代码。
2. **图片组**：一个文件夹或多选的文件；排序规则按 040（文件名的自然顺序）；支持的格式沿用现有图片输入。
3. **PDF**：一页一张；加密、损坏、空文件的状态与 `last_error` 按 040。
4. **分段**：段名、每段从第几张起；跳到某段的开头。
5. **翻页**：上一张、下一张、跳到第 n 张；命令怎么到达输入按 040。`testSlides_flipLandsOnNextTick`：翻页生效那一拍之后取到的第一帧就是新页，没有黑帧、没有旧页多留一拍。
6. **预载**：下一张（和上一张）提前解好放着，翻页不卡；预载几张、占多少内存有上限，超了丢最远的。`testSlides_memoryBounded`：60 页的 PDF 连翻一遍，内存不随页数线性涨（量法参考文件输入循环泄漏那次的做法）。
7. 当前页号进状态 / Stats（字段按 040），到头 / 到尾时的行为按 040。
8. 文件被移走、换了内容时不崩，状态说人话。
9. `swift test`（SwitcherInputs 整包 0 红）；`make lint BRANCH=w6-inputs-slides`，归属检查带 `--base p7-contracts`。

不做：视频进列表（以后加）；直接读 .pptx / .key（只吃导出的 PDF 或图片）；App 的格子和设置页（W6-G1 / W6-G2）；翻页动画。
拿不准的不自己定，写进报告 §4。
报告 reports/w6-inputs-slides.md（五段）：探针的数（尺寸、色彩、耗时、内存）；预载策略的实测。不 push、不 merge。
