现象（Codex 在 main 1f9be64 的隔离实例上实测；g11 树这几处没变）：
- NS02（审计 high）：默认 127.0.0.1:8765、没 token：带 `Origin: https://attacker.invalid` 的 WS 升级 101，立刻收到全量快照（含推流密钥），发 setPreview 生效——任何能让本机浏览器发回环 WS 的网页都能读状态、切节目。路由没看 Origin；token 为 nil 时中间件根本不装。
- NS05：兼容层开着时，带外部 Origin 的 `GET /api?Function=Cut` 200、program 变了；没有 token 也没有来源校验（上游协议就是 GET）。
- NS07：兼容层 TCP 一个连接只发不带换行的数据，`pending` 无界增长（2 MiB → RSS +4.2 MiB）；没有行长 / 连接数上限。
- N12：`StateFeed.loop()` 在订阅表锁外编码旧快照；这期间来的 `subscribe()` 先补发最新的，随后旧的扇出到它 → 新订阅收到 `[2, 1, 2]`；Stream Deck 的 `SwitcherClient.handle` 直接覆盖快照，窗口内 toggle 可能按旧目标。
- NS03（已知 S2）：GET /api/v1/state 与 WS 快照原样带 `outputs[].settings.stream.url / streamKey`。
- NS10 / NS11（low）：插件收到 `state.inputs` 是对象的快照时 `tally.js` 的 `inputs.find` 抛 TypeError、Node 进程退出；连上后 `logger.info` 原样写带 `?token=` 的 URL。
- NS08 明文 / NS06 输入编号：NS08 的提醒文字归 130、手册归 W4-C5，TLS 不做（等用户定）；NS06 = 032 已修（G11 回归用例在）。

做（先写红用例再改；用例名带 ID `testNS02_…` / `testN12_…`）：
1. **NS02 + NS05 浏览器来源拦截**（一套 `BrowserRequestGuard` 中间件，主 API 的 HTTP 路由 + WS 升级 + 兼容层 HTTP 三处共用；TCP 不涉及）：请求带 `Sec-Fetch-Site` 且值不是 `none` / `same-origin`，或带 `Origin` 且不在白名单 → 403（API：`{"error":"forbidden-origin"}`；兼容层：`text/plain` "Forbidden"），命令不进总线、不订阅。`APIServerConfiguration.allowedOrigins: [String]`（默认空 = 不放任何浏览器来源）、`VMixCompatConfiguration.allowedOrigins` 同；`Origin: null` 算不在。非浏览器客户端（Stream Deck / Companion / curl / URLSession）两个头都不带，不受影响——现有 APIServerTests / HTTPTests / C5CompanionScriptTests 一条都不该变红。token 配了也照拦（token 可能被泄到网页里）。用例：带 Origin 的 WS 升级 403 且没收到快照、不带的 101；`Sec-Fetch-Site: cross-site` 的 POST /api/v1/command 403 且状态不变；白名单里的来源放行；兼容层带 Origin 的 Function=Cut 403、program 不变。App 侧：ControlRuntime 不传就用默认（空白名单），设置页不加项（要加写进报告 §4）。
2. **NS07 兼容层 TCP**：`CompatTCPServer.maxLineBytes`（建议 64 KiB）——一行超过就断开这个连接（日志一行）；`maxConnections`（建议 64）——满了新连接直接关；**不加空闲超时**（订阅 TALLY 的客户端本来就只收不发）。用例：发 65 KiB 不带换行 → 连接被断、服务还能接新连接；65 个连接第 65 个被关；正常命令 / SUBSCRIBE 推送照旧。
3. **N12 快照顺序**：每个订阅者记"最后发出的快照键"（`(sequence, tick)`，不能只比 sequence——同 sequence 的动画拍更新要发），`fanOut` 带上快照键、比它旧的不发；`subscribe()` 补发时登记键。Codex 那条搬进 SwitcherControlTests 改名 `testN12_…`（用 clockProvider 暂停推送线程的那套交错）转绿；再加一条"同 sequence 不同 tick 照发"。
4. **NS03 提案 035**（docs/contract-changes/035-api-state-stream-credentials.md，**写完停下来问用户**；没批就只做 1–3 / 5）：建议 API 对外的状态（GET state / WS snapshot；tally 不涉及）把 `streamKey` 换成标记 `<redacted>`、`url` 过 `StreamURLRedaction.redact(url:)`（与诊断包同一份名单）；`setOutputSettings` 收到标记值 = 保留原值（契约一句）；要原文的加 `?secrets=1` 且必须带 token（回环且没 token 也不给）。JSON 形态不变。备选：换 DTO（`hasStreamKey`）——形态变、客户端要改，写进提案让用户挑。批了就落：APIModels / StateFeed / APIServer + 用例（快照里找不到测试密钥；带 token 的 `?secrets=1` 有）。
5. **NS10 / NS11 Stream Deck**：`SwitcherClient.handle` 收 snapshot 前校验 `state.inputs` / `state.outputs` 是数组（不是就丢掉这条、`log` 一行、不改 snapshot）；`emit` 的监听回调包 try/catch（重画抛异常不带走进程）；`connected` 日志只写 host:port，错误日志过一遍"去 token= 查询项"；`Tools/streamdeck-plugin/test/` 加 node --test 用例：畸形快照不抛、合法快照照旧重画、日志里没有 token。
