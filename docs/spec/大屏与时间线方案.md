来由是用户 2026-11-13 提的三件事和一个总要求：

1. 监看框要贴合画面比例（现在窗口一拉大，框跟着变大，画面上下一大片黑）；横屏、竖屏要能选，竖屏时界面排布要跟着变，不能挤得看不到几路输入。
2. 异形屏、多块屏（主屏 + 两侧耳屏，实际做过 1366×762 这种非标分辨率）：要能"先定一路 1080p / 4K 的输出，再在里面画出几块屏"，按屏放内容，监看里看得清每块屏上是什么；一路输入可以铺满整幅大屏，另一路只上两边的小屏。
3. 时间线：五六七块屏同时换内容，一块一块按太费劲；专门做大屏的老师习惯先把时间线编完，现场只管往下走。
4. 现在的软件只做了视频导播，没做大屏导播；希望两者合在一起，像剪辑软件那样有两套工作面板，互相耦合。

2026-11-14 用户把他脑子里的场景讲了一遍（整理自原话），本方案的第二层以它为准：

- 一面 20.5:9 的 LED 墙。中间放一个 16:9，左右各剩一条 2.25:9，当耳屏用。耳屏是在一面墙上人为分出来的，不是另外两块屏。
- 主视觉一定是 20.5:9，铺满整面墙。平时放视频、PPT 是 16:9，进中间，这时候两边耳屏要出来。
- 还在导播界面里，切到主视觉，整个屏幕的布局跟着变成铺满。从中间的 16:9 视频切到采集卡进来的另一台电脑的 PPT，只有中间在动，耳屏不动。
- 在"屏幕"那一页可以设置每个"节目"长什么样，也可以定每个素材去哪块屏。
- **大屏和导播切的是同一个输出，是同一个东西。**

## 0. 结论先行

- **能做，而且不用推倒重来。** 现有引擎有四样东西正好是大屏播控要的：所有切换都落在拍点上的单一状态机、"从一张纹理里取一块画到另一处"的合成能力（多画面和缩略图现在就这么画）、从属节目时钟的文件输入、任意宽高的节目格式（16…8192，竖屏已经在合法范围里）。节目里没有配大屏时，状态、画面、输出与现在逐字节相同。
- **大屏就是节目画面，不是另一路。** 一个节目只有一幅 PGM、一幅 PVW、一套转场。做大屏时，节目画布按现场的屏画出来，再定几个**布局**，每个布局把画布分成几个**分区**；每路输入记着自己上屏时去哪个分区（**上屏位置**）。切换还是原来那一下：这一路进它的分区，同一个布局里别的分区不动；它的分区属于另一个布局，整幅屏就换成那个布局。
- **三件事对应三层，可以分开交付：**
  - 第一层（只动界面，约 1 个会话）：监看框贴合画布比例；横屏时上边整幅给监看，调音台挪到下边、和输入区同高，输入区折行；中间那一列按高度自动收放（时钟不是必选），很宽的画布监看自动叠放，监看下面不留一大片空白；竖屏时监看占满左边，输入和调音台叠在右边；节目格式页加横 / 竖屏预设。
  - 第二层（契约 + 渲染 + 引擎 + 输出 + 界面，约 5 个会话 + 1 个检查点）：**把节目画布分区**。画屏幕、定布局和分区、给输入定上屏位置；合成从"一路输入铺满画布"变成"每个分区画它那一路"；另加**输出口**，把屏幕按信号里的位置打包，送给 LED 处理器。
  - 第三层（约 4 个会话 + 1 个检查点）：**画面预设**（一个布局 + 每个分区放什么，存下来一键调用，就是 HiRender 里的"节目"）和**时间线**（把预设排成提示点序列，现场按一下走一步，或定时自动走）。
- **两套工作面板看的是同一幅画面**：工具条上"导播 ｜ 大屏"切换。导播面板按输入切（点一路，它进自己的上屏位置）；大屏面板按分区和预设排（点分区再点输入、调预设、走时间线）。PVW、PGM、转场、输入、调音台、输出都是同一份，在哪个面板操作结果都一样。
- **操作方式不变**：点一下进预监，按切换才上屏；⇧ 点或打开"直出"就直接上。时间线只是替你把下一步装进预监，GO 就是切换。
- **和现场常用的软件对得上**（§6）：画面预设就是 HiRender S3"节目管理"表里的一列节目；画布和输出口分开摆就是它 5.x"显示管理"里的舞台区域和输出区域。两处不同：它点节目就上屏，我们默认先进预监（另有"直出"开关）；它只能按节目切，我们还能按输入切、布局跟着走，这是导播台带来的。
- **不算难，但量不小**。没有哪一块是引擎做不到的：现在的合成本来就是"先画底、再把新画面按转场盖上来"，要改的只是把目标从整幅换成分区的矩形。工作量主要在两个编辑界面（屏幕编排、时间线）。真正要先验证的有三处（§9.3）：外接显示口能不能逐像素送出、多个输出口之间差不差帧、大画布在入门机型上的渲染耗时。

### 0B.3 一拍里发生什么

1. **状态机**：先走时间线（有到点的提示点就把它的动作当命令应用）→ 推进转场、FTB、叠加动画的进度 → 应用这一拍收到的命令 → 发布新快照。
2. **引擎**：为每路输入挑"时间戳不晚于这一拍"的最新一帧。
3. **渲染**（同一个命令缓冲区）：PGM（按布局画各分区 → 转场 → 叠加 → FTB）→ PVW → 多画面 → 各输出口。
4. **派发**：PGM 给编码、录制、NDI、虚拟摄像头；输出口画面给外部显示和 NDI。谁慢谁自己丢帧，不拖渲染。
5. **界面**：各监看按自己显示器的刷新率取最新画好的纹理。

合成只有一路，所以墙上的每一块永远在同一拍换。比 v0.2 少画两幅（没有另外的舞台 PGM / PVW），也没有第二套转场。

### 0B.4 数据放在哪

节目文件（一个 JSON）里一共这几节：输入（含幻灯片列表的页和分段）、切换、音频、输出、**舞台**（屏幕、输出口、布局与分区、每路输入的上屏位置、画面预设）、**时间线**（分段、提示点）、界面布局。没有舞台和时间线两节的老文件照常打开。

### 0B.5 界面的骨架

- 主窗口从上到下：工具条（正中是"导播 ｜ 大屏"）→ 监看区 → 下边一行（输入区 ｜ 调音台）→ 底栏和状态行。
- 两个面板的监看、转场列、下边一行、底栏是同一份。切到大屏面板只是多出三样：布局与编排的工具行、画面预设条、时间线；监看里的分区可以点。
- 独立窗口：屏幕编排（做大屏时用）、多画面、输入设置、音频设置、输出设置、统计（已有）。

### 0B.6 不变的东西

- 节目里没配大屏，状态、画面、输出与现在逐字节相同。
- 一个节目只有一幅 PGM、一幅 PVW、一套转场、一个 FTB。配不配大屏都一样。
- 铁律全部适用于新部分：渲染线程每帧零分配、统计只有一份、切换只在拍点生效、先写测试。
- 录制、推流、虚拟摄像头取的是 PGM。

## 1. 现状（都是在代码里查到的）

### 1.1 监看框为什么上下一大片黑

- 主窗口上半区是"PVW ｜ 转场列 ｜ PGM"，下面是输入条（`App/Sources/UI/MainWindowController.swift` 的 `buildLayout`）。窗口变大时输入条和调音台保持原尺寸，多出来的宽高**全部**给上半区（`splitView(_:shouldAdjustSizeOfSubview:)`）。
- 监视器 = 26 pt 标题条 + 一块铺满的显示视图（`MonitorView`）；显示视图把节目纹理**等比缩进去、四周清成黑**（`MetalDisplayView` 调 `Placement.fill`）。所以框的形状是窗口给的，不是画面的。
- 输入条只有一行、横向滚动（`InputStripView`），高度固定 197 pt。

按 `Theme` 里的常数算（工具条一行 52、底栏 58、输入条 197、转场列 150、调音台 340），与 docs/user/img/main-window-zh.jpg 的实拍一致：

| 窗口 | 监看画面区（每个） | 16:9 画面本身 | 画面占监看区 | 输入条露出 |
|---|---|---|---|---|
| 1100×720（最小），调音台开 | 302×386 | 302×170 | 44% | 3 路 |
| 1440×900，调音台开 | 472×566 | 472×266 | 47% | 5 路 |
| 1440×900，调音台收起 | 643×566 | 643×362 | 64% | 6 路 |
| 1728×1117（16 寸全屏），调音台开 | 616×783 | 616×347 | 44% | 6 路 |
| 2560×1440，调音台开 | 1032×1106 | 1032×581 | 53% | 10 路 |

结论：监看区一半左右是黑边，而输入条不管窗口多高都只有一行。竖屏画布时这块高的监看区正好用上（用户说的"竖屏很方便"），横屏时是浪费。

### 1.2 节目格式已经支持什么

- `ProgramFormat` 的宽高是任意整数，合法范围 16…8192（提案 034）。设置 › 节目格式里有"自定义"，范围 320–7680 × 240–4320、取偶数（`PreferencesModel`）。**1080×1920 竖屏、1366×762 这样的非标尺寸今天就能填**，引擎、渲染、编码都按它走。
- 缺的是：没有横 / 竖屏的预设和一键互换；界面排布不看画布比例；竖屏时缩略图被钳在 16:9 的框里（`InputCellView.thumbnailHeight`），画面只有框的三分之一宽。

所以"只有一块非标屏"的情况现在就有办法：节目格式填成那块屏的分辨率（比如 1366×762），外部显示输出 PGM。第一层做完后监看框也会贴合它。

### 1.3 现在怎么做三联屏，为什么难用

合成顺序是固定的：PGM 底（一路输入铺满）→ 转场 → 叠加 1–4 → FTB（`CompositorPasses.encodeProgram`）。要做"主屏 + 两耳"只能把节目格式设成输出信号的尺寸，再拿叠加通道当画中画，一路一路手调位置和缩放。问题有四个：

1. 叠加通道只有 4 路，三块屏各放一路就用掉 3 路，字幕没地方了。
2. 位置是"占节目画面的比例"，要自己把像素换算成比例。
3. 监看看到的是**打包后的输出画面**：屏幕按信号里的摆法挤在一起，和现场的样子不一样，小屏看不清。
4. 换内容要逐路改叠加；五六块屏同时换没有办法落在同一拍。

### 1.4 现成能用的零件

## 2. 第一层：主窗口新排布（监看贴合、调音台挪到下边、横竖屏）

2026-11-14 按用户三条反馈改过：横屏时调音台挪到下边、和输入区同高，上边整幅留给监看；竖屏排布重排；监看下面不许空出一大片，中间那一列（带时钟）要自动收放。

### 2.1 规则

1. **监看框 = 画面。** `MonitorView` 的画面区加一条宽高比约束（= 节目格式的宽 : 高，换节目格式时更新）。框外是窗口底色，不再有黑边。
2. **横屏（画布宽 ≥ 高）：上边整幅给监看，下边一行是"输入区 ｜ 调音台"。**
   - 上边：PVW ｜ 转场列 ｜ PGM，横贯整个窗口宽度，不再被调音台占掉 340。
   - 下边一行：左边输入区，右边调音台，**两者同高**。调音台默认宽 340，中间的分隔条可拖；收起调音台后输入区占满整行。
3. **上半区的高度由画面算出来。** 监看宽 `w = (窗口宽 − 转场列 150 − 间隙 4) / 2`，贴合高 `h = w × 画布高 / 画布宽 + 标题条 26`。上半区高 = `max(h, 中间那一列当前这一档的高)`（规则 9）。其余高度全给下边一行。
4. **输入区是会折行的格子。** 一行放不下就折到第二行、第三行，整块竖向滚动；格子的三档大小不变。一行放完之后多出来的宽度，平均分到两头的留白和格子之间，每个空隙一样大（检查点 1 用户看真机后定，§2.6）。
5. **竖屏（画布宽 < 高）：左边整列给监看，右边一栏是"输入区在上、调音台在下"。** 就是把横屏的排法转了 90°：监看占满一条边，输入和调音台共享另一条边（§2.3）。
6. **调音台的高度跟着位置走。** 条子现在的自然高约 380（推子 170）。行高够就和现在一样，更高时推子跟着变长；不够时推子缩短（最短 60），再不够就把声像、总线送出、跟随视频三行收进条子的齿轮，只留名字、表和推子、读数、静音与独听。
7. 分隔条仍然可以拖：横屏往上拖是让下边一行更高（监看等比变小、居中），往下最多拖到贴合高，不会再拖出黑边。收起 / 展开调音台、改节目格式、缩放窗口都按上面几条重算。
8. 留一个开关"窗口 › 排布 › 新排布（默认）/ 旧排布"，旧排布 = 今天的样子（调音台在右侧通高、监看区自由高度），给习惯了的人。
9. **中间那一列自动收放，监看下面不留一大片空白**（用户 2026-11-14 指出：窗口 1440×900 配 2460×1080 的画布，监看下面空了 101）。空白是时钟撑出来的：时钟就在这一列的最下面（`TransitionPanelView` 里的 `ClockView`，56 高），整列摆满约 392 高，监看比它矮时上半区被它撑高。时钟不是必选项，改成四档自动选：

   | 档 | 摆什么 | 高（按代码里各行的高度加出来） |
   |---|---|---|
   | 全 | Cut、转场 1–4、FTB、叠加 1–4、T-bar 组（当前槽、时长、T-bar）、时钟 | 392 |
   | 不带时钟 | 收起时钟 | 328 |
   | 紧凑 | 再收起"当前槽"和"时长"两行（每个转场槽的 ▾ 里都有，不丢功能） | 280 |
   | 最小 | 再收起 T-bar，只留 Cut、转场 1–4、FTB、叠加 | 228 |

   - 选法：取"放得下的最大一档"。放得下 = 这一档不比监看高出 24 以上，并且不会因此少露一行输入。所以监看下面最多空 24，不到一行按钮的高度。
   - 窗口拉大、监看变高，收起来的东西按相反的顺序自己回来。同一个窗口尺寸不管是拉大拉到的还是缩小缩到的，选中的档一样（并排还是叠放另有粘性，见规则 10）。
   - 时钟收起时，时间改在状态行右端用小字显示。
   - 时钟另给一个偏好"显示 › 时钟：自动（默认）/ 一直显示 / 不显示"。选"一直显示"就回到今天的样子，宁可空着也留时钟。
   - 各档的高度实现时用 `fittingSize` 量，不写死。现有用例只保证整列 ≤ 409，392 是按 `TransitionPanelView` 里各行的高度和间距加出来的，真机以量的为准。
10. **很宽的画布，两幅监看自动上下叠放。** 并排时每幅监看只有半个窗口宽，画布越宽画面越矮，矮到连最小档都比它高。叠放时 PVW 在上、PGM 在下，中间那一列挪到右边，每幅监看能用到整个宽度。
    - 什么时候换：叠放的画面比并排大三成以上；或者并排时监看下面空得超过 24，而叠放更大。三成这道门槛是为了不让窗口拉一拉就来回跳。
    - 有粘性（检查点 1 定，§2.6）：已经叠放之后，要等叠放的画面小到并排的 1.15 倍以内、而且上面第二个条件也不成立，才换回并排。换节目格式、切新旧排布、窗口刚打开时按上一条重新定。示意页里的算法没有粘性，只演示无状态的规则。
    - 叠放时下边一行至少留两行输入（并排时本来只有一行的留一行），监看在剩下的高度里尽量大。
    - 5760×1080（三块 16:9 连成的墙）在 1440×900 的窗口里：并排每幅 643×121，叠放每幅 1016×191。2460×1080（20.5:9）不叠放。

|---|---|
| 舞台（Stage） | 做大屏时的节目画布：按现场的相对位置摆着所有屏幕，单位是 LED 的像素点。PGM、PVW 画的就是它 |
| 屏幕（Screen） | 舞台上的一块矩形，对应现场一块物理屏。一整面墙是一块屏幕；主屏加两块分开的耳屏是三块屏幕 |
| 输出口（Raster） | 一路送出去的信号的整幅画面：1920×1080、3840×2160 或自定义。由一个已有的输出（外部显示 / NDI）送出 |
| 映射（Mapping） | 一块屏幕落在某个输出口的哪个矩形里（位置，可选旋转 90° 倍数、镜像） |
| 布局（Layout） | 把舞台分成几个分区的一种分法。一个节目可以有几个布局（"整屏"、"中间 + 两耳"），屏上同一时刻用其中一个 |
| 分区（Zone） | 布局里的一格，放一路输入。由一个或几个矩形组成 |
| 上屏位置（Home） | 每路输入的一项设置：切到它时，它去哪个分区 |
| 画面预设（Look） | 一个布局 + 它每个分区放哪一路，存下来一键调用 |
| 时间线（Timeline）、提示点（Cue） | 见 §4 |

用户口头说的"节目"（"这个节目是什么样的、那个节目是什么样的"）是 HiRender 的叫法，对应这里的画面预设。软件里"节目"已经指整场的文件和 PGM，所以界面上叫"画面预设"。

### 3.2 一幅画布，两种摆法

```
输入
  │  进它的分区（适应 / 填满 / 拉伸 / 点对点）
  ▼
舞台 = 节目画布（PGM / PVW）  ← 监看、录制、推流看这个：屏幕按现场位置摆
  │  每块屏幕取画布上自己那一块
  ▼
输出口画面                    ← 送给 LED 处理器的 1080p / 4K：屏幕按信号里的位置摆
  │
  ▼
外部显示 / NDI（已有的输出）
```

- **舞台就是 `ProgramFormat` 的那幅画布。** 做大屏时画布的宽高 = 所有屏幕的外接矩形，由屏幕编排算出来写进节目格式；帧率照旧自己选。没配大屏时画布是 1920×1080 这类标准尺寸，一切和现在一样。
- **画布和输出口分开摆**，因为现场的摆法和信号里的摆法可以不一样：一条 5760×1080 的长屏要折成两行才塞得进一路 4K；主屏和两块分开的耳屏要挤在一路 1080p 里。分开以后监看永远是现场的样子，信号里怎么摆只在接线时看一次。把两者混成一张图，就是 §1.3 第 3 条的毛病。
- 用户说的"先定一路 1080p / 4K 的输出，再在里面画屏幕"是最简单的情况：一个输出口，屏幕在里面的位置和现场一样。新建时默认就是这样，画一次就够；摆法不一样时再到"输出口"页签里改。
- 改屏幕（加减、挪位置、改尺寸）会改画布尺寸，等同于换节目格式，要重建渲染，开演前做。改布局、分区、上屏位置、预设是轻的，演出中可以改。

### 3.3 布局、分区、上屏位置

- **布局**是一个分区列表，从下到上。同一个布局里的分区一般不重叠（中间 + 两耳），也可以叠着（一个铺满的底 + 上面一个小窗）。空着的分区是透明的，露出下面的分区；最底下是黑。
- **分区**由一个或几个矩形组成，两种铺法：
  - **跨屏**（一个矩形）：这一路按矩形铺一幅，每块屏显示落在自己身上的那部分。"整屏"就是一个盖满舞台的矩形。
  - **各放一份**（多个矩形）：每个矩形里各放一份。"两耳放同一张图"就是一个含两个矩形的分区。
  - 每个分区有默认的适配方式（适应留边 / 填满裁边 / 拉伸 / 点对点），放进去的内容可以单独改；输入自己的裁切和位置设置照旧生效。
- **每路输入有一个上屏位置** = 某个布局里的某个分区。
  - 没设过的输入用"默认分区"（屏幕编排里标星的那个，一般是放 16:9 的那一格）。
  - 上屏位置显示在输入格子上（"→ 中间"），右键能改；在大屏面板里把格子拖到监看里的某个分区上也能改。
  - 屏幕编排里有"按形状分配"：每路输入找宽高比最接近的分区，列出来给人确认，确认后写下来，之后不会自己变（信号中途变了分辨率也不变）。
- **墙面状态** = 用哪个布局 + 每个分区放着哪一路。所有布局的分区内容都记着，所以从"整屏"切回"中间 + 两耳"时，两耳还是上次的内容。墙面状态有两份：**节目**（现在屏上）和**预监**（切换之后）。
- 新建舞台时自动有一个"整屏"布局；屏幕多于一块时再自动给一个"每屏一格"。模板：整屏、中间 16:9 + 两耳、左右对半、三等分、每屏一格、底 + 小窗。

### 3.4 切换

规则只有这几条。导播面板、大屏面板、快捷键、API、时间线都走它：

1. **点一路输入**（数字键、API 的 `setPreview` 相同）：预监 = 屏上现在的样子，再把这一路放进它的上屏位置。它的分区在当前布局里，预监里就只有这一格变；它的分区在别的布局里，预监换成那个布局，那个布局里别的分区是它们上次的内容。
2. **切换**（Cut、当前转场、T-bar，就是现在转场列里那几个）：预监上屏。之后预监变成切换前的样子，再按一次就切回去。和现在一样是对调。
3. **⇧ 点，或打开"直出"开关**：不经预监，这一拍直接上屏。"直出"放在转场列里，一眼看得到；默认关。
4. **⌘ 点**：在预监现有的基础上再放一路，攒几格一起切。
5. **在大屏面板里先点分区、再点输入**：把任意一路放进任意分区的预监，不看上屏位置。
6. **调画面预设**（键位见 §5.3）：一次把布局和几个分区的内容装进预监（直出时直接上屏）。五六块一起换靠它。
7. **转场只在变了的地方做。** 布局没变：只有内容变了的分区做转场，别的分区一个像素都不动。布局变了：整幅一起做。第一版 Cut 和 Fade 按这条做；Wipe、Zoom、Stinger 第一版先整幅做，之后再细化到分区里。
8. 同一路输入换前换后都在屏上（哪怕换了分区）不重播，片子接着放。输入被删掉时，放着它的分区清空。
9. FTB、叠加 1–4 不变，都对整幅画布。叠加以后可以加"限定在某个分区里"（字幕条只压在中间那一格）。
10. **对位图**一个按钮：每块屏显示自己的名字、像素尺寸、边框、对角线，接线时用。

拿用户的场景对一遍（墙是 20.5:9；两个布局"整屏"和"中间 + 两耳"；主视觉的上屏位置是整屏，视频、PPT 电脑、机位是中间，耳屏图是两耳）：

| 屏上现在 | 操作 | 结果 |
|---|---|---|
| 中间 = 视频，两耳 = 耳屏图 A | 点"PPT 电脑"，切换 | 中间换成 PPT，两耳不动 |
| 中间 = PPT，两耳 = 耳屏图 A | 点"主视觉"，切换 | 整面墙换成主视觉，布局跟着变成"整屏" |
| 整屏 = 主视觉 | 点"视频"，切换 | 布局回到"中间 + 两耳"：中间 = 视频，两耳 = 上次的耳屏图 A |
| 中间 = 视频，两耳 = 耳屏图 A | 点"耳屏图 B"，切换 | 两耳换成 B，中间不动 |
| 任意 | 调预设"PPT + 耳屏 B"，切换 | 中间和两耳同一拍一起换 |

### 3.5 状态与命令（草案，正式的走契约提案 036 / 037）

```swift
struct StageState {                       // MixerState.stage；nil = 没配大屏，一切与现在相同
    var screens: [StageScreen]            // 屏幕：id、名字、画布上的矩形
    var rasters: [StageRaster]            // 输出口：id、名字、宽高、每块屏幕在里面的矩形（可旋转 / 镜像）
    var layouts: [StageLayout]            // 布局：id、名字、分区列表（下 → 上）
    var defaultZone: Int                  // 没设上屏位置的输入去哪个分区
    var homes: [Int: Int]                 // 输入编号 → 分区 id
    var looks: [StageLook]                // 画面预设：名字 + 布局 id + [分区 id: 内容]
    var program: WallState                // 现在屏上
    var preview: WallState                // 切换之后
    var direct: Bool                      // 直出
    var testPattern: Bool                 // 对位图
}
struct StageZone { var id: Int; var name: String; var rects: [PixelRect]; var spread: ZoneSpread; var fit: ContentFit }
struct WallState { var layout: Int; var contents: [Int: ZoneContent] }     // 分区 id → 内容；所有布局的都记着
struct ZoneContent { var input: Int; var fit: ContentFit?; var crop: CropInsets?; var opacity: Double }
```

- 画布尺寸仍是 `MixerState.format`。`program` / `preview` 两个编号保留，含义变成"最近一次切上屏的那一路 / 最近一次选进预监的那一路"，老接口和兼容层照读。
- Tally 改由墙面状态推导：在节目墙面当前布局的分区里就是红，在预监墙面里就是绿；叠加、转场中的口径不变。音频的"跟随视频"用同一个判断。
- 现有命令的含义不变，只是落点从"整幅"变成"它的分区"：`setPreview`、`setProgram`、`cut`、`autoTransition`、`fade`、`tbar`、`useTransitionSlot`、`ftb`、`overlay`。
- 新命令：`setStage`（屏幕 / 输出口 / 布局 / 分区的整体替换，等同于改设置）、`setInputHome`、`setZonePreview` / `setZoneProgram`（指定分区放哪一路；⌘ 点和大屏面板用它）、`storeLook` / `recallLook` / `removeLook`、`setDirect`、`setTestPattern`。全部和现有命令同一口径：纯函数、拍点生效、非法的原样返回。
- `OutputSource` 加 `.raster(number: Int)`，沿用现有的外部显示选屏、拔线口径（提案 013 / 015）、`Stats.display[]`；之后再加"只取画布上的一块"（§3.7）。
- 编排数据（屏幕、布局、预设）很少变，运行状态（两份墙面状态、转场进度）才逐拍变；渲染线程每拍只读后者和几个矩形。

### 3.6 渲染

现在的 PGM 是四步：画底（PGM 那一路铺满画布）→ 转场（把 PVW 那一路按进度盖上来）→ 叠加 1–4 → FTB（`CompositorPasses.encodeProgram`）。配了大屏之后还是这四步，只改前两步的目标：

1. **画底**：清黑，按节目墙面当前布局的分区从下到上画。每个分区的每个矩形开一个裁剪框，把那一路按适配方式画进去。
2. **转场**：布局没变时，只对内容变了的分区，把新的那一路按进度盖在它的矩形里（Fade 是不透明度；清空的分区盖一层按进度变黑的底）。布局变了时，把预监墙面整幅按进度盖上来。没变的分区第 1 步画完就不再碰。
3. **叠加、FTB**：不变。
4. **PVW**：按预监墙面画一遍（现在是 PVW 那一路铺满）。画布很大时按缩小的尺寸画，除非有输出要 PVW。
5. **各输出口**：清黑，把每块屏幕在画布上的那一块画到它在输出口里的矩形。尺寸一致时采样点正对像素中心，逐值相同。输出口纹理交给外部显示窗口；有 NDI 要它时再转一次 NV12。

没配大屏时走原来的代码路径，一个字节都不变。"配了一个盖满画布的分区"和"没配"画出来必须逐值相同（V20）。比 v0.2 省：不用另画舞台 PGM、舞台 PVW 两幅，也没有第二套转场。

热路径规则不变：布局、分区的表在换快照时解析成定长数组（和 `MultiviewLayoutTable` 同一做法），渲染线程每拍零分配。要补的两处：`Placement.fill` 现在只有"适应"，加填满 / 拉伸 / 点对点三种；Wipe 的遮罩现在按整幅画面的坐标算，分区里做 Wipe 要改成按矩形算。

规模上限（用户已定，§0A Q5；大档的性能阈值量完再定）：屏幕 ≤ 16、分区合计 ≤ 24、布局 ≤ 8、输出口 ≤ 4、画布每边 ≤ 8192。

### 3.7 输出

- **送给 LED 处理器**走已有的两种输出：外部显示（HDMI / DP，最常见）和 NDI，来源选"输出口 n"。
- 点对点的条件写在界面上：显示器当前分辨率 = 输出口宽高、缩放 1 倍。对不上时输出设置页和底栏标黄，写明"这块屏现在是 A×B，输出口是 C×D，画面会被缩放"。
- 多个外部显示各按自己的刷新呈现，同一拍的画面在不同口上可能差一个刷新周期。要逐帧锁定得走 SDI 输出卡，放后面（§9.4）。
- **录制、推流、虚拟摄像头**取的是 PGM，做大屏时就是墙的画面（比如 2460×1080）。要给直播平台一路 16:9 时，把来源改成"只取一块"：一个分区或一块屏幕的范围（比如中间那一格），里面放什么就出什么。这一项排在第二层的后半，不挡检查点 3。
- **直播和大屏放不同的画面**（两边各切各的）这一版不做。用户的场景是同一个输出；真有这个需要时另做"第二路节目"（后续方案 §3.5 的多画布），不在本方案里。

### 3.8 界面

**导播面板**（配了大屏之后）：

- PVW、PGM 就是墙的样子，监看框贴合舞台的宽高比（§2）。分区的边线可以开关。舞台特别宽时两幅监看自动上下叠放（§2.1 规则 10）。
- 在监看里双击一个分区 = 只放大看这一格，再双击回来。墙很宽、分区很小的时候用。这是对用户最早那句"预览框里根本看不清中间是什么"的直接回答。
- 输入格子上多一个小标签写上屏位置（"→ 中间"）。红灯 = 现在在屏上，绿灯 = 在预监里，含义不变。
- 转场列多一个"直出"开关。

**大屏面板**：

  - "屏幕"：把屏幕拖到现场的相对位置，吸附对齐，X / Y / 宽 / 高可以直接填像素。
  - "布局"：左边是布局列表，右边在舞台上画分区。可以把一块屏切开（"中间放 16:9，两边剩下的做耳屏"一键出），可以把几块屏并成一格。标星的是默认分区。下面列出每路输入的上屏位置，带"按形状分配"。

- **预设表**（预设条的另一种视图）：行 = 分区（按布局分组），列 = 画面预设，格子里是输入。把输入拖进格子就是改这个预设；点列头 = 调这个预设。五六块屏时一眼看全每个预设里每块放什么，用过 HiRender 节目管理的人不用学。
- 节目里没配大屏时，大屏面板是一个引导页（"先画屏幕 → 定布局 → 给输入定上屏位置"）。

### 3.9 拿用户的 20.5:9 走一遍

现场：一面 LED 墙，2460×1080 个点（20.5:9）。LED 处理器吃一路 4K。

```
布局"整屏"                                   布局"中间 + 两耳"
┌──────────────────────────────────────┐    ┌────┬────────────────────────────┬────┐
│                整屏                   │    │左耳│           中间              │右耳│
│              2460×1080                │    │270 │        1920×1080           │270 │
└──────────────────────────────────────┘    └────┴────────────────────────────┴────┘
```

1. 屏幕编排 › 屏幕：画一块屏"主墙"，2460×1080。画布随之是 2460×1080。
2. 屏幕编排 › 布局：自动有"整屏"。再加一个布局，用模板"中间 16:9 + 两耳"：中间 1920×1080（从 x = 270 起），左耳、右耳各 270×1080（2.25:9），两耳合成一个分区、各放一份。默认分区标在"中间"。
3. 屏幕编排 › 输出口：建输出口 3840×2160，主墙放在左上角，1:1。处理器那边截同一块。
4. 上屏位置：主视觉（2460×1080 的图或片子）→ 整屏；耳屏图 → 两耳；视频、PPT 电脑（采集卡）、机位是默认的"中间"，不用设。
5. 存两个画面预设备用：预设 1"主视觉"（整屏 = 主视觉），预设 2"PPT + 耳屏"（中间 = PPT 电脑，两耳 = 耳屏图）。
6. 演出中就待在导播面板，和现在一样按：点"视频"、切换，中间换成视频，耳屏不动；点"PPT 电脑"、切换，中间换成 PPT；点"主视觉"、切换，整面墙换成主视觉；再点"视频"、切换，回到中间 + 两耳。监看里看到的就是墙现在的样子，中间那一格有多大就多大。

屏是分开的几块时做法一样。比如主屏 1366×762、两侧各一块 512×288 的耳屏、处理器吃一路 1920×1080：第 1 步画三块屏，按现场位置摆；第 2 步布局用"每屏一格"，再加一个"整幅"；第 3 步在输出口里把三块挤着摆（主屏放 (0, 0)，左耳 (1408, 0)，右耳 (1408, 288)），处理器按同样的坐标截取。

## 4. 第三层：时间线

### 4.1 形态：提示点序列，画在时间轴上

时间线 = 一串**提示点**。每个提示点 = "到这一步，屏上变成什么样（调哪个画面预设 / 改哪几个分区）+ 用什么转场 + 顺带发哪些命令 + 什么时候走"。

- 触发方式三种：**手动**（等操作员按 GO）、**跟随**（上一条走完 n 秒后自动走；或上一条里的片子放完时走）、**定时**（距时间线起点 hh:mm:ss.ff）。后续加时间码（LTC / MTC）。
- 提示点可以**分段**（用户 2026-11-14：一场 20–30 张 PPT 要分成几段）：段有名字和颜色，时间轴上是一条色带，列表里是一行段标题；可以直接跳到某一段的开头，段可以折叠。
- 界面上画成横向时间轴：行 = 分区（每个分区在每个提示点之后放什么，一段一段的色块，带输入名），外加一行"命令"（放片、上字幕、开始录制这类动作的标记）；列 = 提示点；手动提示点是一道停止线。看起来和剪辑软件的时间线一样，但编辑单位是提示点，不是任意摆放的素材块和关键帧。
- 同一份数据还有列表视图（一行一个提示点：编号、名字、触发、转场、备注），排练时改起来快。
- 这张"列 = 演出的一个时刻、行 = 每块屏放什么"的表，和 HiRender 的节目管理、Millumin 的 dashboard 是同一种东西，只是每列多了触发方式。

为什么不先做自由时间线（轨道上任意摆素材块、打关键帧，HiRender 的"时间轴线模式"、WATCHOUT 那种）：现场有实时信号（机位、PPT）时，"这段放多长"是不知道的，能预编的是**顺序和画面**，时刻要么等人按、要么跟着片子走。提示点序列两种都能表达，定时和跟随触发也能做出"片头放到 35 秒时两耳换画面"这种编排。它做不了的是位置、缩放、透明度随时间变的关键帧动画和素材块任意交叠。那一半以后作为"时间线片段"嵌进提示点（HiRender 的时间线层节点、Millumin 把 timeline 拖进 dashboard 都是这么嵌的），编辑器的工作量大约再多一倍（§0A Q4）。

### 4.2 和预监 / 切换的关系

时间线不另起一套出画机制，它只做两件事：**把下一个提示点的画面装进预监，到点替你按切换**。预监和 PGM 就是导播面板里那两幅（§3.4）。

- 走到提示点 n：PGM 是提示点 n 的画面，**PVW 自动是提示点 n + 1 的画面**。操作员看预监就知道下一步是什么。
- 按 GO = 这一拍切换（用提示点 n + 1 自己的转场），然后装下一条。
- 临时要改：直接在预监里换某个分区的内容再 GO，或者不走时间线，像平时一样点一路输入、切换；时间线停在原地，按"回到时间线"再接上。**时间线不锁住手动操作**，这是和纯播控软件最大的区别，也是导播台该有的样子。

### 4.3 数据与走带（草案，正式的走契约提案 038）

```swift
struct Timeline { var id: Int; var name: String; var sections: [CueSection]; var cues: [Cue] }
struct CueSection { var name: String; var color: InputColor?; var firstCue: Int }   // 分段：从哪个提示点起
struct Cue {
    var id: Int; var name: String; var color: InputColor?
    var trigger: CueTrigger                 // manual / afterPrevious(ticks) / onMediaEnd(input) / atTime(ticks)
    var look: Int?                          // 调哪个画面预设（可空）
    var zoneChanges: [Int: ZoneContent]     // 在预设之上再改哪几个分区
    var transition: CueTransition           // cut、用哪个转场槽，或指定类型 + 时长
    var actions: [CueAction]                // 相对本提示点起点的拍偏移 + 任意 Command
}
struct SequencerState {                     // MixerState.sequencer，运行状态
    var timeline: Int?; var cueIndex: Int; var running: Bool; var cueStartTick: Tick?; var detached: Bool
}
```

- `actions` 里放的就是现有的 `Command`：开叠加、文件输入从头播、幻灯片翻页、开始录制都行。**提示点因此不只是换画面，这些动作都能编进去。**
- **走带放在状态机的 `advance` 里**：每拍先看有没有到点的提示点和动作，到了就在这一拍应用。好处是时刻逐拍确定、不依赖界面线程、无界面模式能跑能测、和现有场景脚本同一个机制。
- 新命令：`timelineGo`、`timelineBack`、`timelineGoto(cue:)`、`timelineGotoSection(section:)`、`timelinePause(on:)`、`timelineSelect(timeline:)`、`setTimeline`（整体替换一条时间线的内容）。GO 可以绑快捷键、MIDI、Stream Deck、API。
- 运行状态进快照，界面、API、远程面板读同一份。

### 4.4 素材：幻灯片列表和放片

用户 2026-11-14 说明：大屏导播的素材主要是 PPT，一场 20–30 张，要分成几段。一张图占一路输入的话，16 路不够用，所以加一种输入。

**幻灯片列表输入**（契约提案 040，后续方案 §2.5 播放列表的落地）：

- 一路输入里装一串页。来源三种：一组图片（拖一个文件夹或多选）、一份 PDF（PPT / Keynote 导出，一页一张）、视频文件（后做）。只占一个输入编号。
- 页可以**分段**：段有名字，列表里显示段标题。
- 动作：下一张、上一张、跳到第 n 张、跳到某段开头。当前是第几张进状态快照，界面、API、时间线读同一份。
- 下一张提前准备好（图片预先载成纹理），翻页不黑不卡。
- 它就是一路普通输入：有自己的上屏位置，能当叠加，能放进任何分区。不做大屏、只做讲座直播时同样用得上。
- 格子上多两颗按钮（上一张 / 下一张）和"第 7 / 24 张"的读数；输入设置里看整串页的缩略图、拖动排序、分段。

**和时间线的关系：**

- 提示点的动作里可以写"某路幻灯片翻到第 k 张"。
- **按幻灯片生成提示点**：选一路幻灯片列表，一张一个提示点、段落照搬。20–30 张 PPT 的演出，时间线基本是自动出来的，再逐条补"这一张时两耳放什么"。
- 翻页笔的上一张 / 下一张就是时间线的上一条 / GO（§5.3）。

**PPT 的另一种接法不受影响**：讲者自己的电脑经采集卡、NDI 或屏幕捕获进来，是一路普通的实时输入，谁翻页都行。

**放片**：片子仍是文件输入。几块屏要帧同步放片时分两步：上一个提示点里先把这几路定位到开头并暂停（预卷，等解码就位），到点在同一拍放开；它们都从属节目时钟，之后不会互相漂。同步到不到同一帧要用烧了帧号的测试片验证（V17 的放片版）。片子很多的演出以后把视频也收进列表输入（两个列表交替用就能做片子之间的淡变）。片子的声音走调音台，和别的输入一样。

### 4.5 录下操作

"录制操作"开关：排练时手动走一遍（点输入、调预设、切换），软件把每一步连同时刻记成提示点；之后按 GO 重放，或把触发改成手动 / 定时。这是把时间线编出来最快的办法（后续方案 §5.4 宏的"按一遍记下来"）。

## 5. 两套工作面板怎么合在一起

### 5.1 同一幅画面，两种干活的摆法

工具条正中加"导播 ｜ 大屏"分段开关（⌘1 / ⌘2）。两个面板看的是同一幅 PVW、同一幅 PGM，用的是同一套转场。在哪个面板操作，结果都一样；切面板不会改变屏上的任何东西。

| | 导播面板 | 大屏面板 |
|---|---|---|
| 顺手干什么 | 按输入切：点一路，它进自己的上屏位置 | 按分区和预设排：点分区再点输入、调预设、走时间线 |
| 监看 | PVW / PGM | 同一幅，分区带边线和名字、可以点 |
| 多出来的 | 输入格子大，露得多 | 布局与编排的工具行、画面预设条、时间线 |
| **同一份** | PVW、PGM、转场列（Cut、转场槽、FTB、T-bar、直出）、叠加 1–4、输入、调音台、底栏的输出、状态行、设置、快捷键表、API、节目文件 | 同左 |

节目里没配大屏时，导播面板和现在完全一样，大屏面板是一个引导页。配了大屏以后，只用导播面板也能把一场活动做完（用户 2026-11-14 描述的就是这种用法）；大屏面板在编排、一次换好几块、走时间线的时候用。

### 5.2 既然是同一个东西，为什么还分两个面板

- **位置不够。** 预设条和时间线加起来要两百多 pt 的高度，和输入格子抢地方。导播面板把高度给输入，大屏面板把高度给预设和时间线。
- **手法不一样。** 切机位、切 PPT 是"按输入"；一次换五六块是"按预设"。各有各的顺手排法，底下是同一个东西。
- 另一种做法是不分面板，把预设条和时间线做成导播面板里能收起的两条。用户 Q10 定的是两个面板，先按两个面板做；检查点 2 看真机外观时可以再比一次（§11 决策 9）。

### 5.3 快捷键

只有一幅 PGM，所以切换键只有一套，在两个面板里一样，现有键位不变（`HotkeyTable.default`）：数字键选进预监，⇧ 数字直切，空格 Cut，回车走当前转场，F 是 FTB，⌥1–⌥4 执行转场 1–4，⌃1–⌃4 开关叠加 1–4。

新加的：

- 时间线 GO 是 → 和 PgDn，上一条是 ← 和 PgUp。翻页笔发的就是 PgUp / PgDn，拿它走时间线是现场的习惯做法。
- 画面预设暂定 F1…F10。v0.2 写的 ⌃1…⌃0 不行：⌃1–⌃4 已经是叠加开关。笔记本上 F 键要按住 Fn，所以另给一组 ⌃⇧1…⌃⇧0，两组都可改。开工时对着键表和系统自带的快捷键再核一遍。
- 给只做大屏的人留一个开关"大屏面板里数字键调预设、空格 = GO"（§0A Q8）。

### 6.2 大家共有的做法，本方案照做

1. **三层空间。** 内容所在的统一像素空间 → 逻辑屏 → 输出口上的一块区域。HiRender 5.x 的"显示管理"窗口左边是舞台区域、右边是输出区域，同一块表面在两边各有一份位置；取消同步之后在舞台区域按现场摆。这和 §3.2 是同一件事。
2. **输出映射拆成"取哪块"和"摆哪里"两步。** Resolume 把它做成两个阶段，后一个阶段的官方用途之一就是给 LED 处理器重排像素。
3. **素材不直接绑输出口。** 素材放进窗口或图层，屏幕框住舞台的哪一块就出哪一块；跨屏就是把窗口拉到盖住那几块屏。
4. **预编排 = 一键召回的状态 + 线性段落。** 状态是节目列、dashboard 的列、Preset、Memory；段落是时间线，用暂停点切开。走带都是"下一个"键（空格、方向键、PgDn、翻页笔）加具名跳转。
5. **实时信号是一等素材**，能和文件混排，而且不受走带暂停影响（HiRender 叫独立播放，WATCHOUT 叫 Free Running，Millumin 叫 independent layer）。
6. **外控归一成变量和触发器**，再接 MIDI、DMX、TCP / UDP 文本指令、时间码。

### 6.3 分歧，和我们取哪一边

- **所见即所出，还是先进预监再切换。** 媒体服务器（HiRender、WATCHOUT、Millumin、Resolume）一触发就上屏，预监只是软件里的旁路视图。屏幕管理类切换台每块屏一对 PVW / PGM，预设先进 PVW，一次 TAKE 多屏同换。**我们取切换台这一边**：软件本来就是 PGM / PVW 范式，多屏同拍换是它的直接结果。代价是用惯 HiRender 的人会觉得多按一下，所以"直出"开关放在显眼处（§3.4）。
- **时间线，还是预设表。** WATCHOUT 是纯时间线；切换台是纯预设，Barco 另有 Cue 序列；HiRender 和 Millumin 是混合型，一张"列 = 演出的一个时刻"的表，表里可以嵌时间线。**我们先做表这一半**（§4.1），自由时间线以后嵌进来。
- **图层属于谁。** 切换台的图层属于某一块屏；媒体服务器的窗口铺在整个舞台上。**我们的分区铺在舞台上**，所以能跨屏；预监是整面墙一幅（不是每个分区一对），所以布局变了也能先看到。
- **按什么切。** 媒体服务器和屏幕管理类切换台都是按预设（节目）切；导播台是按输入切。**我们两种都要**：每路输入有上屏位置，所以按输入切也能落到对的那一块（用户 2026-11-14 的场景）；预设管一次换好几块。
- **多屏同换靠什么。** 切换台靠 Master Memory 或 Preset 加全局 Take；HiRender 靠"一个节目就是一整列窗口一起换"。我们两样都有：画面预设是那一列，切换是那一下。

### 6.4 从 HiRender 借的具体做法

- 预设表：行 = 分区，列 = 画面预设（§3.8）。
- 同一来源跨相邻两个预设不重播（它叫跨节点）（§3.4）。
- 片子放完之后的动作：循环、定格、停、走下一条（§4.1 的跟随触发）。
- 翻页笔走带：PgUp / PgDn 和方向键（§5.3）。
- 识别显示、待命、一键开关全部输出（§3.4 的对位图；待命就是 FTB；全部开关底栏已有）。
- 采集类信号不跟着时间线暂停。我们的输入本来就是这样。
- 以后再借（§9.4）：给中控的 TCP / UDP 文本指令、LTC / MTC 时间码（触发与同步两种用法）、节目插播（优先级最高的一层，临时盖上去）、多边形表面与箱体网格、输出控制（到点给别的设备发指令）。

### 6.5 没查到的

### 9.2 工作量的实话

- 第一层：小。一个 App 会话。

### 9.3 要先写探针验证的三处（铁律 10）

1. **外接显示口逐像素输出**：非 HiDPI 模式下 drawable 是否等于显示模式的像素；CAMetalLayer 的色彩管理会不会改值（LED 处理器要的是原值）；窗口盖满全屏时有没有被系统合成器缩放。做法：把 1 像素棋盘格和灰阶条送到外接口，用采集卡回采逐值比。需要一块采集卡或一台 LED 处理器（BLOCKED-硬件，用户手里有）。
2. **多个输出口的相位**：两路外部显示同时送闪光帧，回采看差几帧、稳不稳定。
3. **大画布的带宽**：8192×2160 的画布 + 两路 4K 输出口，在 M1 Air（下限机）和 M5 Max 上各量一次渲染耗时，定 V19 大档的阈值。

### 9.4 明确先不做的

直播和大屏放不同的画面（第二路独立的切换，§3.7）、SDI 输出卡与逐帧锁定、多机联动与主备、边缘融合与几何校正（投影用）、多边形或旋转任意角度的屏幕、LED 逐点校色、自由时间线上的素材块与关键帧动画、时间码（LTC / MTC）、给中控的 TCP / UDP 文本指令、DMX / Art-Net、3D 舞台预览。这些是专业媒体服务器的地盘，本方案的定位是"会议和中小型演出里，一台 Mac 把导播和大屏一起管了"。其中时间码、文本指令、自由时间线片段三样离得最近，第三层做完后按需要排。

怎么保证 Opus 做对（写进每个 prompt，144 是样子）：

1. 先写红测试再实现，测试编号在 prompt 里列死。
2. 只准动的目录写死；契约一个字不许动。

## 10. 没有等答复的问题了；这一版替用户选的几个默认

十一条都有结论了（§0A）。下面几条是按"一个输出"重写时选的默认做法。不用专门答复，看着不对随时说，都改得动，也都不影响架构：

1. **切回原来的布局时，别的分区出上次的内容。** 从主视觉切回视频，两耳出的是上次放的耳屏图，不是黑的。
2. **点一路只换它那一格。** 要一次换好几格，用画面预设，或者按住 ⌘ 连点几路再切换。
3. **新加的输入默认去"默认分区"**（一般是放 16:9 的那一格）。格子上看得到，能改；也可以让软件按形状分一遍，分完由人确认。
4. **红灯 = 现在在屏上**，不管在哪一格；绿灯 = 在预监里。
5. **录制和推流录的是整面墙的画面**（比如 2460×1080）。要 16:9 的直播画面时，之后可以选"只取中间那一格"。
6. **直播和大屏放不同的画面**这一版不做（§3.7）。
7. **用户说的"节目"在界面上叫"画面预设"**，因为"节目"在软件里已经指整场的文件。想换叫法可以换。
8. **画面预设的快捷键暂定 F1…F10**，不是 v0.2 写的 ⌃1…⌃0（⌃1–⌃4 已经是叠加开关，§5.3）。
