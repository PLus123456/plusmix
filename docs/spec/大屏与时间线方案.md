# 大屏导播与时间线方案 v0.2

配套《导播台设计方案》《导播台后续方案》《导播台测试标准》。写于 2026-11-13 ～ 14，代码基线 `949d956`（main）。
状态：**v0.2。用户 2026-11-14 已定九条（§0A），还有两条等答复（§10）；整体架构在 §0B，检查点在 §9.1；没有改任何代码**。带界面示意的可点页面在 [大屏与时间线方案-示意页.html](大屏与时间线方案-示意页.html)。

来由是用户 2026-11-13 提的三件事和一个总要求：

1. 监看框要贴合画面比例（现在窗口一拉大，框跟着变大，画面上下一大片黑）；横屏、竖屏要能选，竖屏时界面排布要跟着变，不能挤得看不到几路输入。
2. 异形屏、多块屏（主屏 + 两侧耳屏，实际做过 1366×762 这种非标分辨率）：要能"先定一路 1080p / 4K 的输出，再在里面画出几块屏"，按屏放内容，监看里看得清每块屏上是什么；一路输入可以铺满整幅大屏，另一路只上两边的小屏。
3. 时间线：五六七块屏同时换内容，一块一块按太费劲；专门做大屏的老师习惯先把时间线编完，现场只管往下走。
4. 现在的软件只做了视频导播，没做大屏导播；希望两者合在一起，像剪辑软件那样有两套工作面板，互相耦合。

## 0. 结论先行

- **能做，而且不用推倒重来。** 现有引擎有四样东西正好是大屏播控要的：所有切换都落在拍点上的单一状态机、"从一张纹理里取一块画到另一处"的合成能力（多画面和缩略图现在就这么画）、从属节目时钟的文件输入、任意宽高的节目格式（16…8192，竖屏已经在合法范围里）。大屏和时间线是在这上面**加一层**，不改已有行为：节目里没有配大屏时，状态、画面、输出与现在逐字节相同。
- **三件事对应三层，可以分开交付：**
  - 第一层（只动界面，约 1 个会话）：监看框贴合画布比例；横屏时上边整幅给监看，调音台挪到下边、和输入区同高，输入区折行；竖屏时监看占满左边，输入和调音台叠在右边；节目格式页加横 / 竖屏预设。
  - 第二层（契约 + 渲染 + 引擎 + 输出 + 界面，约 5 个会话 + 1 个检查点）：**舞台**。三样东西分开：舞台（按现场位置摆的逻辑大画布）→ 屏幕（舞台上的矩形）→ 输出口（一路 1080p / 4K 信号里的矩形）。内容不是"拼进输出画面"，而是"放到某个分区"，监看看的是舞台，不是打包后的输出画面。
  - 第三层（约 4 个会话 + 1 个检查点）：**画面预设**（一组屏各放什么，存下来一键调用）和**时间线**（把预设排成提示点序列，现场按一下走一步，或定时自动走）。
- **两套工作面板共用一个节目**：工具条上"导播 ｜ 大屏"切换。输入、调音台、时钟、输出、命令总线是同一份；导播面板管直播 PGM，大屏面板管舞台。直播 PGM 可以直接当大屏的一个来源，一条时间线可以同时指挥两边，一次 TAKE 两边同一拍换。
- **操作范式不变**：大屏面板也是"预监 → TAKE"。导播面板里数字键选的是输入，大屏面板里选的是画面预设；Cut / Auto / FTB 含义相同。时间线只是替你把下一个预设装进预监，GO 就是 TAKE。
- **和现场常用的软件对得上**（§6）：分区 × 画面预设就是 HiRender S3"节目管理"那张表的窗口 × 节目；舞台和输出口分开摆就是它 5.x"显示管理"里的舞台区域和输出区域；预监后一次 TAKE 多屏同换是屏幕管理类切换台的做法。和 HiRender 最大的不同是它点节目就上屏，所以我们另给"直出"开关。
- **不算难，但量不小**。没有哪一块是引擎做不到的；工作量主要在两个编辑界面（屏幕排布、时间线）。真正要先验证的有三处（§9.3）：外接显示口能不能逐像素送出、多个输出口之间差不差帧、大舞台在入门机型上的渲染耗时。

### 0B.2 各部分做什么

|---|---|---|---|
| 输入 | SwitcherInputs | 每路输入自带线程，只往自己的帧槽写。新增"幻灯片列表"：一路输入里装一串图片或 PDF 页，可分段，能上一张 / 下一张 / 跳到第 n 张 | 旧 + 一种新输入 |

| 界面 | App | 主窗口新排布（§2）；"导播 ｜ 大屏"两个面板；屏幕编排窗；预设条与预设表；时间线面板 | 旧，大改 |
| 契约 | SwitcherContracts | 舞台、预设、时间线、幻灯片列表的类型与命令。全部带默认值，老节目文件照读 | 旧，加类型 |

### 0B.3 一拍里发生什么

1. **状态机**：先走时间线（有到点的提示点就把它的动作当命令应用）→ 推进转场、FTB、叠加动画、舞台转场的进度 → 应用这一拍收到的命令 → 发布新快照。
2. **引擎**：为每路输入挑"时间戳不晚于这一拍"的最新一帧。
3. **渲染**（同一个命令缓冲区）：直播 PGM → 直播 PVW → 多画面 → 舞台 PGM → 舞台 PVW → 各输出口。
4. **派发**：PGM 给编码、录制、NDI、虚拟摄像头；输出口画面给外部显示和 NDI。谁慢谁自己丢帧，不拖渲染。
5. **界面**：各监看按自己显示器的刷新率取最新画好的纹理。

所以直播和大屏永远在同一拍上：一次 TAKE 两边同时换，直播 PGM 上大屏不多一帧延迟。

### 0B.4 数据放在哪

节目文件（一个 JSON）里一共这几节：输入（含幻灯片列表的页和分段）、切换（直播 PGM 那一套）、音频、输出、**舞台**（屏幕、输出口、分区、画面预设）、**时间线**（分段、提示点）、界面布局。没有舞台和时间线两节的老文件照常打开。

### 0B.5 界面的骨架

- 主窗口从上到下：工具条（正中是"导播 ｜ 大屏"）→ 监看区 → 下边一行（输入区 ｜ 调音台）→ 底栏和状态行。
- 切面板只换监看区和它旁边的转场列，再加上大屏面板独有的预设条和时间线。下边一行和底栏两个面板共用。
- 独立窗口：屏幕编排（大屏独有）、多画面、输入设置、音频设置、输出设置、统计（已有）。

### 0B.6 不变的东西

- 节目里没配大屏，状态、画面、输出与现在逐字节相同。
- 铁律全部适用于新部分：渲染线程每帧零分配、统计只有一份、切换只在拍点生效、先写测试。
- 录制、推流、虚拟摄像头仍然只认直播 PGM。

## 1. 现状（都是在代码里查到的）

### 1.1 监看框为什么上下一大片黑

- 主窗口上半区是"PVW ｜ 转场列 ｜ PGM"，下面是输入条（`App/Sources/UI/MainWindowController.swift` 的 `buildLayout`）。窗口变大时输入条和调音台保持原尺寸，多出来的宽高**全部**给上半区（`splitView(_:shouldAdjustSizeOfSubview:)`）。
- 监视器 = 26 pt 标题条 + 一块铺满的显示视图（`MonitorView`）；显示视图把节目纹理**等比缩进去、四周清成黑**（`MetalDisplayView` 调 `Placement.fill`）。所以框的形状是窗口给的，不是画面的。
- 输入条只有一行、横向滚动（`InputStripView`），高度固定 197 pt。

按 `Theme` 里的常数算（工具条一行 52、底栏 58、输入条 197、转场列 150、调音台 340），与 docs/user/img/main-window-zh.jpg 的实拍一致：

| 窗口 | 监看画面区（每个） | 16:9 画面本身 | 画面占监看区 | 输入条露出 |
|---|---|---|---|---|
| 1100×720（最小），调音台开 | 302×386 | 302×170 | 44% | 3 路 |
| 1440×900，调音台开 | 472×566 | 472×266 | 47% | 5 路 |
| 1440×900，调音台收起 | 643×566 | 643×362 | 64% | 6 路 |
| 1728×1117（16 寸全屏），调音台开 | 616×783 | 616×347 | 44% | 6 路 |
| 2560×1440，调音台开 | 1032×1106 | 1032×581 | 53% | 10 路 |

结论：监看区一半左右是黑边，而输入条不管窗口多高都只有一行。竖屏画布时这块高的监看区正好用上（用户说的"竖屏很方便"），横屏时是浪费。

### 1.2 节目格式已经支持什么

- `ProgramFormat` 的宽高是任意整数，合法范围 16…8192（提案 034）。设置 › 节目格式里有"自定义"，范围 320–7680 × 240–4320、取偶数（`PreferencesModel`）。**1080×1920 竖屏、1366×762 这样的非标尺寸今天就能填**，引擎、渲染、编码都按它走。
- 缺的是：没有横 / 竖屏的预设和一键互换；界面排布不看画布比例；竖屏时缩略图被钳在 16:9 的框里（`InputCellView.thumbnailHeight`），画面只有框的三分之一宽。

所以"只有一块非标屏"的情况现在就有办法：节目格式填成那块屏的分辨率（比如 1366×762），外部显示输出 PGM。第一层做完后监看框也会贴合它。

### 1.3 现在怎么做三联屏，为什么难用

合成顺序是固定的：PGM 底（一路输入铺满）→ 转场 → 叠加 1–4 → FTB（`CompositorPasses.encodeProgram`）。要做"主屏 + 两耳"只能把节目格式设成输出信号的尺寸，再拿叠加通道当画中画，一路一路手调位置和缩放。问题有四个：

1. 叠加通道只有 4 路，三块屏各放一路就用掉 3 路，字幕没地方了。
2. 位置是"占节目画面的比例"，要自己把像素换算成比例。
3. 监看看到的是**打包后的输出画面**：屏幕按信号里的摆法挤在一起，和现场的样子不一样，小屏看不清。
4. 换内容要逐路改叠加；五六块屏同时换没有办法落在同一拍。

### 1.4 现成能用的零件

| 零件 | 在哪 | 大屏 / 时间线怎么用 |
|---|---|---|
| 单一状态机，命令只在拍点生效，`advance` + `reduce` 是纯函数 | `SwitcherEngine/State`、`Command.swift` 的 `MixerReducing` | 多块屏同一拍换是天然的；时间线走带放进 `advance`，逐拍确定、可无界面测试 |
| 把纹理的一块按裁切画到任意矩形 | `Placement.fill`、`MetalDisplayView.sourceRect` | 分区放内容、舞台 → 输出口的打包，都是这一个操作 |
| 自带帧号 / 输入号的合成测试源 + frameprobe | SwitcherTestKit | 机器判"各屏同一拍换""映射后像素没变" |
| 在指定拍发命令的场景脚本 | `Scenario` / `ScenarioRunner` | 时间线就是它的产品化：提示点 = 一组"相对拍 + 命令" |
| 文件输入从属节目时钟、可按拍定位 | `PlaybackSettings.seekTick`、`setPlayback` / `seekPlayback` | 多屏同步放片：同一拍起播的几个文件之后不会互相漂（起播要先预卷，§4.4） |
| 外部显示窗口把纹理画满整屏，尺寸相同时是 1:1 采样 | `SwitcherExternal`（输入直出那条路的着色器注释里写明 1:1 时逐值相同） | 输出口对上显示器分辨率就是点对点；PGM 那条路是否逐值要用探针确认（§9.3） |
| 多画面里的名字标签渲染 | `LabelRenderer` | 对位图：每块屏显示自己的名字、尺寸、边框 |
| 快捷键 / MIDI / HTTP API / Stream Deck 全走命令总线 | SwitcherControl | 新命令加进目录，所有控制入口同时可用 |

## 2. 第一层：主窗口新排布（监看贴合、调音台挪到下边、横竖屏）

2026-11-14 按用户两条反馈改过：横屏时调音台挪到下边、和输入区同高，上边整幅留给监看；竖屏排布重排。

### 2.1 规则

1. **监看框 = 画面。** `MonitorView` 的画面区加一条宽高比约束（= 节目格式的宽 : 高，换节目格式时更新）。框外是窗口底色，不再有黑边。
2. **横屏（画布宽 ≥ 高）：上边整幅给监看，下边一行是"输入区 ｜ 调音台"。**
   - 上边：PVW ｜ 转场列 ｜ PGM，横贯整个窗口宽度，不再被调音台占掉 340。
   - 下边一行：左边输入区，右边调音台，**两者同高**。调音台默认宽 340，中间的分隔条可拖；收起调音台后输入区占满整行。
3. **上半区的高度由画面算出来。** 监看宽 `w = (窗口宽 − 转场列 150 − 间隙 4) / 2`，贴合高 `h = w × 画布高 / 画布宽 + 标题条 26`。上半区高 = `max(h, 转场列最小高)`（转场列的最小高是 `transitionPanel.fittingSize`，W5-A 时量的是约 409 pt，下面的表按 409 算）。其余高度全给下边一行。
4. **输入区是会折行的格子。** 一行放不下就折到第二行、第三行，整块竖向滚动；格子的三档大小不变。
5. **竖屏（画布宽 < 高）：左边整列给监看，右边一栏是"输入区在上、调音台在下"。** 就是把横屏的排法转了 90°：监看占满一条边，输入和调音台共享另一条边（§2.3）。
6. **调音台的高度跟着位置走。** 条子现在的自然高约 380（推子 170）。行高够就和现在一样，更高时推子跟着变长；不够时推子缩短（最短 60），再不够就把声像、总线送出、跟随视频三行收进条子的齿轮，只留名字、表和推子、读数、静音与独听。
7. 分隔条仍然可以拖：横屏往上拖是让下边一行更高（监看等比变小、居中），往下最多拖到贴合高，不会再拖出黑边。收起 / 展开调音台、改节目格式、缩放窗口都按上面几条重算。
8. 留一个开关"窗口 › 排布 › 新排布（默认）/ 旧排布"，旧排布 = 今天的样子（调音台在右侧通高、监看区自由高度），给习惯了的人。

## 3. 第二层：舞台与屏幕

### 3.1 新增用词（并进设计方案 §1.1）

| 词 | 意思 |
|---|---|
| 舞台（Stage） | 一张逻辑大画布，按现场的相对位置摆着所有屏幕。单位是 LED 的像素点。监看和编排都看它 |
| 屏幕（Screen） | 舞台上的一块矩形，对应现场一块物理屏（主屏、左耳、右耳、侧屏、地屏）。有名字、像素尺寸、舞台上的位置 |
| 输出口（Raster） | 一路送出去的信号的整幅画面：1920×1080、3840×2160 或自定义。由一个已有的输出（外部显示 / NDI）送出 |
| 映射（Mapping） | 一块屏幕落在某个输出口的哪个矩形里（位置，可选旋转 90° 倍数、镜像） |
| 分区（Zone） | 放内容的目标：舞台上一个或几个矩形。每块屏自带一个分区；"整幅"= 所有屏的外接矩形；可以自建（"两耳"、主屏右下角的画中画） |
| 画面预设（Look） | 一组"分区 → 放什么"，存下来一键调用 |
| 时间线（Timeline）、提示点（Cue） | 见 §4 |

### 3.2 三样东西分开

```
来源（编号输入 / 直播 PGM）
        │  放到分区（适应 / 填满 / 拉伸 / 点对点）
        ▼
   舞台画面  ← 监看、编排看这个：屏幕按现场位置摆
        │  每块屏幕取舞台上自己那一块
        ▼
   输出口画面 ← 送给 LED 处理器的 1080p / 4K：屏幕按信号里的位置摆
        │
        ▼
   外部显示 / NDI（已有的输出）
```

分开的原因：现场的摆法和信号里的摆法通常不一样（一路 1080p 里要塞进主屏和两块耳屏，只能挤着放）。把两者混成一张图，就是 §1.3 第 3 条的毛病。分开以后监看永远是现场的样子，信号里怎么挤只在接线时看一次。

### 3.3 分区与内容

- 一个分区同一时刻放**一个来源**，带填充方式（适应留边 / 填满裁边 / 拉伸 / 点对点）、裁切、不透明度。来源可以是编号输入，也可以是**直播 PGM**（导播面板切什么，这个分区跟着是什么，同一拍，不多延迟）。
- 分区有上下顺序。空着的分区是透明的，露出下面的分区；最底下是黑。所以"背景视频铺整幅 + 主屏上放 PPT"就是：整幅分区放背景，主屏分区放 PPT。
- 分区由一个或几个矩形组成，两种铺法：
  - **跨屏**（一个矩形）：来源按这个矩形铺一幅，每块屏显示落在自己身上的那部分。"一路输入铺满整幅大屏"就是放到整幅分区。
  - **各放一份**（多个矩形）：每个矩形里各放一份同样的来源。"两耳放同一路机位"就是一个含两块耳屏的分区。
- 每个分区有自己的 PGM 内容和 PVW 内容，等于每个分区是一个小切换台。

### 3.4 预监与 TAKE

- 舞台有两幅：**舞台 PGM**（现在屏上是什么）和**舞台 PVW**（按下 TAKE 之后是什么）。
- 操作：选分区 → 点输入（或数字键），内容进这个分区的 PVW；或者调一个画面预设，一次填好几个分区的 PVW。按 **TAKE**（Cut = 硬切，Auto = 按舞台转场时长淡变），所有 PVW 与 PGM 不同的分区在**同一拍**换，换完 PVW 与 PGM 对调（和导播面板一样，方便切回去）。
- "直出"开关（放在转场列里，一眼看得到）：打开后选什么立刻上屏，不经预监，点一下画面预设就是整组屏立刻换。给排练用，也给习惯媒体服务器那种所见即所出的人。
- TAKE 之后预监里留什么可选：对调（默认，和导播面板一样）或保持（预监不动，适合连续往下走）。同一个来源在换前换后都在同一个分区里时不重播，片子接着放。
- 舞台黑场（等于舞台的 FTB）、对位图（每块屏显示名字、像素尺寸、边框、对角线，接线时用）各一个按钮。
- 第一版舞台转场只做 Cut 和 Fade。Fade 时每个变了的分区在旧内容上按进度叠新内容（清空的分区按进度淡掉）；没变的分区不参与，画面不动。

### 3.5 状态与命令（草案，正式的走契约提案 036 / 037）

```swift
struct StageState {                      // MixerState.stage；nil = 没有大屏，一切与现在相同
    var size: PixelSize                  // 舞台画布
    var screens: [StageScreen]           // id、名字、舞台矩形、映射（输出口 id + 矩形 + 旋转 / 镜像）
    var rasters: [StageRaster]           // 输出口：id、名字、宽高
    var zones: [StageZone]               // id、名字、矩形（1 个 = 跨屏，多个 = 各放一份）；数组顺序 = 下 → 上
    var program: [ZoneContent]           // 各分区现在放什么
    var preview: [ZoneContent]           // 各分区下一步放什么
    var transition: StageTransition      // cut / fade、时长（拍）、进度、起始拍
    var blackout: FadeToBlack            // 舞台黑场，复用现有 FTB 的结构
    var looks: [StageLook]               // 画面预设：名字 + [分区 id: 内容]，可以只管一部分分区
}
struct ZoneContent { var source: StageSource?; var fit: ContentFit; var crop: CropInsets; var opacity: Double }
enum StageSource { case input(number: Int), program }
```

- `OutputSource` 加 `.stage(raster: Int)`：哪个输出送哪个输出口，沿用现有的外部显示选屏、拔线口径（提案 013 / 015）、`Stats.display[]`。
- 新命令：`setStageLayout`（屏幕 / 输出口 / 分区的整体替换，等同于改设置）、`setZonePreview` / `setZoneProgram`、`stageTake(auto:)`、`setStageTransition`、`stageBlackout`、`storeLook` / `recallLook` / `removeLook`。全部和现有命令同一口径：纯函数、拍点生效、非法的原样返回。
- 编排数据（屏幕、分区、预设）很少变，运行状态（各分区内容、转场进度）才逐拍变；两者在同一个状态里，但渲染线程每拍只读后者和几个矩形。

### 3.6 渲染

每拍在现有三步（PGM、PVW、多画面）后面加：

1. **舞台 PGM**：清黑，按分区从下到上画。每个分区的每个矩形开一个裁剪框，把来源按填充方式画进去；转场中再按进度叠一层新内容。来源是直播 PGM 时直接采这一拍刚画好的 PGM 纹理。
2. **舞台 PVW**：同上，用 PVW 内容。只给操作员看，按不超过 1920 宽渲染；没人看时不画。
3. **各输出口**：清黑，把每块屏幕在舞台纹理上的那一块画到它在输出口里的矩形。尺寸一致时采样点正对像素中心，逐值相同。
4. 输出口纹理交给外部显示窗口；有 NDI / 录制要它时再转一次 NV12。

热路径规则不变：屏幕、分区的表在换快照时解析成定长数组（和 `MultiviewLayoutTable` 同一做法），渲染线程每拍零分配。`Placement.fill` 现在只有"适应"，要加填满 / 拉伸 / 点对点三种。

规模上限（用户已定，§0A Q5；大档的性能阈值量完再定）：屏幕 ≤ 16、分区 ≤ 24、输出口 ≤ 4、舞台每边 ≤ 8192。

### 3.7 输出

- 第一版走已有的两种输出：**外部显示**（HDMI / DP 进 LED 处理器或发送卡，最常见）和 **NDI**。每个输出口对应一个输出，来源选"舞台 · 输出口 n"。
- 点对点的条件写在界面上：显示器当前分辨率 = 输出口宽高、缩放 1 倍。对不上时输出设置页和底栏标黄，写明"这块屏现在是 A×B，输出口是 C×D，画面会被缩放"。
- 多个外部显示各按自己的刷新呈现，同一拍的画面在不同口上可能差一个刷新周期。要逐帧锁定得走 SDI 输出卡，放后面（§9.4）。
- 录制、推流默认仍然是直播 PGM。给录制 / 推流加"来源 = 某个输出口"之后，后续方案 §3.5 的多画布（横竖屏同出）就不用单独做了：一个 1080×1920 的输出口，里面一块屏，分区放"直播 PGM、填满裁边"，就是竖屏那一路。

### 3.8 大屏面板的界面

```

├─────────────────────────────┴────────┴─────────────────────────────────┤
│ 画面预设  [1 整幅] [2 主屏 PPT + 两耳机位] [3 背景 + PGM] [＋]           │
├───────────────────────────────────────────────────────┬────────────────┤
```

- 排布跟主窗口的新规则走（§2）：监看区横贯窗口，下边一行是"输入 ｜ 调音台"，和导播面板是同一行。大屏面板只是在中间多了预设条、在底栏上面多了时间线。
- 舞台监看 = 舞台纹理 + 界面层画的屏幕外框、名字、选中状态。屏幕之间的空隙是窗口底色，一眼看出屏的形状。舞台宽高比大于 2.2 时两个监看上下叠放（PVW 在上），否则并排。
- **屏幕编排**（"大屏 › 屏幕编排…"独立窗口，两个页签）：
  - "舞台"：把屏幕拖到现场的相对位置，吸附对齐，X / Y / 宽 / 高可以直接填像素。
  - "输出口"：选一路输出（或先建一个 1920×1080 / 3840×2160 / 自定义的输出口），把屏幕的矩形拖到信号里的位置；"自动排布"一键挤好；越界、重叠标红。
  - 模板：单屏、主屏 + 两耳、三联等宽、主屏 + 两耳 + 地屏。新建时舞台摆法默认等于输出口摆法，要改再改。
- **预设表**（预设条的另一种视图）：行 = 分区，列 = 画面预设，格子里是来源。把输入拖进格子就是改这个预设；点列头 = 调这个预设。五六块屏时一眼看全每个预设里每块屏放什么，用过 HiRender 节目管理的人不用学。
- **分区矩阵**（可选视图）：行 = 分区，列 = 输入，点交叉点 = 这路输入进这个分区的预监。临时改一两块屏时比逐个点快。
- 输入条第一格固定是"PGM 节目画面"，在大屏面板里也一直看得到直播在播什么。

### 3.9 拿 1366×762 的例子走一遍

现场：主屏 1366×762，两侧各一块 512×288 的耳屏；LED 处理器吃一路 1920×1080。

1. 屏幕编排 › 输出口：建输出口 1920×1080；画主屏 (0, 0, 1366×762)、左耳 (1408, 0, 512×288)、右耳 (1408, 288, 512×288)。处理器那边按同样的坐标截取。
2. 屏幕编排 › 舞台：左耳拖到主屏左边、右耳拖到右边，和现场一样。分区自动有四个：主屏、左耳、右耳、整幅；再建一个"两耳"（各放一份）。
3. 存三个画面预设：
   - 预设 1"整幅"：整幅 ← 背景视频（填满）。
   - 预设 2"主屏 PPT"：主屏 ← PPT 输入（适应），两耳 ← 机位 1（填满）。
   - 预设 3"主屏直播画面"：主屏 ← 直播 PGM，两耳 ← 台标图片。
4. 演出中：按 2 → 预监里主屏是 PPT、两耳是机位 → 空格，三块屏同一拍换。监看里三块屏按现场位置摆着，各自多大就多大，不再是挤在一张 1080p 里的小块。

## 4. 第三层：时间线

### 4.1 形态：提示点序列，画在时间轴上

时间线 = 一串**提示点**。每个提示点 = "到这一步，舞台变成什么样（调哪个画面预设 / 改哪几个分区）+ 用什么转场 + 顺带发哪些命令 + 什么时候走"。

- 触发方式三种：**手动**（等操作员按 GO）、**跟随**（上一条走完 n 秒后自动走；或上一条里的片子放完时走）、**定时**（距时间线起点 hh:mm:ss.ff）。后续加时间码（LTC / MTC）。
- 提示点可以**分段**（用户 2026-11-14：一场 20–30 张 PPT 要分成几段）：段有名字和颜色，时间轴上是一条色带，列表里是一行段标题；可以直接跳到某一段的开头，段可以折叠。
- 界面上画成横向时间轴：行 = 分区（每个分区在每个提示点之后放什么，一段一段的色块，带来源名），外加一行"导播"（切机位、上字幕这类动作的标记）和一行"命令"；列 = 提示点；手动提示点是一道停止线。看起来和剪辑软件的时间线一样，但编辑单位是提示点，不是任意摆放的素材块和关键帧。
- 同一份数据还有列表视图（一行一个提示点：编号、名字、触发、转场、备注），排练时改起来快。
- 这张"列 = 演出的一个时刻、行 = 每块屏放什么"的表，和 HiRender 的节目管理、Millumin 的 dashboard 是同一种东西，只是每列多了触发方式。

为什么不先做自由时间线（轨道上任意摆素材块、打关键帧，HiRender 的"时间轴线模式"、WATCHOUT 那种）：现场有实时信号（机位、PPT）时，"这段放多长"是不知道的，能预编的是**顺序和画面**，时刻要么等人按、要么跟着片子走。提示点序列两种都能表达，定时和跟随触发也能做出"片头放到 35 秒时两耳换画面"这种编排。它做不了的是位置、缩放、透明度随时间变的关键帧动画和素材块任意交叠。那一半以后作为"时间线片段"嵌进提示点（HiRender 的时间线层节点、Millumin 把 timeline 拖进 dashboard 都是这么嵌的），编辑器的工作量大约再多一倍（§0A Q4）。

### 4.2 和预监 / TAKE 的关系

时间线不另起一套出画机制，它只做两件事：**把下一个提示点的画面装进舞台 PVW，到点替你按 TAKE**。

- 走到提示点 n：PGM 是提示点 n 的画面，**PVW 自动是提示点 n + 1 的画面**。操作员看预监就知道下一步是什么。
- 按 GO = 这一拍 TAKE（用提示点 n + 1 自己的转场），然后装下一条。
- 临时要改：直接在预监里换某个分区的内容再 GO，或者不走时间线手动 TAKE；时间线停在原地，按"回到时间线"再接上。**时间线不锁住手动操作**，这是和纯播控软件最大的区别，也是导播台该有的样子。

### 4.3 数据与走带（草案，正式的走契约提案 038）

```swift
struct Timeline { var id: Int; var name: String; var sections: [CueSection]; var cues: [Cue] }
struct CueSection { var name: String; var color: InputColor?; var firstCue: Int }   // 分段：从哪个提示点起
struct Cue {
    var id: Int; var name: String; var color: InputColor?
    var trigger: CueTrigger                 // manual / afterPrevious(ticks) / onMediaEnd(input) / atTime(ticks)
    var look: Int?                          // 调哪个画面预设（可空）
    var zoneChanges: [Int: ZoneContent]     // 在预设之上再改哪几个分区
    var transition: StageTransitionChoice   // cut / fade + 时长
    var actions: [CueAction]                // 相对本提示点起点的拍偏移 + 任意 Command
}
struct SequencerState {                     // MixerState.sequencer，运行状态
    var timeline: Int?; var cueIndex: Int; var running: Bool; var cueStartTick: Tick?; var detached: Bool
}
```

- `actions` 里放的就是现有的 `Command`：切机位、开叠加、文件输入从头播、开始录制都行。**一条时间线因此可以同时指挥导播和大屏。**
- **走带放在状态机的 `advance` 里**：每拍先看有没有到点的提示点和动作，到了就在这一拍应用。好处是时刻逐拍确定、不依赖界面线程、无界面模式能跑能测、和现有场景脚本同一个机制。
- 新命令：`timelineGo`、`timelineBack`、`timelineGoto(cue:)`、`timelineGotoSection(section:)`、`timelinePause(on:)`、`timelineSelect(timeline:)`、`setTimeline`（整体替换一条时间线的内容）。GO 可以绑快捷键、MIDI、Stream Deck、API。
- 运行状态进快照，界面、API、远程面板读同一份。

### 4.4 素材：幻灯片列表和放片

用户 2026-11-14 说明：大屏导播的素材主要是 PPT，一场 20–30 张，要分成几段。一张图占一路输入的话，16 路不够用，所以加一种输入。

**幻灯片列表输入**（契约提案 040，后续方案 §2.5 播放列表的落地）：

- 一路输入里装一串页。来源三种：一组图片（拖一个文件夹或多选）、一份 PDF（PPT / Keynote 导出，一页一张）、视频文件（后做）。只占一个输入编号。
- 页可以**分段**：段有名字，列表里显示段标题。
- 动作：下一张、上一张、跳到第 n 张、跳到某段开头。当前是第几张进状态快照，界面、API、时间线读同一份。
- 下一张提前准备好（图片预先载成纹理），翻页不黑不卡。
- 它就是一路普通输入：能上直播 PGM、能当叠加、能放进舞台的任何分区。导播面板里做讲座直播同样用得上。
- 格子上多两颗按钮（上一张 / 下一张）和"第 7 / 24 张"的读数；输入设置里看整串页的缩略图、拖动排序、分段。

**和时间线的关系：**

- 提示点的动作里可以写"某路幻灯片翻到第 k 张"。
- **按幻灯片生成提示点**：选一路幻灯片列表，一张一个提示点、段落照搬。20–30 张 PPT 的演出，时间线基本是自动出来的，再逐条补"这一张时两耳放什么"。
- 翻页笔的上一张 / 下一张就是时间线的上一条 / GO（§5.3）。

**PPT 的另一种接法不受影响**：讲者自己的电脑经采集卡、NDI 或屏幕捕获进来，是一路普通的实时输入，谁翻页都行。

**放片**：片子仍是文件输入。几块屏要帧同步放片时分两步：上一个提示点里先把这几路定位到开头并暂停（预卷，等解码就位），到点在同一拍放开；它们都从属节目时钟，之后不会互相漂。同步到不到同一帧要用烧了帧号的测试片验证（V17 的放片版）。片子很多的演出以后把视频也收进列表输入（两个列表交替用就能做片子之间的淡变）。片子的声音走调音台，和别的输入一样。

### 4.5 录下操作

"录制操作"开关：排练时手动走一遍（调预设、TAKE、切机位），软件把每一步连同时刻记成提示点；之后按 GO 重放，或把触发改成手动 / 定时。这是把时间线编出来最快的办法（后续方案 §5.4 宏的"按一遍记下来"）。

## 5. 两套工作面板怎么合在一起

### 5.1 一个节目，两个面板

工具条正中加"导播 ｜ 大屏"分段开关（⌘1 / ⌘2）。切面板只换主窗口中上部分，其余不动。

| | 导播面板 | 大屏面板 |
|---|---|---|
| 管什么 | 直播 PGM（给推流、录制、虚拟摄像头） | 舞台（给 LED 屏） |
| 监看 | PVW / PGM | 舞台 PVW / 舞台 PGM |
| 数字键选的是 | 输入 | 画面预设 |
| Cut / Auto / FTB | 直播 PGM | 舞台 |
| 独有 | 转场槽、叠加 1–4、T-bar | 屏幕编排、分区矩阵、画面预设、时间线 |
| **共用** | 输入（同一批编号）、调音台、底栏的输出、状态行、设置、快捷键表、API、节目文件 | 同左 |

节目里没配大屏时，"大屏"面板是一个引导页（"先定一路输出 → 画屏幕"），导播面板和现在完全一样。只做大屏不做直播的人可以一直待在大屏面板。

### 5.2 六个耦合点

1. **输入只有一份。** 在哪个面板加、改名、调设置，另一个面板同时生效。
2. **直播 PGM 是大屏的一个来源。** 主屏放"节目画面"，导播面板切机位，主屏跟着换，同一拍。这是会议、演出最常见的用法。
3. **同一个时钟。** 两边的切换都落在拍点上。"联动"开关打开后，一次空格两边同一拍换。
4. **一条时间线指挥两边。** 提示点里既能换舞台画面，也能发任何导播命令。时间线面板在两个面板里都能打开。
5. **互相看得见。** 大屏面板输入条第一格是直播 PGM；导播面板底栏有一个舞台小窗（点它切到大屏面板）；多画面可以放"舞台 PGM"格。
6. **Tally。** 输入上了直播 PGM 是红灯（不变）。输入上了舞台 PGM，格子上多一个"屏"字徽标，写它在哪几个分区。红灯的含义不改（§10 Q9）。

### 5.3 快捷键

现场最怕"以为在这个面板、其实在那个"。默认做法：**键位不随面板变**——数字键和空格永远是导播的；舞台的预设是 ⌃1…⌃0，舞台 TAKE 是 ⌃空格，时间线 GO 是 → 和 PgDn、上一条是 ← 和 PgUp（翻页笔发的就是 PgUp / PgDn，拿它走时间线是现场的习惯做法）（都可改；具体键位开工时要对着现有键表和系统自带的快捷键再核一遍，⌃数字在开了多桌面切换的机器上会被系统占用）。给只做大屏的人留一个开关"数字键与空格跟随当前面板"，打开后在大屏面板里数字键调预设、空格 = GO（§0A Q8）。

## 6. 对照：别的软件怎么做，我们取哪部分

资料来自官方手册和官方在线文档，由一个调研代理通读后摘要；我自己抽查了 HiRender S3 2018 版手册的快速使用指南几页（节目管理表、添加屏幕、窗口属性、翻页笔），与摘要一致。链接在 §6.6。只借思路和交互范式，不借名字、图标、文案（设计方案 §0）。

### 6.1 用词对照

| 本方案 | HiRender S3 | 屏幕管理类切换台（Barco Event Master、Analog Way LivePremier） | WATCHOUT 7 | Millumin | Resolume Arena |
|---|---|---|---|---|---|
| 舞台 | 舞台 | 一块 Screen 的像素画布 | Stage | Canvas | Composition |
| 屏幕 | 4.x：屏幕与切片里"取哪块"那一半；5.x：表面 | Screen（Barco 叫 Screen Destination）里一个输出口占的区域 | Display 在舞台上的矩形 | output 在 canvas 上的位置 | Slice（Input Selection 阶段） |
| 输出口与映射 | 4.x：屏幕（一个显卡口）与切片里"摆哪里"那一半；5.x：屏幕（真实输出口），表面在输出区域里的位置 | Output；在 Canvas 里摆口；AOI | Display 的节点、通道、分辨率 | output（显示器、输出卡、NDI） | Screen 与 Output Transformation 阶段 |
| 分区 | 窗口（舞台坐标里的位置和大小） | Layer（属于某一块屏） | cue 在舞台上的位置 | layer | layer，或 slice 的输入 |
| 画面预设 | 节目（节目管理表的一列：每个窗口放什么） | Preset（Barco）；Screen Memory 与 Master Memory（Analog Way） | 没有对应，靠时间线 | dashboard 的一列 | 没查 |
| 时间线、提示点 | 节目的先后顺序，加时间线上的控制命令（播放、暂停、停止、跳转） | Cue（Barco：若干动作的序列，可带等待） | Timeline，加 Control cue 与 Marker | 列的先后顺序；timeline 的分段 | 没查 |
| 预监后 TAKE | "预监"只在软件自己的舞台窗口里看，没有 TAKE；连线并实时更新时所见即所出 | 每块屏一对 Program / Preview；预设先进 Preview，一次全局 Take 一起换 | 编辑用的 Blind Edit | 编辑用的 Silent Edition | — |
| 舞台黑场 | 待命 | — | — | — | — |
| 对位图 | 识别显示 | — | — | — | — |

### 6.2 大家共有的做法，本方案照做

1. **三层空间。** 内容所在的统一像素空间 → 逻辑屏 → 输出口上的一块区域。HiRender 5.x 的"显示管理"窗口左边是舞台区域、右边是输出区域，同一块表面在两边各有一份位置；取消同步之后在舞台区域按现场摆。这和 §3.2 是同一件事。
2. **输出映射拆成"取哪块"和"摆哪里"两步。** Resolume 把它做成两个阶段，后一个阶段的官方用途之一就是给 LED 处理器重排像素。
3. **素材不直接绑输出口。** 素材放进窗口或图层，屏幕框住舞台的哪一块就出哪一块；跨屏就是把窗口拉到盖住那几块屏。
4. **预编排 = 一键召回的状态 + 线性段落。** 状态是节目列、dashboard 的列、Preset、Memory；段落是时间线，用暂停点切开。走带都是"下一个"键（空格、方向键、PgDn、翻页笔）加具名跳转。
5. **实时信号是一等素材**，能和文件混排，而且不受走带暂停影响（HiRender 叫独立播放，WATCHOUT 叫 Free Running，Millumin 叫 independent layer）。
6. **外控归一成变量和触发器**，再接 MIDI、DMX、TCP / UDP 文本指令、时间码。

### 6.3 分歧，和我们取哪一边

- **所见即所出，还是预监后 TAKE。** 媒体服务器（HiRender、WATCHOUT、Millumin、Resolume）一触发就上屏，预监只是软件里的旁路视图。屏幕管理类切换台每块屏一对 PVW / PGM，预设先进 PVW，一次 TAKE 多屏同换。**我们取切换台这一边**：软件本来就是 PGM / PVW 范式，多屏同拍换是它的直接结果。代价是用惯 HiRender 的人会觉得多按一下，所以"直出"开关放在显眼处（§3.4）。
- **时间线，还是预设表。** WATCHOUT 是纯时间线；切换台是纯预设，Barco 另有 Cue 序列；HiRender 和 Millumin 是混合型，一张"列 = 演出的一个时刻"的表，表里可以嵌时间线。**我们先做表这一半**（§4.1），自由时间线以后嵌进来。
- **图层属于谁。** 切换台的图层属于某一块屏；媒体服务器的窗口铺在整个舞台上。**我们的分区铺在舞台上**，所以能跨屏；但每个分区各有 PGM / PVW，所以能预监。两边各取一半。
- **多屏同换靠什么。** 切换台靠 Master Memory 或 Preset 加全局 Take；HiRender 靠"一个节目就是一整列窗口一起换"。我们两样都有：画面预设是那一列，TAKE 是那一下。

### 6.4 从 HiRender 借的具体做法

- 预设表：行 = 分区，列 = 画面预设（§3.8）。
- 同一来源跨相邻两个预设不重播（它叫跨节点）（§3.4）。
- 片子放完之后的动作：循环、定格、停、走下一条（§4.1 的跟随触发）。
- 翻页笔走带：PgUp / PgDn 和方向键（§5.3）。
- 识别显示、待命、一键开关全部输出（§3.4 的对位图与舞台黑场；全部开关底栏已有）。
- 采集类信号不跟着时间线暂停。我们的输入本来就是这样。
- 以后再借（§9.4）：给中控的 TCP / UDP 文本指令、LTC / MTC 时间码（触发与同步两种用法）、节目插播（优先级最高的一层，临时盖上去）、多边形表面与箱体网格、输出控制（到点给别的设备发指令）。

### 6.5 没查到的

HiRender 5.2 课程目录里"节目的单播与多播"的含义、OSC 的地址表；Barco 输出口在目的地里的摆法和 Cue 各参数的确切含义；Analog Way 是否自带提示点列表；Resolume 的走带方式。这些不影响本方案的取舍。

### 9.2 工作量的实话

- 第一层：小。一个 App 会话。
- 第二层：中到大。渲染和状态各一个会话是清楚的活；界面里屏幕编排窗是最费工的一块（拖拽、吸附、两个页签、模板）。
- 第三层：走带本身不大（放进 `advance`，几百行 + 用例）；时间线面板是整个方案里最大的一块界面。
- 加起来和第五波界面改版是一个量级（十四五个会话、五个检查点）。界面会话拆成"先外观、后接线"两步之后会话数多了几个，但每一步都小，而且外观改起来不牵动引擎。

### 9.3 要先写探针验证的三处（铁律 10）

1. **外接显示口逐像素输出**：非 HiDPI 模式下 drawable 是否等于显示模式的像素；CAMetalLayer 的色彩管理会不会改值（LED 处理器要的是原值）；窗口盖满全屏时有没有被系统合成器缩放。做法：把 1 像素棋盘格和灰阶条送到外接口，用采集卡回采逐值比。需要一块采集卡或一台 LED 处理器（BLOCKED-硬件，用户手里有）。
2. **多个输出口的相位**：两路外部显示同时送闪光帧，回采看差几帧、稳不稳定。
3. **大舞台的带宽**：8192×2160 的舞台 + 两路 4K 输出口，在 M1 Air（下限机）和 M5 Max 上各量一次渲染耗时，定 V19 大档的阈值。

### 9.4 明确先不做的

SDI 输出卡与逐帧锁定、多机联动与主备、边缘融合与几何校正（投影用）、多边形或旋转任意角度的屏幕、LED 逐点校色、自由时间线上的素材块与关键帧动画、时间码（LTC / MTC）、给中控的 TCP / UDP 文本指令、DMX / Art-Net、3D 舞台预览。这些是专业媒体服务器的地盘，本方案的定位是"会议和中小型演出里，一台 Mac 同时管直播和几块屏"。其中时间码、文本指令、自由时间线片段三样离得最近，第三层做完后按需要排。

## 10. 还等你答复的两条

其余九条已定，见 §0A。这两条用户说没看懂，换个说法再讲一遍。两条都不影响架构，没答复之前按建议值写。

### Q3 在大屏面板点了一个画面预设，现场的屏是立刻变，还是先看一眼再变？

- **立刻变**（就是"所见即所得"，HiRender 是这样）：点预设 2，三块屏马上换成预设 2。少按一下；点错了观众也马上看到。
- **先看一眼再变**（预监后 TAKE，导播面板现在就是这样）：点预设 2，只有软件里左边"舞台预监"变成预设 2 的样子，现场的屏不动；看着没错，按一下空格，三块屏同时换。多按一下；点错了有机会改。
- 两种都会做，转场列里有一个"直出"开关随时切。要定的只是**默认开哪一种**。
- 走时间线时两种没有区别：预监里本来就是下一步，按 GO 就上屏。
- 建议：默认"先看一眼再变"。

### Q9 一路输入只上了大屏、没上直播，它的格子要不要亮红灯？

- 现在的红灯：哪一路正在直播 PGM 上，它的格子标题条是红的，意思是"这一路观众正在看，别动它"。
- 加了大屏以后会有新情况：比如 PPT 只放在主屏上，直播里播的是机位。这时 PPT 那一格亮不亮红？
  - **亮红**：简单，但红灯就分不出是"在直播里"还是"在大屏上"。
  - **不亮红，格子上另加一个小标签"屏 · 主屏"**：红灯仍然只表示在直播里，标签写明它正在哪块屏上。
- 一场活动只做大屏、不做直播的话，两种差别不大。
- 建议：不亮红，加标签。
