# 导播台测试标准 v0.1

配套《导播台设计方案》。目的：把"不掉帧、不失步、不崩"变成可以量、可以自动跑、可以对比版本的东西。

口径修订（2026-09-19，G3 检查点按用户授权落地各会话报告里等拍板的口径问题；**阈值一个没动**）：§2.1 到达相位、底纹、到达余量参数；§2.3 整秒拍、音轨时间轴、不连续检测；§3 V3 / V4 / A1 / A2 / S3 的口径；§4 A2 的判法；§7 stats.jsonl 字段。依据见 reports/G3-notes.md §11.3。
口径修订（2026-09-20，G4 检查点；**阈值一个没动**）：§3 V4 / V6——frameprobe 在播段口径只统计有单一输入身份的帧，Fade / Wipe / Zoom / Stinger 的中间拍不计入（引擎侧 stats.jsonl 全程照算，两个口径都要满足），+1 帧相位余量按每个连续在播段各算一次；"Cut"= 新 ID 紧接旧 ID 出现的切换。依据见 reports/G4-notes.md §3 与 reports/issues/G4-w1-testkit-frameprobe-wipe-zoom-progress.md。用户 2026-09-22 确认；同日定两条基线口径（不是阈值）：V1 的"2 ms 本机参考线"是 G2 按 M0 灰底负载给 M5 Max 定的，自 G4 起只作参考（必须档 / 目标档阈值不变，检查点报告里单列为参考行）；§6 L5 性能回归的基线自 G4 起为 baselines/g4-m5max.json（g3 基线因噪声底纹与新负载不可比，W4-A 从 g4 起算）。

## 0. 原则

1. 直播软件的质量只有三件事：不掉帧、不失步、不崩。所有指标都围绕这三件事。
2. 每个指标四要素齐全：定义、测法、阈值、报告口径。缺一个就不算指标。
3. 能自动测的绝不手测。为此引擎必须有无界面模式和内置合成测试源。
4. 性能有基线。每个版本和上一个版本比，退步就阻塞。
5. 阈值分两档：必须（发布门槛）和目标（努力方向）。
6. 符号约定：A/V 偏移以音频为准，音频超前为正、滞后为负，和 ITU-R BT.1359 一致。

## 1. 指标定义

编号规则：V 视频、A 音频、E 编码/录制/推流、L 延迟、S 稳定性与资源、C 控制接口。第二版及以后功能的新增指标（V10 起、A8 起、E10 起等）见《导播台后续方案》第 9 节，各功能开工时合并进本节。

### V 系列：视频

| 编号 | 名称 | 定义 | 单位 |
|---|---|---|---|
| V1 | 渲染耗时 | 一拍开始到该拍命令缓冲区在 GPU 上完成的时间；报平均值和 p99 | ms |
| V2 | 渲染滞后丢帧 | 下一拍到期时上一帧尚未提交而被跳过的拍数；报计数和占总拍数的比例 | 帧、% |
| V3 | 输出帧间隔抖动 | PGM 帧派发时刻与理想拍点之差；报 p99 和最大值 | ms |
| V4 | 输入帧重复/丢弃率 | 每路输入：同一输入帧被合成两次以上的比例；输入帧到达但从未被合成的比例。区分"设计内"（30 fps 进 60 fps 节目必然重复）和"设计外" | % |
| V5 | 帧计数一致性 | 长跑后输出总帧数与"时长 × 帧率"的差 | 帧 |
| V6 | 切换准确性 | 切换命令指定在第 n 拍生效，输出里新输入出现的第一帧是否恰好是第 n 拍；Cut 时不得出现任何混合帧 | 帧 |
| V7 | 转场进度精度 | Fade 时实际混合比例对时间的曲线与设定曲线之差；T-bar 位置到混合比例的映射误差 | 帧、% |
| V8 | 画面正确性 | 给定状态和输入图，离线渲染结果与参考图的差异（叠加顺序、位置、抠像、缩放） | PSNR dB / SSIM |
| V9 | 色彩正确性 | 灰阶和色条经"输入 → 合成 → NV12 → 编码（无损或 ProRes）"往返后的电平误差；BT.709 限制范围（16–235）不得被拉伸或压缩 | 8-bit 电平 |

### A 系列：音频

| 编号 | 名称 | 定义 | 单位 |
|---|---|---|---|
| A1 | 音频断裂 | 输出回调超时次数 + 缓冲欠载次数 + 输出中检出的不连续（波形跳变） | 次 |
| A2 | A/V 偏移 | 输出中同一事件（闪光帧 vs click）音频相对视频的时间差；音频超前为正。报均值、标准差、最大绝对值 | ms |
| A3 | A/V 漂移 | 长跑期间 A2 的变化量（线性拟合斜率 × 时长） | ms |
| A4 | 多文件对齐 | ISO 分路录制时，各文件中同一事件的时间差 | ms |
| A5 | 监听延迟 | 麦克风入口到耳机出口 | ms |
| A6 | 表的准确度 | 用 EBU Tech 3341 / 3342 测试信号，响度、真峰值读数与标称值之差 | LU、dB |
| A7 | 实时线程违规 | 音频回调内发生锁等待、内存分配、系统调用的次数 | 次 |

### E 系列：编码、录制、推流

| 编号 | 名称 | 定义 | 单位 |
|---|---|---|---|
| E1 | 编码滞后跳帧 | 输出队列因编码器跟不上而丢弃的帧数 | 帧、% |
| E2 | 码率遵从 | 10 秒滑动窗口平均码率与设定值之差；1 秒窗口峰值与设定值之比 | %、倍 |
| E3 | 关键帧间隔 | 实际关键帧间隔与设定值之差 | 帧 |
| E4 | 编码画质 | 固定测试片源经"文件输入 → 编码 → 录制"后，用 VMAF / PSNR 与源比；报绝对值和相对上一版本的变化 | 分、dB |

| L3 | 推流出口延迟 | 编码器输出到数据包离开网络接口 | ms |

### S 系列：稳定性与资源

| 编号 | 名称 | 定义 | 单位 |
|---|---|---|---|
| S1 | 长稳 | 标准负载连续运行 8 小时 / 24 小时，全程每个 5 分钟窗口内 V2、A1、E1 都不超阈值，无崩溃 | 通过 / 失败 |

|---|---|---|---|

## 2. 测试信号与工装

没有这些，上面的指标大部分测不了。它们是产品的一部分，不是测试脚本的附属。

### 2.1 合成视频源（引擎内置输入）

每帧烧入：
- 帧号：16 个 32×32 的黑白方块（二进制，带 4 位校验），压缩后仍能可靠读出。
- 输入 ID：一个固定颜色块，每路输入不同颜色。
- 输入 ID 的解码阈值与它的边界：契约 `TestPattern.paletteIndex` 按"离最近调色板色 ≤ 24"判（16 色两两距离的下限是 56.6，取一半）；
  frameprobe 的自证解码再收紧到 12（`--id-tolerance`）。收紧的理由写在这里，因为它是判据而不是实现细节：
  调色板里 **0 + 2 = 8、1 + 2 = 15、7 + 9 = 15、2 + 3 = 7、0 + 9 = 11 这五对颜色的 50% 混合与第三种颜色的距离 < 0.4**
  （调色板由 0 / 128 / 255 三档分量拼出来，中点必然撞上另一个格点）。也就是说转场混合帧只看 ID 块的颜色，
  **无论阈值多紧都躲不开被解成第三路**——C3 的"不许解成第三路"必须靠另外两票独立判据：**底色**（中心采样区与 ID 邻域带的灰度
  都要等于该路的标称灰度，见下条）和**码字块电平纯度**（帧号行 / 时间戳行那 64 个块必须是纯黑 16 或纯白 235，混过一次就落在中间）。
  阈值 12 把"能被读成第三色"的混合比例从 [0.29, 0.71] 收到 [0.39, 0.61]，两侧都落进那两票的判掉区间（用户 2026-09-23 批）。
- 解码区与它的保护带：帧号行、时间戳行、ID 块、闪光块、中心采样区（宽高各 1/4），外加 **ID 块下方的背景带**——
  从 ID 块下缘往下半个块高起、高一个块高、宽四个 ID 块（1080p 上 x ∈ [16, 272]、y ∈ [192, 224]，即 0.178–0.207 倍高）。
  这条带是 frameprobe 拿来与中心采样区比对、认出转场合成帧的第二个采样点，所以**节目文件里的叠加、Stinger 图案、
  边框等一律不许占用这几块**：图案区以下、**0.22 倍高以上**这条横带归解码用。
  （G4 的 Stinger PNG 左右立柱正好从 0.22 倍高起、余量 14 px——现在这是规矩，不再是巧合；用户 2026-09-23 批）
- 时间戳：生成时的 host time，同样二进制块。
- 闪光帧：每秒第 0 帧右上角一个 64×64 全白块，其余帧全黑。用于 A/V 偏移。
- 可配置：帧率（30 / 59.94 / 60）、人为抖动、人为丢帧、人为时钟漂移（±100 ppm）。
- 到达相位：合成源的帧比其 pts 提前半个节目帧到达引擎（headless `--input-lead-ms` 默认 = 半帧），音频块不提前。这是各检查点 V4 可比的前提（G2 报告 §7 第 5 条）。
- 底纹：灰底（V6 / V7 用 64 / 192）或噪声底纹 `noise(level, amplitude, seed)`（契约提案 006）。E2 要噪声底纹才有可判对象：G4 起的 L2 场景用噪声（振幅 24），M0 基线保留灰底。
- 引擎到达余量（设计方案 §3.2 挑帧规则的实现参数；检查点一律用默认值，改过的路要在报告里写明）：估计器窗口 8 块 × 1 s，每块记最小值与最大的 8 个样本，热身 1 块，起流块在两个完整块后作废；
  初值 = max(下限, 第一帧到达延迟 d₀ + 保护带)；保护带 = 1 ms + 15% × 可覆盖抖动跨度；单次上调 ≤ 一个节目帧；上限 = 窗口最小到达延迟 + 一个节目帧 + 保护带（随时生效）；绝对上限 500 ms；上限锚点 = 窗口最小值（W1-B2 报告 §1、§4 第 1 条）。

### 2.2 合成音频源

- 1 kHz 正弦 -20 dBFS，每秒和闪光帧同一时刻叠加一个 1 ms 的 click。
- 可配置采样率漂移（±100 ppm），模拟不同设备时钟。

### 2.3 frameprobe（分析工具）

命令行工具，读输出文件或抓下来的流，逐帧解出帧号、输入 ID、闪光；解音轨找 click。输出 JSON：
- 丢帧、重复帧的序列和统计（V4、V5）。
- 每次切换在第几帧生效、有无混合帧（V6）。
- Fade 期间逐帧的混合比例（V7；输入 A 用灰度 64、输入 B 用灰度 192，混合比例可以直接算出来）。
- 每个闪光帧对应的 click 时间差序列（A2、A3、A4）。
- 整秒拍：闪光帧的节目拍号是标称整数帧率的倍数（60 fps 节目 = 整秒；59.94 = 每 1.001 s）才算"整秒配对"；A2 / A3 只用整秒配对判定，其余配对只报不判（59.94 的路在播时闪光周期 1.001 s 是已知假象）；不从第 0 拍起的文件要给 `--start-tick`。
- 音轨时间轴：录制文件按编辑列表（AVFoundation 口径）；推流落盘文件（无编辑列表的分片 MP4）按 ffmpeg 口径——音轨起点 = 容器 tfdt 偏移 + 加回 AAC priming（`--aac-priming auto`），报告同时给两种口径（W1-A2 报告 §1.2）。
- 不连续检测（`av --discontinuities`）：相邻样本跳变 > 0.5 满幅，落在已知 click 位置 ±1 ms 内的排除。这是 A1 第三项的正式离线口径；stats.jsonl 的 `audio.discontinuities` 是流式启发式，只作信息项。

### 2.4 无界面模式

```
switcher-headless --show test.json --script scenario.json --duration 3600 --stats stats.jsonl
```

- 按脚本在指定拍点发命令（切换、转场、叠加、开关录制推流）。
- 每秒一行统计写进 stats.jsonl：V1、V2、V3、E1、E2、A1、内存、CPU、GPU。这份 stats 和 UI 状态行、API 是同一个结构。

### 2.5 回环采集

Mac 的外部显示输出 → HDMI 采集卡 → 回到本机另一路输入或另一台 Mac。用于 L2 和显示路径验证。

### 2.6 网络损伤

- macOS 自带 dnctl + pfctl（dummynet）做限速、丢包、延迟；更稳的做法是一台 Linux 路由器跑 tc netem。
- 本地推流服务器用 MediaMTX（MIT），能收 RTMP / SRT 并落盘，落盘文件交给 frameprobe。

### 2.7 设备矩阵（最小集合）

| 类别 | 至少 |
|---|---|
| 机器 | 1 台无风扇笔记本（M1 Air，8 GB）+ 1 台 Mac mini / Studio（目标机） |
| macOS | 当前版本和上一个大版本 |
| UVC 采集卡 | 1 种主流型号（Elgato Cam Link 4K 之类） |
| DeckLink | 1 块（Mini Recorder 或 UltraStudio） |

| 音频接口 | 1 台 USB 接口 + 一个聚合设备 |

### 2.8 性能采集

- 引擎内所有阶段打 os_signpost；用 xctrace record --template 'Metal System Trace' 抓；Instruments 的 Allocations / Leaks 跑 S2。
- 环境固定：接电源、关低电量模式、记录机型和 macOS 版本、关闭其它占 GPU 的程序。

### 2.9 实时线程检查

- 调试构建里给音频回调加断言（进入回调时置标志，锁、分配、日志的封装函数检查标志）。
- 有条件的话用 clang 的 RealtimeSanitizer（-fsanitize=realtime，需较新工具链），把带 [[clang::nonblocking]] 标记的函数里的违规直接报出来。

## 3. 测试方法

按指标编号给出做法。所有"标准负载"指第 13 节设计方案里的 1080p60 八路场景，除非另有说明。

| 指标 | 做法 |
|---|---|
| V1–V3、V5 | 无界面模式，8 路合成源（帧率混用 30 / 59.94 / 60），跑 1 小时，读 stats.jsonl；同时录一份文件交 frameprobe 数总帧数和缺口。V3 用 stats.jsonl 的 `jitter_ms`（渲染线程唤醒时刻 − 理想拍点，每秒窗口最大值），p99 取各秒最大值（比逐帧 p99 严；G2 报告 §7 第 4 条） |
| V4 | 同上，frameprobe 按输入 ID 统计每路的重复和丢弃；30 fps 源在 60 fps 节目里重复率应恰好 50%，其他都算设计外。设计内的期望按精确速率核算：在播 K 帧、输入帧率 r、节目帧率 P → 设计内 dup / drop 期望 = K·\|1 − r/P\|，允许 +1 帧相位余量（向上取整；frameprobe 在播段口径里每个连续在播段各 1 帧——同一路每次回到 PGM 相位都重新起算，G4 定），超出的算设计外——"设计外 = 0"按这个口径判；StatsSummary 按平均帧率算的比例只作 §4 必须档（≤ 0.05%）的参照（G2 报告 §7 第 6 条）。frameprobe 这一口径只统计有单一输入身份的帧：Fade / Wipe / Zoom / Stinger 期间的合成帧（转场应用拍之后到完成拍之前）不计入——它们的帧号行与 ID 块可能来自不同输入或是混合值，按输入统计没有定义；引擎侧 stats.jsonl 的 dup / drop 全程照算，两个口径都要满足（G4 报告 §3；场景里的转场拍段由 gate 脚本给 `frameprobe --blank-ticks`） |
| V6 | 脚本在第 1000 拍 Cut、第 3000 拍 Fade（30 帧）；frameprobe 找新输入 ID 出现的第一帧；Cut 前后不得有混合帧。"Cut"= frameprobe 里新 ID 紧接旧 ID 出现（中间没有解不出身份的帧）的切换；Wipe / Zoom / Stinger 是转场不是 Cut，它们的中间拍不参与"所有 Cut 干净"的判定（G4 报告 §3） |
| V7 | 输入 A 灰度 64、输入 B 灰度 192，Fade 30 帧；frameprobe 逐帧算混合比例，与线性曲线比；T-bar 用脚本推到 25 / 50 / 75%，读混合比例 |
| V8 | 离线渲染：固定状态（叠加 1 和 3 开、画中画在右下、抠像开）+ 固定输入图 → PNG；和参考图比 PSNR / SSIM。参考图有意更新时必须在 PR 里说明 |
| V9 | 灰阶（0–255 步进 8）和 75% 色条做输入，录 ProRes 或无损，ffmpeg 取像素值比对 |
| A1 | 8 小时长稳期间统计回调超时和欠载；同时对录制文件做波形不连续检测（相邻样本跳变 > 0.5 满幅且不在 click 位置；§2.3 的离线口径 `frameprobe av --discontinuities`，stats.jsonl 的 discontinuities 只作信息项） |
| A2 | 录制标准负载 10 分钟，frameprobe 找每个闪光帧和对应 click；分别对录制文件、NDI 输出（用 NDI 录制器抓）、回环采集的外部显示各测一次。只取整秒配对（§2.3），判最大绝对值，均值 / 标准差同时报；推流落盘文件按 ffmpeg 口径 |
| A3 | 8 小时录制，对 A2 序列做线性拟合，斜率 × 8 h |
| A4 | ISO 分路录 4 路，每路各自含闪光和 click；比较各文件同一事件的时间 |
| A5 | 耳机输出用线回环到音频接口输入，发 click，测往返再除以二；或用专门的往返延迟工具 |
| A6 | EBU Tech 3341 / 3342 的测试文件通过文件输入播放，读表，和标称值比 |
| A7 | 调试构建 + 断言 / RealtimeSanitizer 跑标准负载 10 分钟，违规数必须为 0 |
| E1 | 标准负载 + 3 路编码，读 stats；再故意把编码器压到极限（4K + 3 路）确认计数正确增长而渲染不受影响 |
| E2、E3 | 录制文件或 MediaMTX 落盘文件用 ffprobe -show_packets 算码率窗口和关键帧间隔 |
| E4 | 固定测试片段（自有素材，含静态、慢动、高动态三段）经文件输入编码录制，ffmpeg libvmaf 对源算分；结果存入基线表 |
| E5 | 正常停止录制 20 次（各种时长），每个文件 ffprobe；时长与脚本时长比 |
| E6 | 录制中随机时刻 kill -9，重复 10 次；ffprobe 每个文件，比较可播放时长与实际录制时长 |
| E7、E8 | 3 路推到 MediaMTX 的三个端口；用 dummynet 封其中一个端口 30 秒后放开；看其他两路丢帧、看被封那路是否重连、重连后录一段交 frameprobe 测 A2 |
| E9 | dummynet 把带宽限到设定码率的 70%，跑 5 分钟；软件报告的网络丢帧和 MediaMTX 落盘文件的缺帧数比 |
| L1 | 合成源帧里有生成时间戳，编码器入口再打一次戳，差值就是 L1；按输入类型换真实设备时，用回环抓设备输出帧里的时间信息 |
| L2 | 两种方法任选：一是手机显示毫秒秒表，摄像头拍它，外部显示输出 PGM，用 1/1000 s 快门同时拍下秒表和显示器，读差；二是回环采集 + 合成源帧号。每种输入 10 次取中位数；另测设备直连显示器作扣除参考 |
| L3 | 编码器输出时刻和抓包时刻（tcpdump）比 |
| S1 | 8 小时脚本：每 30 秒切换一次、每 5 分钟开关一次叠加、2 路推流 + 1 路录制 + NDI 全程开；读 stats 检查每个 5 分钟窗口 |
| S2 | 长稳期间每分钟采一次 RSS，预热 30 分钟后线性拟合 |
| S3 | 长稳期间的 CPU（进程级）和 GPU 平均和 p95；GPU 用 IOKit 的 `Device Utilization %`（与 powermetrics 同一计数器、不需要 root；powermetrics 作对照，G2 报告 §7 第 3 条） |
| S4 | M1 Air 跑标准负载 1 小时，powermetrics 记频率；对照 V2 |
| S5 | 拔插 UVC 采集卡和 USB 摄像头各 20 次（可用支持软件断电的 USB hub 自动化）；记崩溃、恢复时间、编号设置 |
| S6 | 系统设置里逐个撤销权限再启动；授权后不重启看能否恢复 |
| S7 | 录到一个快满的小分区；录到一个被限速的外置盘 |
| C1 | WebSocket 客户端在已知时刻发 cut，PGM 帧号给出生效拍点；差值 |
| C2 | 客户端记录收到状态增量的时刻和该状态对应的拍点时刻 |

| C4 | 脚本每秒发 100 条带序号的命令，检查状态里的最终序号和顺序 |
| C5 | Companion 配一页按钮对着兼容层端口，逐个按，看 PGM 和按钮 tally 反馈 |

