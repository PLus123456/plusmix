大屏与时间线方案

监看框贴合画面、横竖屏排布、按屏放内容的"舞台"、一键多屏的画面预设和时间线，再加"导播 ｜ 大屏"两套工作面板。能做，而且是在现有引擎上加一层，不用推倒重来。

等你拍板没有改任何代码。完整文字在 docs/spec/大屏与时间线方案.md，代码基线 main 949d956。

三件事，三层

每一层可以单独交付。节目里没配大屏时，一切和现在逐字节相同。

第一层 · 只动界面

监看框贴合画面，横竖屏

监看框的形状跟画布走，不再上下一大片黑。省出来的高度给输入条变多行。竖屏时输入区挪到监看右侧。

约 1 个会话，不碰契约，现在就能开
第二层 · 舞台

画出屏幕，按屏放内容

舞台、屏幕、输出口三样分开。监看看的是现场的样子，不是挤进一路 1080p 之后的样子。也是预监后 TAKE，多块屏同一拍换。

约 5 个会话 + 1 个检查点
第三层 · 预设与时间线

编好，现场只管往下走

一组屏各放什么存成画面预设。时间线把预设排成提示点，替你把下一步装进预监，GO 就是 TAKE。

约 4 个会话 + 1 个检查点

第三层

时间线：GO 一下走一步

时间线是一串提示点。它不另起一套出画机制，只做两件事：把下一个提示点的画面装进舞台预监，到点替你按 TAKE。所以预监里永远是"下一步"，手动随时能插进来改。按 GO 试试。

舞台 PVW · 下一步
舞台 PGM · 现在屏上

触发有三种：手动（等 GO）、跟随（上一条走完或片子放完自动走）、定时。"录制操作"可以把排练时手动走的一遍直接记成提示点。走带放在状态机里按拍执行，所以时刻逐拍确定，不靠界面线程。GO 默认也认 PgDn 和方向键，翻页笔能用。上面这张表和 HiRender 的节目管理是同一种东西：行是每块屏，列是演出的一个时刻，只是每列多了触发方式。

对照

和 HiRender S3、屏幕管理类切换台对一遍

读了 HiRender S3 的三份官方手册和几款同类软件的官方文档。模型对得上，差别主要在一处：它点节目就上屏，我们默认先进预监。

  • 以后再借的：给中控的 TCP / UDP 文本指令、LTC / MTC 时间码、临时盖上去的插播层。

落地顺序

和第五波界面改版一个量级：十来个会话、两个检查点。第 1 步不依赖任何决定。

步会话交付依赖
1监看贴合与竖屏排布第一层全部（只动 App）无
2契约提案：舞台、预设提案写完停下来问你，批了再落类型你定下面的问题
3舞台合成 ‖ 舞台状态与命令渲染两遍 + 输出口打包；TAKE、同拍2
4输出口出画 ‖ 大屏面板外部显示 / NDI 点对点；面板切换、舞台监看、屏幕编排、预设条3
5检查点合入、全量、接真屏或回采的人工清单4
6–7契约提案：时间线 → 走带 ‖ 时间线面板提示点、GO、录制操作5
8播放器输入一路输入装一串片子，接缝不黑可与 7 并行
9–10手册 → 检查点合入、放行7–8
  • 要先写探针验证的三处：外接显示口能不能逐像素送出（缩放、色彩管理）；多个输出口之间差不差帧；大舞台（8192 宽 + 两路 4K）在入门机型上的渲染耗时。前两条需要采集卡或 LED 处理器回采。
  • 明确先不做：SDI 输出卡与逐帧锁定、多机联动、边缘融合和几何校正、LED 逐点校色、自由时间线上的关键帧、DMX / Art-Net。定位是"一台 Mac 同时管直播和几块屏"。
