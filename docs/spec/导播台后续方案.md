## 1. 引擎升级

### 1.1 float16 线性工作空间

- 给谁用：所有人。半透明叠加、淡入淡出、缩放在 gamma 域混合会偏暗偏脏，线性域才正确。这是 1.4 的前提。
- 设计：合成 pass 的中间纹理改成 RGBA16Float。输入采样着色器里把 BT.709 gamma 值转线性（反 OETF），所有混合、缩放、抠像在线性域做，输出 kernel 再转回 gamma 并抖动到 8-bit（Nageru 的做法：中间 16/32-bit 浮点，输出加抖动）。
- 动哪些模块：SwitcherCore 合成引擎的纹理池、全部着色器、输出转换 kernel。数据模型和接口不变。
- 代价：显存带宽翻倍，Apple Silicon 上可接受；渲染耗时预算放宽 30%。
- 新增测试：V8 参考图全部重新生成并在 PR 里说明；V9 不变；V1 阈值临时放宽 30% 后再收回。

### 1.2 缩放质量

- 设计：缩放提供两档。性能档：mipmap + 双线性（第一版）。质量档：Lanczos3（MPSImageLanczosScale 或自写 compute kernel），用于画中画和多画面缩略图。每个输入可单独选档。
- 新增测试：V8 加缩放专项参考图（细线、文字），质量档 SSIM ≥ 0.99。

### 1.3 自写混合 MP4 封装器与多轨录制

- 给谁用：需要把录制直接丢进 Final Cut / Premiere / Resolve 的人，以及想在一个文件里存多路 ISO 的人。
- 设计：录制期间写分片 MP4（moof 片段，每 1 秒），正常停止时把 moov 重写到文件头变成标准 MP4（这就是 OBS 换成混合 MP4 的思路）；崩溃时片段仍可播放。一个文件可含多条视频轨（PGM + 各输入 ISO）、多条音轨（各总线、各输入）、章节标记（快捷键打点）、时间码轨。
- 动哪些模块：SwitcherOutputs 新增 muxer；录制器从 AVAssetWriter 切到它；AVAssetWriter 保留给 ProRes .mov。
- 选型：自写（MP4 规范公开），或用 FFmpeg 的 movenc（LGPL 构建，用 frag_keyframe + 结束时二次封装）。先用 FFmpeg 跑通，再决定要不要自写。
- 新增测试：E12 兼容性（QuickTime、Final Cut、Premiere、Resolve、VLC 全部能开、多轨可见）；E6 收紧到损失 ≤ 1 s；A4 多轨对齐 ≤ 1 ms。

### 1.4 10-bit / HDR

- 给谁用：用 DeckLink 10-bit SDI、拍 HLG 的人；HDR 是少数，10-bit SDR 是多数。
- 设计：
  - 输入：DeckLink v210、HEVC Main10 文件、ProRes 10-bit → 采样着色器解到 float16 线性（1.1 已经够精度）。
  - 色彩管理：每路输入带色彩空间标签（BT.709 / BT.2020，SDR / PQ / HLG）。工作空间定为线性 BT.2020 float16。SDR 源上变换、HDR 源保留，输出时按目标输出各自转换；SDR 输出用 BT.2390 / BT.2408 的映射做下变换。
  - 输出：HEVC Main10（VideoToolbox），ProRes 422 HQ / 4444，NDI 高质量模式；HDR 元数据（mastering display、MaxCLL）写进流和文件。
  - 预览：CAMetalLayer 开 EDR（wantsExtendedDynamicRangeContent），在支持的 Mac 显示器上看到真 HDR。
- 新增测试：V15 10-bit 电平误差 ≤ 1（10-bit 刻度）、色彩空间标签正确、SDR/HDR 混合场景的下变换对参考图 ΔE 阈值。
- 依赖：1.1。

### 1.5 降级策略

- 给谁用：无风扇的 MacBook Air 用户，和输入接太多的人。
- 设计：引擎监控 V1、V2 和热压力（ProcessInfo.thermalState）。触发条件成立时按顺序降：缩略图刷新率 → 多画面刷新率 → 预览窗口分辨率 → 质量档缩放改性能档 → 非 PGM 输入的解码分辨率。PGM 和编码永远最后动。每一步都在状态里标记，UI 显示黄色提示。压力消失后按相反顺序恢复。
- 新增测试：S9 触发后 V2 达标，恢复后自动回升；S4 更新为引用 S9。

## 2. 输入扩展

### 2.1 Syphon

- 给谁用：演出场景，把 Resolume、TouchDesigner、Processing、Unity 的画面直接拿进来。
- 设计：SyphonMetalClient 给的就是 IOSurface 背后的 Metal 纹理，零拷贝进帧槽。同时做 Syphon 服务端把 PGM 发出去给别的软件。
- 选型：Syphon 框架，BSD。
- 新增测试：L1 加 Syphon 类型，≤ 1 帧。

### 2.2 浏览器源

- 给谁用：用网页做叠加（在线计分板、评论墙、歌词投影的网页版）。
- 设计，两条路：
  - 轻量路：WKWebView 放在一个透明的、最底层的隐藏窗口里，用 ScreenCaptureKit 的窗口捕获拿画面。便宜，纯苹果框架。坑：窗口必须在屏幕上；alpha 通道能不能透传要验证。
  - 完整路：CEF（Chromium Embedded Framework，BSD-3）离屏渲染，带 alpha、60 fps、页面音频。这是 OBS 的做法，用户熟悉的网页叠加都按它测过。包体 100 MB 以上，正好做成 6.2 的进程外插件，不污染主程序。
  - 先做轻量路，验证 alpha 不行就上完整路。
- 新增测试：V14 渲染 fps ≥ 30（目标 60）、alpha 正确（参考图）、页面 CPU 占用不影响 V2。
- 依赖：完整路依赖 6.2。

### 2.3 远程连线（WebRTC）

- 给谁用：远程嘉宾、异地讲员、外场记者。要求嘉宾不装软件，点链接就进。
- 设计：
  - 服务端：LiveKit（Go，Apache-2.0），自建或用其云服务。导播台作为一个参与者进房间，订阅所有嘉宾，发布一路回传。
  - 嘉宾页：静态网页（我们的 HTTP 服务器托管），LiveKit JS SDK，看到回传的 PGM、听到 mix-minus。
  - 每个嘉宾 = 一路输入：视频帧进帧槽，音频进环形缓冲；WebRTC 自己保证嘉宾的音画同步，我们只在到达时打 host time。
  - mix-minus：每个嘉宾听到的是 Master 减去他自己的声音。实现是 Master 算一次，每个嘉宾减去自己（后处理、带增益的信号），N 次减法，很便宜。这需要 4.1 的"每嘉宾一条回传总线"。
  - 回传视频：PGM 低码率再编一路（VideoToolbox 会话数够）。
  - 轻量替代：单向贡献（远程一台摄像机）可以用 HaishinKit 的 WHIP/WHEP 直接收，不需要房间。
- 选型：LiveKit 服务端与 Swift SDK 都是 Apache-2.0。不选自己撸 WebRTC 框架做 P2P，服务端一条路走到底。
- 新增测试：A8 mix-minus 回声（嘉宾自己的声音回到自己耳朵 ≤ -60 dB）；L4 嘉宾端到端 ≤ 400 ms（目标 250）；服务器链路用 dummynet 加 3% 丢包后 A1 仍为 0。
- 依赖：4.1。

### 2.4 PTZ 控制

- 给谁用：教会、会议室，一个人管三四台云台机。
- 设计：协议三选：VISCA over IP（索尼系，UDP 52381，覆盖最广）、NDI PTZ（NDI 摄像机，SDK 自带命令）、ONVIF（SOAP，最重，最后做）。预置位挂在输入上；选项"选到 PVW 时自动调预置位"；手柄用 GameController 框架。
- 动哪些模块：SwitcherControl 新增 PTZ 驱动；输入设置加 PTZ 配置。
- 新增测试：C8 命令发出延迟 ≤ 20 ms；协议单元测试对照抓包样本。

### 2.5 播放列表与媒体播放器

- 给谁用：片头片尾、多段宣传片、诗歌背景视频。
- 设计：播放列表是一种输入：一组文件，每个带入点出点、结束动作（下一段 / 停在末帧 / 循环 / 切回上一 PGM）。播放器控制：播放、暂停、定位、循环、变速。切换到 PGM 时自动从入点开始（可选）。音频有闪避钩子（4.1）。片段之间预解码下一段的首帧，接缝无黑帧。
- 新增测试：V12 接缝处无黑帧无重复帧（帧号）、定位延迟 ≤ 100 ms。

### 2.6 数据源

- 给谁用：字幕要跟名单、赛程、比分、RSS 走的人。
- 设计：DataSource 对象轮询或监听：本地 CSV / JSON 文件（文件监视）、HTTP JSON、Google Sheets（"发布为 CSV"链接，不用 OAuth）、RSS、内置计分板（快捷键 / API 直接加减）。数据变化在下一拍生效。字段绑定语法 {{source.row[n].column}}，给 3.1 用。
- 新增测试：更新延迟 ≤ 1 s + 轮询周期；坏数据（缺列、非法编码）不崩、保留上次值并提示。
- 依赖：3.1。

## 3. 制作功能

### 3.1 标题设计器

- 给谁用：所有人。第一版只能叠图片，这是最大的功能缺口。
- 设计（核心决定：用 Core Animation 树做标题，用 CARenderer 渲进 Metal 纹理）：
  - 一个标题 = 一棵 CALayer 树：CATextLayer（Core Text 排版）、CALayer 图片、CAShapeLayer 形状、CAGradientLayer、遮罩。动画 = CAAnimation（入、出、循环、滚动 crawl、倒计时、时钟）。
  - 渲染：CARenderer(mtlTexture:) 每拍以节目时钟的时刻调 beginFrame(atTime:)，动画进度由我们传入的时间决定，逐帧确定、可测试；结果是带预乘 alpha 的纹理，直接当 Overlay 合成。不用 CPU 栅格化。
  - 编辑器：同一棵层树放进 AppKit 画布加编辑手柄，所见即所得，零额外渲染代码。
  - 文件：模板是 JSON（层、属性、动画关键帧、字段），字段用 2.6 的绑定语法；一个模板多组预设（同一版式不同文案）。
  - 内置模板包：下三分之一、全屏名单、计分板、倒计时、滚动条、时钟。
- 动哪些模块：新 Package SwitcherTitles（模型 + 渲染 + 编辑器）；输入层加"标题输入"类型；Overlay 的进出动画和标题自己的动画统一由拍点驱动。
- 新增测试：V10 动画起始拍点误差 0、时长误差 ≤ 1 帧；文字渲染参考图（字体嵌入、多语言、emoji）；标题层渲染耗时 ≤ 1 ms。

### 3.2 实时字幕

- 给谁用：无障碍需求（教会、学校）、多语言活动。
- 设计：Master 或麦克风总线送去语音识别，识别结果写进 3.1 的"字幕条"模板字段。识别后端可插：Soniox 流式（你 LectureLive 里的转写和翻译链路可以直接搬过来）、苹果自带的 SFSpeechRecognizer（可离线）、Whisper 的 Core ML 版。第一步只做烧录进画面；嵌入 CEA-608/708 字幕轨和推流平台的字幕接口放后面。
- 新增测试：字幕延迟（话音结束到上屏）≤ 2 s；识别线程不影响 V2、A1。
- 依赖：3.1。

### 3.3 虚拟演播室

- 给谁用：小演播室、没有实体布景的节目。
- 设计：2.5D，不做真 3D。一个布景 = 分层图片（背景、桌子、前景）+ 一路抠像后的摄像机 + 可选的第二块屏（嵌入另一路输入）。"虚拟机位"是一组变换预设（推拉、平移），切换预设时对变换插值，层之间按深度做视差。抠像用 1.1 的线性域升级版（更好的溢色抑制、边缘柔化、光照匹配）。布景文件可从分层 PSD 导入。
- 动哪些模块：合成引擎加"布景图"这种复合输入；抠像着色器升级。
- 新增测试：V11 抠像质量（对已知 alpha 的合成参考，边缘 IoU ≥ 0.95）；V7 覆盖虚拟机位过渡。
- 依赖：1.1。

### 3.4 回放与慢动作

- 给谁用：体育、赛事、任何"再看一遍"的场景。这是 vMix 4K/Pro 档最贵的功能之一。
- 设计：
  - 录：回放录制器持续把选中的 N 路输入（含 PGM）以帧内编码写盘（ProRes Proxy 1080p60 每路约 90 Mb/s，4 路约 45 MB/s，内置 SSD 无压力；或 H.264 全 I 帧），按拍点索引，环形覆盖，保留时长可设。内存放不下，算一下就知道：1080p NV12 每帧 3 MB，20 秒 × 60 fps × 4 路 ≈ 15 GB。
  - 标：快捷键打入点出点（对任意机位）；事件列表可命名。
  - 放：回放播放器是一路输入，从任意点解码（帧内编码所以定位便宜），速度 25%–100%，播放中可切机位；"送 PGM"可带 stinger。慢动作第一步用帧重复和帧混合；真插帧见 7.4。高帧率摄像机（120 fps）进来时慢放自然更顺。
  - 硬件：这一项要求快的 SSD，UI 显示写入余量。
- 动哪些模块：SwitcherOutputs 加回放录制器（用 1.3 的封装器），SwitcherInputs 加回放播放器，UI 加回放面板。
- 新增测试：E10 标记精度 ≤ 1 帧、播放启动 ≤ 200 ms（必须 500）、回放录制期间 V2 不变、磁盘写入余量 ≥ 2 倍、环形覆盖后连续无断层、8 小时不漏。
- 依赖：1.3。

### 3.5 多画布

- 给谁用：同时出横屏（YouTube）和竖屏（抖音 / TikTok）的人。Meld 用这个打市场。
- 设计：画布 = {分辨率、每路输入在这块画布上的构图（裁切、位置）、这块画布自己的叠加层、挂在它上面的输出}。PGM/PVW 的切换状态所有画布共享，只有构图不同。渲染在同一个命令缓冲区里画所有画布，成本线性增加。
- 动哪些模块：MixerState 加 canvases[]；输出挂到画布；UI 加画布切换和构图编辑。
- 新增测试：V13 所有画布同一拍切换（帧号一致）；V1 按画布数线性放宽。

### 3.6 多画面定制与 Aux 路由

- 设计：多画面布局可编辑（格数、大小、标签、tally、每格电平表、安全框）。输出源统一成一个枚举：PGM、PVW、多画面、任一输入、任一画布、清洁 PGM（无叠加）——任何输出（外部屏、NDI、录制、推流）都可选任意源，等于 ATEM 的 Aux 总线。
- 新增测试：C3 扩展到每个输出的源标签与画面帧号一致。

## 4. 音频扩展

### 4.1 更多总线、闪避、对讲

- 设计：总线扩到 Master + A–G + 每嘉宾回传总线（给 2.3）。自动闪避：指定侧链（如麦克风总线）超过阈值时压低指定输入（背景音乐），触发 / 释放时间可调。对讲：操作员麦克风只送某条回传总线（对嘉宾说话不进 PGM）。每条总线独立效果链。
- 新增测试：A10 闪避触发 / 释放时间误差 ≤ 10 ms、无爆音；A8 对讲不漏进 Master（≤ -80 dB）。

### 4.2 AU 插件宿主

- 设计：只做 Audio Unit（AUv2 / AUv3），不做 VST3（VST3 SDK 是 GPLv3 与 Steinberg 专有许可双授权，Apache 项目里用着别扭；Mac 上 AU 覆盖足够）。AUv3 在 macOS 上默认进程外，插件崩了不带走主程序。插件报告的处理延迟自动做补偿（对齐视频）。每路输入和每条总线可挂效果链，带预设。
- 新增测试：A9 插件报告延迟后 A2 不变；S8 插件崩溃隔离；A7 宿主调用不违反实时线程规则。

### 4.3 响度归一化与输出延迟

- 设计：文件输入加载时用 libebur128 预扫描，按目标响度（默认 -23 LUFS，可改）设初始增益，素材之间音量统一。每个输出可设独立音频延迟（对齐外部大屏或投影的处理延迟）。
- 新增测试：预扫描后播放响度 ±1 LU；输出延迟设置与 A2 测量一致。

## 5. 输出与控制扩展

### 5.1 局域网 HLS

- 给谁用：分会场、大堂、育婴室，用 iPad / Apple TV / 浏览器看 PGM，不经过公网。
- 设计：内置 HTTP 服务器（swift-nio 或 Hummingbird，都是 Apache-2.0）从内存环里发 fMP4 分片和播放列表；分片 1–2 秒，延迟 6–10 秒；可选 LL-HLS 到 2–3 秒。复用推流的编码会话，不多占编码器。
- 新增测试：E11 苹果的 mediastreamvalidator 无错误；10 个客户端并发不掉线；延迟达标。

### 5.2 外部 tally

- 设计：三种出口。TSL UMD 3.1 / 5.0（行业标准，UDP，几十字节一包，硬件 tally 和多画面设备都认）；WebSocket JSON（自制 ESP32 灯用）；vMix 兼容层顺带覆盖 Tally Arbiter 这类工具。
- 新增测试：C7 tally 包发出延迟 ≤ 1 拍 + 网络；与画面一致 100%。

### 5.3 Web 控制器与 iPad

- 设计：本地 HTTP 服务器带一套响应式网页，用 WS API 做第二操作位（切换、叠加、音频、播放列表、计分板），支持自定义按钮页。之后再做原生 iPad 应用（同一 API）。
- 新增测试：C9 = C1–C4 在 Web 控制器上重跑；手机、iPad、桌面浏览器各一。

### 5.4 宏与触发器

- 设计：宏 = 命令序列加等待（录制方式：按一遍记下来）。触发器 = 事件 → 宏：输入信号出现 / 消失、切换发生、定时、MIDI、GPI（经 tally 设备回读）、数据源变化。复杂逻辑交给 6.1 的脚本。
- 新增测试：宏执行时序误差 ≤ 1 拍；触发器不重入。
- 依赖：6.1（宏和触发器的执行器就是脚本引擎的子集）。

## 6. 平台化

### 6.1 脚本

- 设计：JavaScriptCore（苹果自带，无依赖，默认没有任何 I/O，天然沙箱）。暴露：同一套命令 API、状态订阅、事件（切换、输入状态、tally、定时器、MIDI）、受限的 fetch、标题字段读写、数据源。脚本跑在自己的队列，绝不进实时线程；看门狗限制单次执行时间，死循环被终止并报错。文件访问、网络访问按脚本声明的权限授予。
- 对照：vMix 用 VB.NET，OBS 用 Lua / Python。Mac 上 JS 是最自然的选择，Stream Deck 插件和网页控制器也是 JS，生态统一。
- 新增测试：C6 死循环脚本 ≤ 1 s 内被终止且 V2 不受影响；API 覆盖率测试（每条命令有脚本用例）。

### 6.2 插件系统（三层）

- 第一层，着色器插件：一个 .metallib + JSON 清单（参数、输入数量）。做滤镜、转场、抠像变体。着色器做不了 I/O，安全，进程内加载。
- 第二层，进程外插件：清单 + 可执行文件。协议：XPC 或本地 socket 握手、声明能力（源 / 输出 / 滤镜）、视频用 IOSurface ID + host time PTS 交换、音频用共享内存环、控制用 JSON。主程序监管：崩了自动重启，对应输入进 noSignal。任何语言都能写。浏览器源（CEF 路线）、第三方设备 SDK、云服务对接都走这层；NDI / DeckLink 如果许可证上需要隔离也能挪过来。代价是多 0–1 帧延迟。
- 第三层，脚本插件：JS 包 + JSON 定义的设置面板，用 6.1 的 API。
- 稳定性：协议带版本号，主程序保持向后兼容两个版本；插件目录（见 8.3）。
- 新增测试：S8 插件崩溃 0 次影响主程序、恢复 ≤ 1 s；L4 插件帧路径 ≤ 1 帧；协议兼容性测试跑上一版插件。
- 依赖：6.1。

## 7. 前沿与研究项

这些是 vMix 没有、Mac 平台反而有优势的地方（Core ML、神经网络引擎、Vision 框架）。也和你的 PyTorch 背景对得上：训练在 PyTorch，导出 Core ML 部署。

### 7.1 无绿幕抠像

- Vision 的人像分割（VNGeneratePersonSegmentationRequest）实时档在神经网络引擎上跑，输出 alpha 蒙版；跑在独立线程，结果下一拍用（1 帧延迟）。质量不够就自己训一个小模型换上。
- 新增测试：V11 分割版 IoU ≥ 0.90；每帧 ≤ 2 ms 且 V2 不受影响。

### 7.2 自动构图与自动切换

- 自动构图：人脸检测（VNDetectFaceRectanglesRequest）驱动裁切框，平滑跟随，做画中画和竖屏画布的自动取景。
- 自动切换：每路麦克风做话音检测，按"谁在说话"规则自动把对应机位推到 PVW（只到 PVW，切 PGM 由人确认，可选全自动）。
- 新增测试：裁切框抖动（帧间位移 p99 ≤ 2 px）；话音检测误触发率。

### 7.3 降噪

- 麦克风输入可挂：苹果的语音处理单元（AUVoiceIO，带回声消除）或 RNNoise（BSD-3）。
- 新增测试：A7 不违规；处理延迟计入 A9 补偿。

### 7.4 慢动作插帧

- 3.4 的升级：Vision 的光流（VNGenerateOpticalFlowRequest）或自训插帧模型，做 25%–50% 速度的平滑慢放。Nageru 配套的 Futatabi 就是 GPU 光流插帧的思路，代码 GPLv3 只能看不能抄。
- 新增测试：插帧画质（对高帧率真值的 PSNR）；是否能实时（1080p 25% 速 ≤ 1 拍）。

### 7.5 双机热备

- 教会和活动最怕的是主机死机。现实版本：两台 Mac 接同样的信号（SDI 分配器、NDI 本来就能多收），备机以只读方式跟随主机的命令流（WS），保持同样状态；看门狗发现主机心跳停了，备机接管推流地址和 NDI 名字。做不到无缝，目标是几秒内恢复。
- 新增测试：拔主机网线后备机接管 ≤ 5 s；接管后 A2 达标。

## 8. 运维与项目运营

### 8.1 更新、崩溃报告、诊断包

- 自动更新：Sparkle（MIT），签名 + 公证，增量更新。
- 崩溃报告：MetricKit 拿崩溃诊断，加自己的符号化，用户同意后上传；不上传任何节目内容。
- 诊断包：一键导出日志、stats.jsonl、去掉密钥的节目文件、系统信息，报问题时附上。
- 遥测：默认关；开了只发匿名的机型、macOS 版本、输入类型、编码器数量，为兼容性数据库服务。

### 8.2 本地化、文档、示例

- 中英双语起步，字符串外置，社区翻译。
- 文档站：概念（PGM/PVW 那套术语）、每种输入的接法、设备兼容性、API 参考、脚本参考、测试标准（公开，让用户知道你怎么验的）。
- 示例节目文件：教会（3 机位 + 歌词字幕 + 直播）、教室（屏幕 + 摄像头 + 录制）、活动（4 机位 + 回放 + 多画面）。

### 8.3 开源运营

- 许可证与贡献：Apache-2.0，贡献用 DCO 签字（不用 CLA）。
- 设备兼容性数据库：社区提交采集卡、摄像头、音频接口的实测结果（型号、固件、macOS 版本、通过的测试项），网页可查。这是你自己测不过来的部分，也是别人最愿意贡献的部分。
- 插件目录：清单格式、签名、审核规则；着色器插件包可以直接在目录里下载安装。
- 路线图公开，功能投票；每个大功能开工前先发设计稿征求意见。
- 测试硬件众筹：设备矩阵里缺的卡让社区借或捐。

### 8.4 如果以后想商用

- 核心保持开源，商业化只能加在外面：付费插件包（回放、虚拟演播室、远程连线的托管服务器）、支持合同、和硬件商的捆绑、托管的 LiveKit / HLS 中继服务。不要走"开源版阉割、商业版完整"的路，社区会散。
