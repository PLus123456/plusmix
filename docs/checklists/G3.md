# G3 人工检查清单（M1 切换 + M2 音频 + M3 输出 + M5 控制）

落地方案 §4 G3 的人工部分，G3 prompt 第 3 条。每条写"怎么做 / 看什么 / 过的标准"，做完在方框里打勾并记下看到的数字。
前提：`make gate3` 已跑完（自动项），`make gen build-app` 能编出 App。**接线状态见最后一节**：App 一期（W2-B）只接了合成源，
摄像头 / 文件 / 录制器 / 推流 / 音频引擎 / API 的 App 接线超过检查点 50 行的胶水额度，等用户决定由谁做；没接上的项先按 headless 的等价物做。

## 1. 打开 App，加输入，键盘 / T-bar / FTB

- [ ] 启动：`make gen build-app` 后打开 `.build/DerivedData/Build/Products/Debug/Switcher.app`（或 Xcode 里跑 Switcher scheme）。
      看：主窗口出来，深色，底栏状态行每秒刷新（fps / render / GPU / CPU / 丢帧）。
- [ ] 添加输入 → 合成源（60 fps，带音频）→ 编号 1；再加 **内置摄像头** → 编号 2；再加 **视频文件** `Tests/Fixtures/pattern.mov`（循环）→ 编号 3。
      看：三个格子都出画面、tally 边框正确（PGM 红 / PVW 绿）。摄像头如果只显示"…在 W2-A，合并后可用"说明 App 还没接 W2-A 的输入工厂（见最后一节）。
- [ ] 键盘：按 `2`（PVW 标题变 "2 …"）→ `空格`（Cut：PGM 变 2，PVW 变原 PGM）→ `3` → `回车`（Fade 30 拍 = 0.5 s，能看到 T-bar 自己往上走再回弹）。
      过：每一步画面与标题条同时变，Cut 无过渡帧。
- [ ] 鼠标把 T-bar 拖到 50% 停住：PGM 里两路各一半（合成源 + 摄像头能明显看出叠加）；再拖到顶：对调并回弹到 0；松手前没到顶则停在原位。
- [ ] `F` 键 FTB：PGM 0.5 s 渐黑、PGM 标题变 "PGM · FTB"，Master 表随之落到 −∞（音频引擎接上后）；再按一次渐出。

## 2. 录 2 分钟，对音画

- [ ] 底栏"录制"→ 变 "● 录制中"（状态行编码跳帧 0、码率 ≈ 6 Mbps）。对着摄像头拍手 5 次（间隔 10 s），2 分钟后停止。
      **App 没接录制器之前的等价做法**：`switcher-headless run --show scenarios/g3-show.json --script scenarios/g3.json --duration 120 --record /tmp/g3-manual.mov --stats /tmp/g3-manual.jsonl --audio-device null`。
- [ ] QuickTime 打开 .mov：能播、时长 2:00 ± 1 帧、拍手声与手合上的画面同一帧（逐帧 ← → 看，允许 ±1 帧 = 16.7 ms）。
- [ ] 停止后如果开了"转 MP4"，.mp4 也能播；没开的话 `ffprobe /tmp/g3-manual.mov` 无错误、两轨时长差（E5 口径 ≤ 20 ms；已知 W1-E 录制器会多写 50–150 ms 音频，见 reports/G3.md 已知问题）。

## 3. 推到本地 MediaMTX，断网恢复

- [ ] 另一终端：`mediamtx scripts/mediamtx.yml`（RTMP 1935、SRT 8890）。App 底栏"推流"（或 Show 文件里加一路 `stream` 输出，url `rtmp://127.0.0.1:1935/s1`）。
      **App 没接推流之前的等价做法**：`swift test --package-path Packages/SwitcherOutputs --filter MediaMTXTests/testRTMP_endToEnd`（10 s 端到端，落盘在 `$TMPDIR/switcher-streaming-tests/rtmp-e2e/`）。
- [ ] `ffplay rtmp://127.0.0.1:1935/s1`：能看，帧号块在走，闪光每秒一次，延迟 < 2 s。
- [ ] 关 Wi-Fi 30 s（本机回环不受影响——改用 `sudo scripts/netem.sh block 1935 30` 封端口 30 s）再放开：状态行"重连中（第 n 次，x s 后）"，放开后 ≤ 15 s 恢复，ffplay 画面继续、帧号连续（重连后第一帧是关键帧）。

## 4. 外接显示器（如有）

- [ ] 接 HDMI 显示器，把一个监视窗口拖过去（一期只有主窗口；外部输出窗口是 W3-C 的）：拖动主窗口 10 s、进出全屏，状态行 **丢帧（missed_render）不增**。
      没有外接屏：BLOCKED-硬件，写在报告里；内置屏上同样拖 10 s 看丢帧不增（W2-B 的自动测试已覆盖）。

## 5. API 状态与画面一致

- [ ] App 起 API 后（或 headless `--api`）：`curl -s http://127.0.0.1:8765/api/v1/state | python3 -m json.tool | grep -E '"program"|"preview"'`。
      过：program / preview 与主窗口标题条一致；`curl -s -X POST http://127.0.0.1:8765/api/v1/command -d '{"cut":{}}'` 后画面立刻对调，`applied` 为 true。
- [ ] `curl -s http://127.0.0.1:8765/api/v1/tally`：PGM 路 program true，PVW 路 preview true，其余 false。

## 6. USB 摄像头拔插 3 次（如有）

- [ ] 加一路 USB 摄像头（或 iPhone 连续互通相机：设备列表里 `.external`），记下编号。拔掉：格子变"无信号"，App 不崩，编号不变；插回：≤ 3 s 恢复画面。重复 3 次。
      没有 USB 摄像头：BLOCKED-硬件；内置摄像头拔不了。用 `Packages/SwitcherInputs/Scripts/hotplug-timer.sh <uniqueID> 3` 可以自动计时（S5 的 20 次版本同一个脚本）。

## 7. 摄像头延迟（已知问题，顺手看）

- [ ] 摄像头加进来的头 4 s 是否黑屏；对着摄像头挥手，PGM 里的延迟感（W2-A 量到产品配置下 L1 2.5–3.9 帧、起流黑屏 4.2 s，根因在引擎到达余量，
      裁定与修法见 reports/issues/W2A-w1-core-arrival-pacing-vs-camera-latency.md 末尾的"G3 复核"）。这里只记录现象，不判过失败。
