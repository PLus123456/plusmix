## 4. 推流鉴权（W5-D）：地址带 user:pass 推到开鉴权的 MediaMTX

MediaMTX 1.21 的 RTMP 鉴权只认查询串 `?user=&pass=`，**不做 Adobe 挑战**；地址里的 user:pass@ 是给 Wowza / Nimble / FMS 这类 Adobe（FMLE 兼容）鉴权入口的，W5-D 自己做了前两轮、HaishinKit 永远拿不到带 userinfo 的地址。所以这里两条都要看：

- [ ] 开鉴权的 MediaMTX（在 scripts/mediamtx.yml 后面接 `authMethod: internal` + `authInternalUsers`：用户 pub / secret 只给 publish，匿名给 api；W5-D 的 `StreamAuthMediaMTXTests.authConfig` 里有现成的一段）：推流地址 `rtmp://127.0.0.1:1935/s1?user=pub&pass=secret` → 推上（MediaMTX 日志 `is publishing to path 's1'`），底栏"● 推流中"；去掉查询串 → publish 被拒（`NetStream.Publish.Unauthorized`，MediaMTX 故意拖 2.5 s 才回），底栏橙"推流 · 1 路异常"。
- [ ] 地址写 `rtmp://pub:secret@127.0.0.1:1935/s1`（userinfo 写法）推同一台开鉴权的 MediaMTX → **推不上**（这是 MediaMTX 的规矩，不是 bug；W5-D 的 `testE_streamAuth_mediamtxIgnoresUserinfo_documented` 钉的就是这个），错误文字里**没有**密码原文；换成不开鉴权的 MediaMTX → 推上（第 1 轮 connect 被接受，退回不带账号连）。
- [ ] 有 Wowza / Nimble（试用版即可）的人：推流页填 `rtmp://用户:密码@主机/应用` → 推上，服务器日志里恰好三次连接（要 adobe → 发挑战 → 通过）；密码故意写错 → 约 1 s 内失败，错误"鉴权失败（用户名或密码不对）：… reason=authfailed"，**不狂连**（HaishinKit 自带那套输错一次密码 13 s 连 430 次）。本机没有这类服务器：**BLOCKED-服务器**，W5-D 用自写的 AdobeAuthGateway 验过。
- [ ] 帮助 › 导出诊断包 → 解包 grep 密码：节目文件里 userinfo 整段是 `<redacted>`、查询串里 pass / user 的值打码；**但密钥写在路径里（rtmp://h/live/密钥）时原样进包**（问题单 W5D-w4-release-diagnostics-stream-key-in-url-path，W4-B）；底栏推流按钮的悬停提示仍原样显示地址含密码（问题单 W5D-w5-app-bottom-bar-stream-tooltip-shows-credentials，92 / 87）。这两条是**已知未修**，看到了别记成新问题。
