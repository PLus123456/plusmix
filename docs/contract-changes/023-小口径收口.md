## 一、转场进行中 setPreview / setProgram 拒收

提出会话 / 分支：W5-E / `w5-core-transition-guard`（prompt 90，2026-10-01；工作树分支 `claude/w5-core-transition-guard-e2ff9a`，同一提交）
状态：**已批**（用户 2026-10-01："批，P5 落地"）。语义本身用户 2026-09-29 已按 docs/ui-study/04-待拍板.md Q66 定了 (a)，reducer 与用例已在本分支实现；
这一节批的是"写进契约文字"那几句（CONTRACTS.md 与 `Command` 的文档注释），由 P5（prompt 99）照下面"契约文字"落地，W5-E 不动 SwitcherContracts / CONTRACTS.md。

### 改什么

不加类型、不改字段、不改 JSON 形态、`Command` 仍是 34 个 case；`setPreview` / `setProgram` 的 reducer 规则多一条：

| reducer 规则（`.setPreview(input:)` / `.setProgram(input:)`） | 结果 |
|---|---|
| `state.transition.isActive` | **原样返回**（新增；回执 applied = false） |
| `input` 既不是 0（黑场）也不在输入表 | 原样返回（原规则；总线入口的 `CommandValidator` 先拒，HTTP 400） |
| 其它 | `preview` / `program` = input（原规则） |

"转场进行中"就用契约里现有的 `TransitionState.isActive`（`progress > 0 || startTick != nil`），**定义不改**：
- auto 转场（fade / autoTransition 起的 Fade、Wipe、Zoom、Stinger）：从应用命令那一拍（progress 0、startTick 已记）到对调前一拍都算；
  对调那一拍状态机先 advance 再应用该拍的命令，所以排在对调那一拍的 setPreview 照常生效。
- T-bar：推杆在 (0, 1) 之间 progress > 0，**算进行中**（现有定义已经包含，不用补）；拉回 0 = 取消（progress 0、无 startTick），不算；推到 1 = 提交，不算。
- Cut 与选了 cut 类型 / 时长 0 的 autoTransition 原子完成，没有进行中的拍。
- 只看转场：FTB 渐变、叠加进出动画不挡（与提案 016 落地时 setTransitionParams 的口径相同）。

转场进行中被拒的命令因此是：fade / setTransition / setTransitionParams / autoTransition / **setPreview / setProgram**；
cut（立即完成对调）与 tbar（接管）照收；其余命令（叠加、音频、输出、输入表、loadShow）与转场无关，照旧。

### 为什么

- 问题单 reports/issues/UIA-w1-core-preview-program-change-mid-transition.md（S2）/ Q66：渲染器转场中按**当前**的 program 画底、按**当前**的 preview 画切进来的画面
  （`Packages/SwitcherCore/Sources/SwitcherRender/Renderer/CompositorPasses.swift:246-256`），而 setPreview / setProgram 没有 `isActive` 保护——
  转场中按数字键 / 点缩略图把正在切进来的画面换掉，Shift + 点把正在切出去的底图换掉，PGM 上是可见跳变。操作员转场中按数字键很常见。
- 用户 2026-09-29 定 (a) 拒收：最像硬件台、最安全，与 fade / setTransition / setTransitionParams / autoTransition 同一口径；(b)"收下、完成后再生效"要多记两个字段（契约 + 渲染器），以后再说。
- 顺带收掉两处不一致（都是好处）：
  - tally：转场中 `tally(ofInput:)` 把 PVW 也算 PGM，以前中途换 PVW，tally 灯会在转场中途从一路跳到另一路；
  - AFV：以前转场中 setProgram / setPreview 换了画面，状态机不发转场事件（`StateMachine.events` 只在进 / 出转场时发），
    AFV 仍按开始时的两路交叉淡变，声画不一致；现在这两条命令改不了转场中的两路（removeInput 删掉其中一路仍会把引用置 0，那是另一回事，见 W5-E 报告 §4）。

### 怎么迁移

只改命令语义，不改任何类型、字段、JSON：`Show.schemaVersion` 不升，节目文件与场景文件原样可读。
依赖"转场中改 PVW / PGM 会生效"的客户端：收到 applied = false 后等转场结束（`GET /api/v1/state` 或 WS 推来的快照里 `transition.isActive` 变 false）再发；
想立刻换到别的输入，先发 cut 完成当前转场，再发 setPreview / setProgram。
不批的话：reducer 规则照样生效（用户已定），只是 CONTRACTS.md §8 的 setPreview / setProgram 两行与代码不一致，等下次契约落地再补。
