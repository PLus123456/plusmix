# 故障排查

先看三处：输入格子上的一行文案（每路输入自己的状态，[输入 › 输入的状态](输入.md#输入的状态)）、底栏录制 / 推流按钮的悬停提示（逐路写状态和起不来的原因）与[推流 / 录制状态窗](输出.md#推流--录制状态窗)（每一路的最后错误和断线、重连的经过），和状态行右侧的提示 / 提醒（输出与系统级的事）。
出错（error）的格子、起不来的输出都写明了原因和下一步；"无信号"的格子不写在等什么，按 [§2](#2-无信号) 逐项查。这一页按症状把它们汇总起来。

## 1. 权限

| 症状 | 原因 | 怎么办 |
|---|---|---|
| 摄像头格子："摄像头权限被拒。打开 系统设置 › 隐私与安全性 › 摄像头，允许本程序后会自动恢复，不用重启" | 第一次弹窗时点了"不允许"，或从来没弹过 | 去那个页面把 PlusMix 打开；≤ 2 s 自动恢复。添加输入面板的横幅上有"打开系统设置…"直达 |
| 摄像头有画面、没声音；纯音频设备格子写"麦克风权限" | 设备自带麦克风 / 音频输入要单独的麦克风权限 | 系统设置 › 隐私与安全性 › 麦克风 |
| 屏幕输入一直"无信号"或写"屏幕录制权限被拒"，而且**从没弹过窗** | 屏幕录制没有系统弹窗，是设计如此 | 系统设置 › 隐私与安全性 › 屏幕与系统音频录制，点 + 把 PlusMix.app 加上，允许后自动恢复（系统可能要求重开 PlusMix） |
| 授权过了，重新编译 / 更新之后又问 | 没有 Team ID 的 ad-hoc 签名每次构建签名都变，系统当成新程序 | `DEVELOPMENT_TEAM=<TeamID> make gen` 用固定身份签名；或者每次重新授权 |
| 权限被"系统策略限制（家长控制 / MDM）" | 设备管理策略禁了 | 找管理员，程序自己解不开 |
| 从终端 / 脚本起的 PlusMix 拿不到摄像头 | TCC 授权归启动它的进程（Terminal、IDE）所有 | 授权给 Terminal.app，或从 Finder / Dock 起 App |
| 第一次打开"允许局域网"或 tally 流时弹"允许传入连接" | macOS 防火墙开着 | 点允许；不然别的机器连不上 |

## 2. 无信号

noSignal 的格子只写"无信号"（纯音频输入写"等音频设备…"），下表按输入类型列常见原因；error 的格子写的是原因本身。

| 输入 | 格子上的文案 | 常见原因 / 怎么办 |
|---|---|---|
| 摄像头 / 采集卡 | "无信号" | 拔了；插回同一个设备自动恢复（≤ 3 s） |
| DeckLink | "无信号" | 驱动没装（装 Blackmagic Desktop Video，装好、插上卡自动好，不用重启），或线没插 / 卡不在（信号回来或卡插回自动好） |
| DeckLink | "DeckLink SDK 未编译进来：…后重新编译" | error：这份 App 编译时没有 DeckLink SDK，要换带 SDK 编的版本 |
| NDI® | "无信号" | 源还没上线、发送端没开、不在同一网段，或名字不对：名字要与发送端显示的 `机器名 (源名)` 一致，添加面板的 NDI® 页会每 4 s 重找一次；上线后自动接上 |
| NDI® | "NDI SDK 未编译进来：…后重新编译" | error：这份 App 编译时没有 NDI SDK；装 NDI SDK for Apple 到 `/Library/NDI SDK for Apple`（或设 `NDI_SDK_DIR`）后重新编译。添加面板的 NDI® 页这时写"找不了 NDI 源：…" |
| 视频文件 | "文件里没有视频轨：…" | 选的是纯音频文件（mp3 / wav / m4a / aac）：这一版的文件输入还要求有画面 |
| 视频文件 | "文件不存在：…" | 路径错；相对路径相对节目文件所在目录（[示例 › 相对路径](../../Samples/README.md#2-相对路径)）。文件放到位后要删掉这一路重新加，或重新打开节目 |
| 图片 | "图片不存在：…" | 同上；文件放到位后自己换上（每 0.25 s 看一次），不用重加 |
| 纯音频设备 | "等音频设备…" | 拔了；插回自动好；"系统默认输入"的路在系统换默认设备时自动重建 |
| 任何输入 | 画面有、但 60 fps 节目里看着像 30 fps | 摄像头协商到了 30 fps（它不支持 60；添加面板上那一行是黄的）：这是设计内的重复，不是丢帧 |

## 3. 磁盘

| 状态行 | 行为 |
|---|---|
| "录制 n：磁盘剩余 x MB" | 低于 1 GB 的提醒，还在录 |
| "录制 n：磁盘剩余 x MB，低于下限 200 MB" | 没设备用目录：只停这一路录制；推流、画面不受影响。改下限：设置 › 高级 › 磁盘下限（或启动参数 `--record-min-free-mb`） |
| "录制 n：磁盘满（…）" | 写满：保留已写片段，这一路停 |
| "录制 n：磁盘满，已切到备用目录：<文件名>" | 设了备用录制目录（设置 › 高级，或 `--record-fallback`）时，写满**或低于下限**都切过去继续录——低于下限时也是这句话，盘其实没满 |
| "录制 n 起不来：…" | 目录不可写 / 不存在；改好目录会自动重试 |
| "ISO 输入 n 不存在或分支用完（每路最多 4 个 ISO / Aux）" | ISO 录的那一路输入不在了，或那一路已经被 4 个 ISO 录制 / Aux（外部显示、NDI® 发送的单路来源）占满：减掉几个再录 |
| "录制 n 封口失败：…" | 停止时写索引失败；`.mov` 带片段，已写的部分仍可播 |
| 按底栏"录制"什么都没录，提示"没有参与录制的路" | 录制页里每一路的"参与录制"都关了，或 ISO 页 PGM 那一行取消了又没勾任何输入：勾上要录的路 |

录到外置盘 / 镜像时"剩余空间"按那个卷算。进程被强杀：`.mov` 恢复到最后一个 1 s 片段（E6 要求损失 ≤ 2 s）。

## 4. 推流

| 底栏 / 推流页 / API state | 意思 |
|---|---|
| "推流 · 连接中"、"连接中（第 n 次）"（API 的 `state` 在 `connecting` 和 `backoff` 之间来回，等下一次尝试时是 `backoff`） | 还没连上过：服务器不通、地址或路径不对。本机 MediaMTX 只收配置里写了的路径（仓库的 `scripts/mediamtx.yml` 只有 s1 / s2 / s3 / srt1，密钥要空），推到别的路径会一直连接中。开关开着时这一段锁着：先关掉开关再改地址 |
| "推流 · 重连中（第 n 次）"（`state` 同样在 `connecting` / `backoff` 之间来回） | 推上过、断线了：指数退避重连，一直重试；两次尝试之间最多等"重试间隔最长 n s"（默认 30 s）；恢复后第一帧关键帧 |
| "推流 · 1 路异常"（深红），悬停写"推流 n 起不来：…" / `failed` | 起不来：地址协议不认识（只认 rtmp / rtmps / srt）、地址格式不对、没有服务器。推流页那一段写着原因：改好地址（回车或离开输入框）会自动重试，或"停用这一路"；正常的路不受影响，点底栏主体只重试起不来的路 |
| "推流 n 没有地址" | 输出设置里地址为空 |
| 一直"连接中（第 n 次）"，状态窗的"最后错误"写"鉴权失败…"（系统日志里同一句） | 推流页"鉴权…"里的用户名 / 密码不对；这一版照样按退避一直重试。开关开着时这一段锁着：先关掉开关，改对再开 |
| 填了"鉴权…"，连接成功、一开始推就被拒（最后错误 / 日志里是 `NetStream.Publish.Unauthorized`） | 服务器（MediaMTX、SRS、nginx-rtmp 之类）要的是地址后面的查询串：关掉开关，"鉴权…"里"写法"改选"查询串（?user=&pass=）"、参数名按服务器的规矩填（[输出 › 推流鉴权](输出.md#推流鉴权)） |
| 最后错误 / 系统日志里有"鉴权方式不支持：…" | 服务器要的鉴权方式这一版不支持 |
| 想知道断过几次、什么时候断的、为什么 | [推流 / 录制状态窗](输出.md#推流--录制状态窗)：断线 / 重连两列是次数，下面的事件按时间列"断开：原因 → 重连中（第 n 次）→ 重连上" |
| SRT 设了 passphrase 推不上 | passphrase 只能用字母、数字和 `- . _ ~`，10–79 个字符 |
| 帧数在涨、播放端却没画面 | 看 `stats.encoder[].dropped`（网络丢帧）：带宽不够时先丢非关键帧；降码率（推流页"质量"选低一档），推流页底的"合计上行"不要超过上行带宽的一半 |
| 本机 MediaMTX 收不到 SRT | MediaMTX 的 SRT 端口要绑 IPv4（`srtAddress: 0.0.0.0:8890`，仓库里的 `scripts/mediamtx.yml` 已改）；RTMP 不受影响 |

## 5. NDI® 发送 / DeckLink / 虚拟摄像头没装好

| 症状 | 意思 |
|---|---|
| NDI® 发送页状态"不可用：没有 NDI SDK"、`state = unavailable` | 编译时没探测到 NDI SDK：输出不会真的发出去。装 SDK 后 `make clean && make build`（Xcode 会缓存清单里的探测结果） |
| `state = failed`，状态行有原因 | SDK 在但初始化 / 建实例失败：看原因（多半是别的程序占着 NDI® 运行时或名字冲突），改设置后重试 |
| 添加输入面板横幅"NDI® 运行库不在" / "这一版没带 DeckLink 支持" | 这份 App 编译时没带那个 SDK：照样能加，但那一路一直报错，要换带 SDK 编的版本（NDI® 横幅上"装好之后这一路会自己好"那句不成立）；"看说明"打开本手册的对应一节 |
| 添加输入面板横幅"DeckLink 驱动没装" | 照样能加，装好驱动、插上卡那一路自己恢复，不用重启 |
| 虚拟摄像头："失败：系统不允许安装：需要正式签名的版本，并从"应用程序"文件夹运行" | 开发构建激活不了系统扩展：按 [输出 › 虚拟摄像头](输出.md#5-虚拟摄像头) 的三步 |
| 虚拟摄像头："等待在「系统设置 → 隐私与安全性」里允许" | 系统弹了允许提示但还没点；macOS 15 起在 通用 › 登录项与扩展 |
| 虚拟摄像头："找不到虚拟摄像头设备（扩展未安装 / 未激活）；已丢 n 帧" | 输出开着、扩展没连上；每秒重试，激活后自动接上 |
| 系统设置里看不到扩展 / 激活后 FaceTime 里没有 "PlusMix" 摄像头 | 扩展必须嵌在 /Applications 里的 App 内；换过 bundle id / Team ID 要先"卸载扩展"再装 |

## 6. 画面与声音

| 症状 | 看什么 |
|---|---|
| 状态行"丢帧"（missed_render）在涨 | 渲染没赶上拍点。常见原因：别的程序占满 GPU、机器降频、多画面窗口被盖住时系统降低了刷新。空机器上正常是 0 |
| 长时间没人碰机器后开始掉帧 | 用户"空闲"时 macOS 会拖慢实时线程的唤醒。PlusMix 在引擎跑着时自己阻止系统睡眠、App Nap 和显示器休眠（设置 › 性能与电源，默认都开），平常不用再做什么。**无人值守、要合盖或锁屏的长跑**仍然另外跑 `caffeinate -u -i -d -s`：App 挡不住合盖和手动锁屏，也给不了 `-u` 那条"用户在用"的声明 |
| A/V 对不上 | 输入设置 › 音频 › 音频延迟补偿（0–500 ms）修采集设备自己的偏差；引擎内部的对齐延迟（默认 2048 帧 = 42.7 ms）在 设置 › 节目音频，改了要点"应用并重起引擎"才生效（会停掉录制 / 推流，先问） |
| 开了 Master 的压缩 / 限幅后，监视器、外部显示、多画面的画面整体晚了几十毫秒 | 正常（监听同步）：Master 的效果延迟有多少（5–35 ms），画面就延后多少，扬声器 / 耳机里的声音和画面对得上；录制 / 推流 / NDI® 同一条时间线。状态窗底部写"视频延后 n ms" |
| 开了 Bus A / B 的压缩 / 限幅后，送到设备的那两路比画面晚一点 | 画面只按 Master 的延迟延后；Bus A / B 自己多出来的那部分没有补（只影响这两路送到设备声道的声音） |
| 调了某一路的音频效果，听不出变化 | 每路的效果是生效的：看"启用"是不是关着（= 旁路）；**每路的"限幅器"不起作用**（只有总线装限幅）；同一路写了两个压缩只装第一个；用 API 写的均衡超过 16 段的不装 |
| 切走了声音还在 / 切上了没声音 | 先看调音台头部的 AFV 总开关：**新节目默认关着**，关着时每一路的"跟随视频"都不起作用。总开关开着时看那一路的"跟随视频"：关着 = 一直出声；开着 = 只在 PGM 上出声 |
| 耳机里听到的是 Master，各路"送 H"的声音听不到 | 这一版耳机出口平时放 Master，调音台里有独听时才放耳机总线（独听的那几路）；监听菜单（Master 条的耳机图标）还没接上，Master / Bus A / B 灰着 |
| 独听时耳机里听到的比画面早 | 独听的监听点默认在对齐延迟线之前（低延迟）；要与画面对齐，设置 › 节目音频 › 耳机监听点 选"延迟线后"，点"应用并重起引擎"后生效 |
| 独听 / PFL / AFL 听不到，调音台头部写"当前设备没有耳机声道" | 输出设备只有 2 个声道、都给了 Master：设置 › 音频设备 打开"监听时临时占用 Master 声道"（独听时扬声器 / 耳机里放独听的那几路，当场生效）；或换一台多声道设备，给耳机分一对声道 |
| Bus A / B 没有声音出来 | 设置 › 音频设备 里给 Bus A / B 选一对声道（要多声道设备），应用并重起引擎 |
| 提醒"Master 电平持续 30 秒低于 −50 dBFS（话筒开了吗？）" | 看话筒那一路是不是静音、推子、送没送 Master、跟随视频是不是把它关在外面了 |
| 音频设备起不来："音频设备「…」建不起来（…），退到空设备" | 设备被拔 / 被别的程序独占：设置 › 音频设备 重新选；空设备下画面照常、录制 / 推流照常有声音（只是本机不出声） |

## 7. 界面

| 症状 | 意思 |
|---|---|
| 主窗口里点什么都没反应，状态行写"界面已锁定" | 界面锁开着：点底栏最右的锁，或 窗口 › 锁定界面。快捷键、菜单栏照常 |
| 格子上的"转场 / Cut"是灰的，点缩略图没反应 | 转场正在进行（T-bar 推到一半也算）：等它做完；或者这一路已经在 PGM 上 |
| 按快捷键没反应 | 统计窗、推流 / 录制状态窗、多画面窗口在前时快捷键不派发：点一下主窗口再按（设置窗、输入 / 叠加 / 音频设置窗在前时照常） |
| 点"转场 4"不切，弹出一个输入列表 | 这个槽是 Stinger、还没选输入：从弹出的列表里选一路（只改这个槽），再点一次才执行（[概念 › 转场列](概念.md#转场列)） |
| T-bar 推到头松手又弹回去了 | 正常：过 97% 松手就提交（PGM / PVW 对调），T-bar 回到最左等下一次；没过 97% 松手才停在原位 |
| ⌥1–⌥4 都只是"执行当前转场"，不分槽 | 这台机器存过旧的快捷键表：设置 › 快捷键 › 恢复默认表 |
| 关掉主窗口弹出"要保存…"或"退出会停止…" | 关主窗口 = 退出 PlusMix，和 ⌘Q 一样先问 |
| 帮助 › PlusMix 使用手册 是灰的，写"手册尚未随包" | 这份构建的包里没有 `Resources/Help/`：多半是 Xcode 工程是加随包手册之前生成的，`make gen` 后重新编译；手册原文在仓库的 `docs/user/` |

## 8. API 与控制面板

| 症状 | 意思 |
|---|---|
| "API 起不来（127.0.0.1:8765）：…" | 端口被占（上一个 PlusMix / headless 没退干净）：`lsof -i :8765` 看是谁；设置 › 远程控制 换端口 |
| curl 返回 401 | 设置 › 远程控制 里设了 token：请求带 `Authorization: Bearer <token>`（WebSocket 也可用 `?token=`） |
| 命令返回 200 但 `applied = false` | 状态机按规则忽略了（转场进行中再发转场、**转场进行中改 PVW / PGM**、已是目标状态），不是错误 |
| 返回 400 | 命令结构错 / 引用不存在的输入 / 输出编号；正文里有原因 |
| 别的机器上的控制面板 / Companion 连不上 | 默认只听本机：设置 › 远程控制 把本地 API 或兼容层改成"允许局域网"，应用并重起引擎，用页上显示的地址；防火墙问"允许传入连接"时点允许 |
| tally 灯连不上 | 设置 › Tally 打开只读 tally 流（默认关），用页上的地址；"tally 流起不来"多半是端口被占，换一个 |
| Stream Deck 按钮灰色"未连接" | API 没开、地址端口不对、token 不对；插件日志在 `~/Library/Logs/ElgatoStreamDeck/` |

## 9. 日志与诊断

- 帮助 › 导出诊断包…：设置（不含 API token）、最近一秒的统计、去掉推流密钥的节目文件、快捷键 / MIDI 表、系统信息，经你同意再加崩溃诊断和最近两小时的日志；存到保存框里选的位置，导出完在 Finder 里选中它，可以先自己打开检查再发出。帮助 › 打开诊断文件夹 打开的是 `~/Library/Application Support/PlusMix/Diagnostics`，里面是系统交来的崩溃 / 卡死等诊断记录（`crash-….json`、`hang-….json` 等，只留最近 100 份），不是导出的包；推流 / 录制状态窗的"显示日志…"打开的也是它（推流 / 录制的日志不在里面，看下一条的系统日志）。
- 引擎发出的提示（录制、推流、NDI® 发送、外部显示、虚拟摄像头这类）同时写进系统日志；底栏自己弹的提示（例如"没有参与录制的路"、"转场进行中…"）不写。看最近 10 分钟（写全路径 `/usr/bin/log`：终端里直接敲 `log` 也行，但在脚本或非交互的 zsh 里 `log` 是 zsh 自带的同名命令，会报"too many arguments"）：

```bash
/usr/bin/log show --predicate 'process == "PlusMix"' --last 10m --style compact
```

- 每秒一行的统计（`stats.jsonl`，字段见 [测试标准 §7](../testing/测试标准.md#71-统计字段-statsjsonl)）：启动参数 `--stats <文件>`，或从 API `GET /api/v1/state` 的 `stats` 读；统计窗里看的是同一份。报问题时附上它。
- 复现问题用无界面引擎更省事：`switcher-headless run --show <节目> --duration 60 --stats /tmp/stats.jsonl`（[示例](../../Samples/README.md#1-打开)）。
