# 输出

输出菜单里六个设置页各管一种输出；底栏的"录制 / ISO… / 推流 / 外部输出 / 多画面"是它们的快捷入口。
每个输出有编号、名字、"应该在跑"的开关和自己的设置；运行中的帧数 / 码率 / 丢帧只在状态行和 API 的 `stats` 里，不存进节目文件。

| 种类 | 送什么 | 开关怎么起 |
|---|---|---|
| 录制 | PGM，或某一路输入（ISO） | 底栏"录制"一起起停；快捷键 / API `startRecord` |
| 推流 | PGM | 底栏"推流"；`startStream` |
| NDI 发送 | PGM / PVW / 多画面 / 某一路输入 | NDI 页的"发送"开关；`setOutputEnabled` |
| 外部显示 | PGM / PVW / 多画面 / 某一路输入（Aux） | 外部输出菜单 / 页；`setOutputEnabled` |
| 虚拟摄像头 | **PGM** | 输出 › 虚拟摄像头 › 启用；`setOutputEnabled` |
| 多画面 | 多画面画面（给下游用） | 多画面页 / `setOutputEnabled`；布局与开关无关 |

## 1. 录制

输出 › 录制设置…。默认目录 `~/Movies/Switcher`，节目文件里写相对目录时挂在它下面。

| 项 | 说明 |
|---|---|
| 目录、文件名模板 | 模板支持 `{show}` `{date}` `{time}` `{output}`；默认 `{show}-{date}-{time}` |
| 容器 | `.mov`（默认，每 1 s 一个片段，进程被杀也能恢复到最后一个片段）或 `.mp4`；"停止后转封装成 MP4"失败时保留 .mov |
| 视频 | H.264 / HEVC / ProRes 422 / 422 HQ / 4444（硬件编码），码率、关键帧间隔、尺寸（默认 = 节目） |
| 音频 | AAC（默认 160 kbps）或 PCM；音频 = Master 总线 |

- 编码 PTS 用拍点时刻，录制文件的时长与"拍数 × 帧时长"一致（[测试标准](../testing/测试标准.md) E5）；正常停止 20 次、录制中强杀 10 次都有自动测试。
- 一个节目里可以有多路录制输出（例如 PGM 一份 H.264、一份 ProRes），底栏按钮一起起停，起点是同一拍。

### ISO 分路

输出 › ISO 分路录制…（或底栏"ISO…"）：勾选的输入各录一个文件（来源 = 该输入的原始画面，编码 / 目录抄 PGM 录制输出，文件名模板自动带 `{output}`）。

- 与 PGM 同一拍起停、共用起点，所以各文件同一事件的时间差实测 0.0–0.2 ms（[测试标准](../testing/测试标准.md) A4 要求 ≤ 1 帧）。
- ISO 文件的音轨 = 该路推子后、AFV 之前的声音（切走了也照录）。
- 30 fps 的输入录成 60 fps 节目时每帧重复一次，与 PGM 同一网格。
- 每路输入最多 4 个分支（ISO / Aux 窗口 / NDI 输入源共用），用完会提示。
- 页面上显示录制目录、剩余空间和"还能录多久"（按所有录制输出码率之和估）。

### 磁盘保护

每秒看一次每路录制的剩余空间（外置盘 / 镜像也算对）：

| 情况 | 行为 |
|---|---|
| 剩余低于 1 GB | 状态行提示"录制 n：磁盘剩余 x MB" |
| 剩余低于下限（默认 200 MB，偏好设置 / 启动参数 `--record-min-free-mb` 可改） | **只停这一路录制**，提示"低于下限"；推流、画面、别的录制不受影响 |
| 写满 / 写入失败 | 这一路停并保留已写片段；设了备用目录（`--record-fallback`）就在下一拍切到备用目录继续录 |

测过的场景：录到 50 MB 的小镜像、两路 40 Mbps 同时写满（[测试标准](../testing/测试标准.md) S7）。

## 2. 推流

输出 › 推流设置…：每个目的地一路输出，独立编码、独立重连。

| 项 | 说明 |
|---|---|
| 地址 | `rtmp://host/app`、`rtmps://host/app`、`srt://host:port?streamid=…&passphrase=…&latency=…`；协议由地址决定 |
| 密钥 | RTMP 拼在地址后面作流名；SRT 没写 `streamid` 时补成 `streamid=密钥` |
| 视频 / 音频 | 同录制（平台一般要 H.264 + AAC，关键帧间隔 2 s = 60 帧 @30 / 120 帧 @60） |
| 重连 | 断线后指数退避自动重连，上限默认 30 s；重连后第一帧是关键帧 |

- 多路推流互不影响：一路断网，其他路丢帧 0（E7）；断网 30 s 恢复后 10 次全部重连成功、≤ 15 s（E8）；带宽不够时的"网络丢帧"计数与真实丢帧差 ≤ 5%（E9）。这些都在本地 MediaMTX + 网络损伤下自动测。
- 状态行显示"推流 · 重连中（第 n 次）"之类；API `stats.encoder[]` 里 `state` 是 idle / connecting / publishing / backoff / stopping / stopped / failed。
- 本机先试：`mediamtx scripts/mediamtx.yml`，地址 `rtmp://127.0.0.1:1935/live`、密钥随意，`ffplay rtmp://127.0.0.1:1935/live/<密钥>` 看（[示例 › 直播](../../Samples/README.md#4-直播先在本机试)）。RTMP 与 SRT 在本项目里端到端测过；RTMPS 走同一条路，只是加了 TLS。

## 3. NDI 发送

输出 › NDI 发送…：每路发送一个输出，源名就是输出的名字，网络上显示为 **`机器名 (输出名)`**。

| 项 | 说明 |
|---|---|
| 来源 | PGM / PVW / 多画面 / 某一路输入（Aux，原始画面）。PVW / 多画面按需多出一路画面，开头可能缺一两帧 |
| 分组 | NDI 分组名（逗号分隔），空 = 默认组 `public`。接收端按分组过滤 |
| 转换 | NV12 → UYVY 的转换用 GPU / CPU / 自动（自动 = 定期比一次，哪个省用哪个） |
| 音频 | PGM / PVW / 多画面送 Master；某路输入送该路推子后的声音 |

- 改名 / 改来源 / 改分组会重建发送端（接收方要重新选源），转换方式随时切。
- **SDK 不在**（编译时没探测到 NDI SDK for Apple）：输出能加、能开，但不会真的发出去；状态显示"不可用（没有 NDI SDK / 初始化失败）"，API `stats.encoder[]` 里这一项 `state = "unavailable"`。
- SDK 在但起不来（初始化 / 建实例失败）：`state = "failed"`，状态行有原因；改设置后会重试。
- `stats.encoder[]` 的 `connections` 是当前接收方数，`bitrate` 是 UYVY 原始码率（1080p60 约 2 Gb/s，这是正常的）。

## 4. 外部输出（第二块显示器）

输出 › 外部输出…，或底栏"外部输出"（显示器 × 来源的菜单）。一路外部输出 = 一块显示器上的无边框全屏窗口。

- 来源：PGM / PVW / 多画面 / 某一路输入（Aux，全分辨率原始画面）。
- 显示器不在时：默认黑着等它回来、不动主屏；"显示器不在时退回主屏"会在主屏全屏（盖住操作界面），只在明确要的时候开。
- 画面由显示器自己的刷新节拍取最新帧，拖动主窗口、进出全屏都不影响渲染线程（丢帧计数不增）。Esc 关闭窗口。
- 节目文件保存显示器 ID 和来源，重新打开时恢复；显示器 ID 重启后可能变，换了就重选一次。

## 5. 虚拟摄像头

输出 › 虚拟摄像头：让 FaceTime、QuickTime、浏览器会议等把 Switcher 当成一台摄像头。**送的是 PGM**（不可选来源）。

安装（一次）：

1. 用带 Team ID 的签名构建（`DEVELOPMENT_TEAM=<TeamID> make gen build-app`），把 Switcher.app 放进 `/Applications` 再启动——系统扩展只能从 /Applications 里的 App 激活。
2. 输出 › 虚拟摄像头 › 安装 / 激活扩展…，然后到 系统设置 › 通用 › 登录项与扩展（旧版本在"隐私与安全性"）里允许。菜单里"查询扩展状态"能看当前状态。
3. 输出 › 虚拟摄像头 › 启用 / 停用虚拟摄像头输出。在 FaceTime / QuickTime 新建影片录制里选 "Switcher" 摄像头。

- 开发构建（没有 Team ID、ad-hoc 签名）激活会失败，状态显示"签名 / 权限 / 位置不满足，要带 Team ID 签名、从 /Applications 运行（BLOCKED-签名）"，App 不崩。
- 输出开着但扩展没连上：状态"找不到虚拟摄像头设备（扩展未安装 / 未激活）；已丢 n 帧"，每秒重试；连上后自动发。关掉输出后对方看到占位画面（深灰 + 移动白条）。
- 帧率跟节目，1080p NV12；从 PGM 到对方进程 ≤ 3 帧是设计目标（签名机器上验证）。

## 6. 多画面

输出 › 多画面布局…；窗口 › 多画面窗口（或底栏"多画面"）开独立窗口，可拖到任何屏、全屏。

| 项 | 说明 |
|---|---|
| 预设 | `pgmPvw+grid`（默认：上 PVW / PGM，下半按路数 4×2 / 6×3 / 8×4）、`pgmPvw+4x2`、`pgmPvw+2x2`、`3x3`、`4x4` |
| 自定义 | 每格一个来源（PGM / PVW / 输入 n）+ 位置尺寸，非空时代替预设 |
| 安全框 | PGM / PVW 格画 EBU R95 动作安全 3.5% / 字幕安全 5% |
| 电平表 | 输入格画该路的表，PGM 格 = Master、PVW 格 = 当前 PVW 那一路；读数就是状态行 / API 那一份 |

- 每格有 tally 边框（红 PGM / 绿 PVW）和名字标签；纯音频输入的格子画名字 + 电平表。
- 布局存在节目文件里（第一个多画面输出的设置），对多画面窗口、缩略图条、外部输出 / NDI 的"多画面"来源都生效。
- 多画面输出的"开关"只决定要不要把多画面画面送给下游（NDI / 外部输出），布局与它无关，只承载布局的那一个可以一直关着。
