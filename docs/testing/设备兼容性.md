# 设备兼容性

Switcher 团队自己测不过来所有的采集卡、摄像头、音频接口和显示器；这张表靠使用者提交。每一行 = 一台设备在一个 Switcher 版本 + 一个 macOS 版本上跑过的结果。
提交方式：复制 §3 的模板填好，作为 Pull Request 加到 §2 对应的表里（或开一个 issue 贴上来）。写清楚**怎么测的**比结论重要。

## 1. 通过项的定义

每一列对应 [测试标准](测试标准.md) 里的一个指标或人工检查；填 ✅ / ❌ / —（没测）。

| 列 | 怎么判 |
|---|---|
| 枚举 | 添加输入面板里能列出来（名字 / 型号正确） |
| 出画面 | 添加后 ≤ 5 s 出画面，分辨率 / 帧率与设备标称一致 |
| 音频 | 设备自带的音频（摄像头麦克风、SDI 内嵌、音频接口的输入声道）能进调音台、电平表有读数 |
| 热插拔（S5） | 拔掉 → 格子"无信号"、不崩；插回 ≤ 3 s 自动恢复、编号与设置不变（20 次） |
| L1 / L2 | 内部延迟 ≤ 3 帧；端到端（扣除设备自身）≤ 3 帧，含设备的总值按类型：UVC ≤ 150 ms、SDI ≤ 100 ms、NDI ≤ 160 ms、屏幕 ≤ 80 ms。测法见测试标准 §3 |
| A2 | 该路的 A/V 偏移（闪光 / 拍手 vs 声音）≤ 1 帧；写实测值和用了多少延迟补偿 |
| 长跑 | 连续 1 小时以上无断流、无掉帧增长 |

## 3. 提交模板

复制一行，`—` 表示没测：

```
| <设备型号> | <固件 / 驱动版本> | <接口 USB-C / HDMI / SDI / Thunderbolt / Wi-Fi> | <分辨率@帧率、像素格式> | <macOS 版本> | <Switcher 版本或提交号> | 枚举 | 出画面 | 音频 | 热插拔 | L1 / L2（数值） | A2（数值，延迟补偿 ms） | 长跑（时长） | 备注 / 提交人 |
```

备注里写：机型（M1 Air / M2 mini …）、节目格式、怎么测的（用了哪条测试标准的方法）、遇到的坑（要不要装驱动、协商到了什么格式、需要多少延迟补偿）。
不要提交推流密钥、序列号之类的隐私信息。
