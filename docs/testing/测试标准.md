# PlusMix 测试标准（公开版）

这是 PlusMix 用来判断"能不能发布"的标准：每个指标有定义、测法、阈值和报告口径，缺一个就不算指标。内部版本（含修订记录与各会话的口径讨论）是
[docs/spec/导播台测试标准.md](../spec/导播台测试标准.md) v0.1，本版阈值与它逐条相同，只去掉了内部引用。

## 0. 原则

1. 直播软件的质量只有三件事：不掉帧、不失步、不崩。所有指标都围绕这三件事。
2. 每个指标四要素齐全：定义、测法、阈值、报告口径。
3. 能自动测的绝不手测。为此引擎有无界面模式和内置合成测试源。
4. 性能有基线。每个版本和上一个版本比，退步就阻塞。
5. 阈值分两档：**必须**（发布门槛）和**目标**（努力方向）。
6. 符号约定：A/V 偏移以音频为准，音频超前为正、滞后为负（ITU-R BT.1359）。

## 1. 指标定义

编号：V 视频、A 音频、E 编码 / 录制 / 推流、L 延迟、S 稳定性与资源、C 控制接口。

### V 系列：视频

| 编号 | 名称 | 定义 | 单位 |
|---|---|---|---|
| V1 | 渲染耗时 | 一拍开始到该拍命令缓冲区在 GPU 上完成的时间；报平均值和 p99 | ms |
| V2 | 渲染滞后丢帧 | 下一拍到期时上一帧尚未提交而被跳过的拍数；报计数和占总拍数的比例 | 帧、% |
| V3 | 输出帧间隔抖动 | PGM 帧派发时刻与理想拍点之差；报 p99 和最大值 | ms |
| V4 | 输入帧重复 / 丢弃率 | 每路输入：同一输入帧被合成两次以上的比例；输入帧到达但从未被合成的比例。区分"设计内"（30 fps 进 60 fps 节目必然重复）和"设计外" | % |
| V5 | 帧计数一致性 | 长跑后输出总帧数与"时长 × 帧率"的差 | 帧 |
| V6 | 切换准确性 | 切换命令指定在第 n 拍生效，输出里新输入出现的第一帧是否恰好是第 n 拍；Cut 时不得出现任何混合帧 | 帧 |
| V7 | 转场进度精度 | Fade 时实际混合比例对时间的曲线与设定曲线之差；T-bar 位置到混合比例的映射误差 | 帧、% |
| V8 | 画面正确性 | 给定状态和输入图，离线渲染结果与参考图的差异（叠加顺序、位置、抠像、缩放） | PSNR dB / SSIM |
| V9 | 色彩正确性 | 灰阶和色条经"输入 → 合成 → NV12 → 编码（无损或 ProRes）"往返后的电平误差；BT.709 限制范围（16–235）不得被拉伸或压缩 | 8-bit 电平 |

| 编号 | 名称 | 定义 | 单位 |

## 2. 测试信号与工装

它们是产品的一部分，不是测试脚本的附属：没有它们，上面的指标大部分测不了。

### 2.1 合成视频源

引擎内置的输入类型（[用户手册 › 输入](../user/输入.md#合成测试源)）。每帧烧入：

- **帧号**：16 个 32×32 的黑白方块（二进制，带 4 位校验），压缩后仍能可靠读出。
- **输入 ID**：一个固定颜色块，每路输入不同颜色（16 色调色板）。解码按"离最近调色板色 ≤ 24"判，frameprobe 的自证解码再收紧到 12：
  调色板由 0 / 128 / 255 三档分量拼出，两色 50% 混合有五对会撞上第三种颜色，所以转场混合帧**不能只看 ID 块**，还要靠底色一致与码字块电平纯度两票独立判据。
- **保护带**：帧号行、时间戳行、ID 块、闪光块、中心采样区（宽高各 1/4）以及 ID 块下方一条背景带（1080p 上 x ∈ [16, 272]、y ∈ [192, 224]）归解码用；
  测试用的节目文件里叠加、Stinger 图案、边框一律不许占用图案区以下、0.22 倍高以上这条横带。
- **时间戳**：生成时的 host time，同样二进制块。
- **闪光帧**：每秒第 0 帧右上角一个 64×64 全白块，其余帧全黑。用于 A/V 偏移。
- 可配置：帧率（30 / 59.94 / 60）、人为抖动、人为丢帧、人为时钟漂移（±100 ppm）。
- 到达相位：合成源的帧比其 pts 提前半个节目帧到达引擎（headless `--input-lead-ms` 默认 = 半帧），音频块不提前。
- 底纹：灰底（V6 / V7 用 64 / 192）或灰底 + 零均值噪声 `noise(level, amplitude, seed)`；E2 要噪声底纹才有可判对象（纯灰底压不出设定码率），检查点场景用噪声（振幅 24）。
- 引擎的到达余量（挑帧规则的实现参数）检查点一律用默认值：估计器窗口 8 块 × 1 s，热身 1 块；初值 = max(下限, 第一帧到达延迟 + 保护带)，保护带 = 1 ms + 15% × 可覆盖抖动跨度；
  单次上调 ≤ 一个节目帧；上限 = 窗口最小到达延迟 + 一个节目帧 + 保护带；绝对上限 500 ms。

### 2.2 合成音频源

- 1 kHz 正弦 −20 dBFS，每秒和闪光帧同一时刻叠加一个 1 ms 的 click。
- 可配置采样率漂移（±100 ppm），模拟不同设备时钟。

### 2.3 frameprobe（分析工具）

`Tools/frameprobe`：读输出文件或抓下来的流，逐帧解出帧号、输入 ID、闪光；解音轨找 click。输出 JSON / Markdown：

- 丢帧、重复帧的序列和统计（V4、V5）。
- 每次切换在第几帧生效、有无混合帧（V6）。
- Fade 期间逐帧的混合比例（V7；输入 A 灰度 64、输入 B 灰度 192，比例可直接算出）。
- 每个闪光帧对应的 click 时间差序列（A2、A3、A4）。
- **整秒拍**：闪光帧的节目拍号是标称整数帧率的倍数（60 fps 节目 = 整秒；59.94 = 每 1.001 s）才算"整秒配对"；A2 / A3 只用整秒配对判定，其余只报不判。不从第 0 拍起的文件要给 `--start-tick`。
- **拍号按 PTS 算，漏帧单独报**：文件里漏了帧时，后面的帧不往前挪。
  - `switches` / `fade`（V6 / V7 的 Cut 与 Fade）：拍号 = `--start-tick` + round((pts − 第一帧 pts) × fps)。fps 只认 `--fps`；没给时按相邻帧的 pts 差估（不用容器的标称帧率——它是"样本数 / 时长"，漏了帧就偏低，长文件里会把转场落点挪后几拍）。
    漏掉的拍单独列：报告里的 `missingFrames`（拍号列表）/ `missingFrameCount`；每条切换的 `missingBetween` = 旧输入最后一帧与新输入第一帧之间漏的拍数（没漏不写）——Cut 紧挨着的前一拍漏了时，落点只能确定在这一段里，标出来、不改判；Fade 窗口里漏的拍没有样本，不进曲线偏差。
  - `av` 的闪光拍号用同一个式子，但没给 `--fps` 时 fps 取容器标称帧率；`wipe` / `zoom` 的拍号 = `--start-tick` + round(pts × fps)（与剖面窗口、`--blank-ticks` 同一个式子），窗口里漏的帧同样列出，没给 `--fps` 时也用标称帧率。`stats` 的 V5 期望帧数在没给 `--fps` 时同样按标称帧率算（会把漏帧藏掉）。
    所以 **`av` / `wipe` / `zoom` / `stats` 量漏了帧的文件要给 `--fps`**（gate 脚本里这几步都给了）。
  - 第一帧 pts = 0 时两组式子一样（录制文件都是）；没漏帧时输出与以前逐字段相同（新字段都是可选的）。
- **多文件 A4**（`av` 带多个文件，gate4 里 PGM + ISO）：click 以传入的**第一个**文件（PGM）配到的那个为锚，其他文件取离锚最近的 click（±0.5 s 内）；闪光离锚 click 落在半秒 ±1 帧内的事件（59.94 段的已知平局）只列不判。
  **判定事件里有文件缺 click、或缺这个事件的闪光，A4 不过**（`passA4 = false`；`missingClickFiles` / `missingFlashFiles` 列出是哪几个文件，`missingClickEventCount` / `missingFlashEventCount` 计数）；一个文件都没配上 click 的事件（没有锚，例如从第 0 拍起录的文件的第 0 s）不算缺，只比闪光，另计 `unanchoredEventCount`。
  `maxClickSpreadMs` / `maxFlashSpreadMs` 只在判定事件、只在有值的文件之间算（缺的那一格不进极差），所以判 A4 要同时看 `passA4`——gate 脚本就是这么判的；全部事件的极差另给 `allEventsMaxClickSpreadMs` / `allEventsMaxFlashSpreadMs`。
- **音轨时间轴**：录制文件按编辑列表（AVFoundation 口径）；推流落盘文件（无编辑列表的分片 MP4）按 ffmpeg 口径——音轨起点 = 容器 tfdt 偏移 + 加回 AAC priming（`--aac-priming auto`），报告同时给两种口径。
- **不连续检测**（`av --discontinuities`）：相邻样本跳变 > 0.5 满幅，落在已知 click 位置 ±1 ms 内的排除。这是 A1 第三项的正式离线口径；stats.jsonl 的 `audio.discontinuities` 是流式启发式，只作信息项。
- **自证解码**（默认开）：帧号行、时间戳行、ID 块、底色、节奏互相印证，转场合成帧被判成"解不出"而不是错号；`--no-self-check` 关。

### 2.4 无界面模式

```bash
switcher-headless run --show show.json --script scenario.json --duration 3600 --stats stats.jsonl
```

- 按脚本在指定拍点发命令（切换、转场、叠加、开关录制推流）。场景格式 `{durationTicks, events: [{tick, command}]}`，命令 JSON 与 API 相同。
- 每秒一行统计写进 stats.jsonl：V1、V2、V3、E1、E2、A1、内存、CPU、GPU。这份 stats 和 UI 状态行、API 是同一个结构（§7.1）。

### 2.5 回环采集

Mac 的外部显示输出 → HDMI 采集卡 → 回到本机另一路输入或另一台 Mac。用于 L2 和显示路径验证。

### 2.6 网络损伤

- macOS 自带 dnctl + pfctl（dummynet）做限速、丢包、延迟（`scripts/netem.sh`）；更稳的做法是一台 Linux 路由器跑 tc netem。
- 本地推流服务器用 MediaMTX（MIT），能收 RTMP / SRT 并落盘，落盘文件交给 frameprobe。

### 2.7 设备矩阵（最小集合）

| 类别 | 至少 |
|---|---|
| 机器 | 1 台无风扇笔记本（M1 Air，8 GB）+ 1 台 Mac mini / Studio（目标机） |
| macOS | 当前版本和上一个大版本 |
| UVC 采集卡 | 1 种主流型号 |

| 音频接口 | 1 台 USB 接口 + 一个聚合设备 |

### 2.8 性能采集

- 引擎内所有阶段打 os_signpost；用 `xctrace record --template 'Metal System Trace'` 抓；Instruments 的 Allocations / Leaks 跑 S2。
- 环境固定：接电源、关低电量模式、记录机型和 macOS 版本、关闭其它占 GPU 的程序。

### 2.9 实时线程检查

- 调试构建里给音频回调加断言（进入回调时置标志，锁、分配、日志的封装函数检查标志）。
- 有条件的话用 clang 的 RealtimeSanitizer（`-fsanitize=realtime`），把带 `[[clang::nonblocking]]` 标记的函数里的违规直接报出来。`scripts/check-rt-symbols.sh` 静态检查热路径目标文件里不许出现的符号。

## 3. 测试方法

"标准负载"指 1080p60 八路合成源场景（帧率混用 30 / 59.94 / 60，带抠像与叠加），除非另有说明。

| 指标 | 做法 |
|---|---|
| V1–V3、V5 | 无界面模式跑 1 小时，读 stats.jsonl；同时录一份文件交 frameprobe 数总帧数和缺口。V3 用 stats.jsonl 的 `jitter_ms`（渲染线程唤醒时刻 − 理想拍点，每秒窗口最大值），p99 取各秒最大值（比逐帧 p99 严） |
| V4 | 同上，frameprobe 按输入 ID 统计每路的重复和丢弃；设计内的期望按精确速率核算：在播 K 帧、输入帧率 r、节目帧率 P → 设计内 dup / drop 期望 = K·\|1 − r/P\|，允许 +1 帧相位余量（每个连续在播段各算一次），超出的算设计外。frameprobe 只统计有单一输入身份的帧：Fade / Wipe / Zoom / Stinger 的中间拍不计入；引擎侧 stats.jsonl 的 dup / drop 全程照算，两个口径都要满足 |
| V6 | 脚本在第 1000 拍 Cut、第 3000 拍 Fade（30 帧）；frameprobe 找新输入 ID 出现的第一帧；Cut 前后不得有混合帧。"Cut"= 新 ID 紧接旧 ID 出现（中间没有解不出身份的帧）的切换；Wipe / Zoom / Stinger 的中间拍不参与"所有 Cut 干净"的判定 |
| V7 | 输入 A 灰度 64、输入 B 灰度 192，Fade 30 帧；frameprobe 逐帧算混合比例，与线性曲线比；T-bar 用脚本推到 25 / 50 / 75%，读混合比例 |
| V8 | 离线渲染：固定状态（叠加开、画中画在右下、抠像开、五种转场中点、多画面各预设）+ 固定输入图 → PNG；和参考图比 PSNR / SSIM。参考图有意更新时必须说明原因 |
| V9 | 灰阶（0–255 步进 8）和 75% 色条做输入，录 ProRes 或无损，ffmpeg 取像素值比对 |
| A1 | 8 小时长稳期间统计回调超时和欠载；同时对录制文件做波形不连续检测（§2.3 的离线口径） |
| A2 | 录制标准负载 10 分钟，frameprobe 找每个闪光帧和对应 click；分别对录制文件、NDI 输出（用 NDI 录制器抓）、回环采集的外部显示各测一次。只取整秒配对，判最大绝对值，均值 / 标准差同时报；推流落盘文件按 ffmpeg 口径 |
| A3 | 8 小时录制，对 A2 序列做线性拟合，斜率 × 8 h |
| A4 | ISO 分路录 4 路，每路各自含闪光和 click；比较各文件同一事件的时间 |
| A5 | 耳机输出用线回环到音频接口输入，发 click，测往返再除以二；或用专门的往返延迟工具 |
| A6 | EBU Tech 3341 / 3342 的测试文件通过文件输入播放，读表，和标称值比 |
| A7 | 调试构建 + 断言 / RealtimeSanitizer 跑标准负载 10 分钟，违规数必须为 0 |
| E1 | 标准负载 + 3 路编码，读 stats；再故意把编码器压到极限（4K + 3 路）确认计数正确增长而渲染不受影响 |
| E2、E3 | 录制文件或 MediaMTX 落盘文件用 `ffprobe -show_packets` 算码率窗口和关键帧间隔 |
| E4 | 固定测试片段（自有素材，含静态、慢动、高动态三段）经文件输入编码录制，ffmpeg libvmaf 对源算分；结果存入基线表 |
| E5 | 正常停止录制 20 次（各种时长），每个文件 ffprobe；时长与脚本时长比 |
| E6 | 录制中随机时刻 kill -9，重复 10 次；ffprobe 每个文件，比较可播放时长与实际录制时长 |
| E7、E8 | 3 路推到 MediaMTX 的三个端口；用 dummynet 封其中一个端口 30 秒后放开；看其他两路丢帧、看被封那路是否重连、重连后录一段交 frameprobe 测 A2 |
| E9 | dummynet 把带宽限到设定码率的 70%，跑 5 分钟；软件报告的网络丢帧和 MediaMTX 落盘文件的缺帧数比 |
| L1 | 合成源帧里有生成时间戳，编码器入口再打一次戳，差值就是 L1；换真实设备时用回环抓设备输出帧里的时间信息 |
| L2 | 两种方法任选：手机显示毫秒秒表，摄像头拍它，外部显示输出 PGM，用 1/1000 s 快门同时拍下秒表和显示器，读差；或回环采集 + 合成源帧号。每种输入 10 次取中位数；另测设备直连显示器作扣除参考 |
| L3 | 编码器输出时刻和抓包时刻（tcpdump）比 |
| S1 | 8 小时脚本：每 30 秒切换一次、每 5 分钟开关一次叠加、2 路推流 + 1 路录制 + NDI 全程开；读 stats 检查每个 5 分钟窗口 |
| S2 | 长稳期间每分钟采一次 RSS，预热 30 分钟后线性拟合 |
| S3 | 长稳期间的 CPU（进程级）和 GPU 平均和 p95；GPU 用 IOKit 的 `Device Utilization %`（与 powermetrics 同一计数器、不需要 root） |
| S4 | M1 Air 跑标准负载 1 小时，powermetrics 记频率；对照 V2 |
| S5 | 拔插 UVC 采集卡和 USB 摄像头各 20 次（可用支持软件断电的 USB hub 自动化）；记崩溃、恢复时间、编号设置 |
| S6 | 系统设置里逐个撤销权限再启动；授权后不重启看能否恢复 |
| S7 | 录到一个快满的小分区；录到一个被限速的外置盘 |
| C1 | WebSocket 客户端在已知时刻发 cut，PGM 帧号给出生效拍点；差值 |
| C2 | 客户端记录收到状态快照的时刻和该状态对应的拍点时刻 |
| C3 | 长稳期间每次切换后，比对 API 的 tally 和 frameprobe 解出的输入 ID |
| C4 | 脚本每秒发 100 条带序号的命令，检查状态里的最终序号和顺序 |
| C5 | Companion 配一页按钮对着兼容层端口，逐个按，看 PGM 和按钮 tally 反馈 |

### 7.1 统计字段 stats.jsonl

每行一个 JSON 对象，UI 状态行、API、测试三方共用这个结构，不允许各自另算。字段的权威定义在 [docs/CONTRACTS.md §2.7](../CONTRACTS.md)，
用户视角的摘要表在 [API 文档 §5](../api/README.md#5-stats每秒一行的统计)。

```
ts, tick, render_ms, missed_render, jitter_ms,
per_input{n: {fps, dup, drop, latency_ms, latency_max_ms}},
encoder[{output, skipped, bitrate, frames, dropped, disk_free_mb, reconnects, connections, state}],
display[{output, kind, frames, dropped, undelivered, state}],
audio{dropouts, underruns, discontinuities, meters{buses[{bus, peak_db, rms_db, true_peak_db, lufs_m, lufs_s, lufs_i, lra}], inputs{n: {peak_db, rms_db}}}},
rss_mb, cpu_pct, gpu_pct
```

- 计数类字段全是自启动累计，相邻两行相减得窗口增量；`fps` = 窗口内该输入推入帧数 / 秒；`bitrate` = 窗口平均 bit/s；`ts` = Unix 秒。
- `jitter_ms` = 渲染线程唤醒时刻 − 理想拍点的每秒最大值；`gpu_pct` = IOKit Device Utilization。
- `encoder[].output` / `display[].output` = 该项对应输出在节目输出表里的编号（0 = 填数方没给；主界面监视器不是输出，用 0）；读的一方按它对号。
- `encoder[].state`：录制 idle / recording / stopping / stopped / failed；推流 idle / connecting / publishing / backoff / stopping / stopped / failed；
  NDI publishing / idle / unavailable（SDK 不在）/ failed（SDK 在但起不来）。
- `display[]`：显示类输出各一项，`kind` ∈ externalDisplay / virtualCamera / multiviewWindow / monitor；`dropped` = 在呈现 / 发布时没赶上的帧，
  `undelivered` = 不在呈现 / 发布（显示器不在、扩展没连上、窗口收起）时没送出去的帧，两者不重叠；`state` ∈ idle / presenting / noDisplay / waitingExtension / publishing / stopped / failed。
- `rms_db` = 推子后 300 ms 一阶平均的均方根 dBFS，dB / LUFS 下限 −120。
- 老文件缺键 = 0 / "idle" / 空数组，写出总是写全。

## 8. 引用的外部标准

| 标准 | 用在哪 |
|---|---|
| ITU-R BT.1359-1 | A/V 偏移可察觉阈值 +45 / −125 ms，可接受阈值 +90 / −185 ms（音频超前为正）。本标准的 A2 阈值比它严得多，是为了整条链路加起来仍在里面 |
| EBU R37 | 广播出口 +40 / −60 ms；ATSC IS-191 更严，编码器入口 +15 / −45 ms。作为 A2 的外部对照 |
| ITU-R BS.1770、EBU R128、EBU Tech 3341 / 3342 | 响度和真峰值表的算法与测试信号（A6） |
| ITU-R BT.709 | 色彩矩阵和电平范围（V9） |
| 通行的三类丢帧口径 | 渲染滞后、编码滞后、网络丢帧的定义（V2、E1、E9），方便和用户熟悉的数字对照 |
