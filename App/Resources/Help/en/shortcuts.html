Shortcuts, MIDI and control panels

Every control path sends the same commands (Concepts › How a switch happens), so keyboard, MIDI, Stream Deck, Companion and scripts can be mixed freely and always agree on the state.

Default shortcut table

Active while the main window is in front (not while typing in a text field); also while the Settings, Input Settings, Overlay Settings or Audio Settings windows are in front (while Settings › Shortcuts is recording a key, the key goes into that row and switches nothing). Not while the Statistics window, the Stream / Recording Status window or the multiview window is in front: click the main window, then press the key.

KeyAction
1 … 9, 0Put input 1–10 on PVW (0 = input 10)
⇧1 … ⇧0Cut input 1–10 straight to PGM (PVW unchanged)
SpaceCut
ReturnRun the current transition slot (the T-bar uses it too; Transition 1 · Fade 0.5 s in a new show)

⌥1 … ⌥4Run Transition 1–4 (selects that slot and starts it at once; Return and the T-bar use it afterwards; Concepts › Transition slots)

  • Recording and streaming have no default keys: stopping them from a hotkey never asks, so one stray key would stop the show. Add them yourself if you want (Editing the table), e.g. with "All recordings on / off".
  • The interface lock has no default shortcut: use the lock at the far right of the bottom bar, or Window › Lock Interface.
  • On a Mac that saved a shortcut table before (hotkeys.json), ⌥1–⌥4 are still "Run Current Transition" from the old table (that is how the old default table was saved; it isn't upgraded automatically): click "Reset to Defaults" in Settings › Shortcuts for the new table (re-add your own rows afterwards).
  • ⌃1–⌃4 are also the system's "Switch to Desktop 1–4": if those are turned on in System Settings › Keyboard › Keyboard Shortcuts › Mission Control, the system takes these keys first. ⌥1–⌥4 are not used by the system.
  • Help › Keyboard Shortcuts generates a page from the current table (key / action / note) and opens it in your browser — handy to print for the desk; after editing the table, click it again for the new version.

Menu shortcuts (standard AppKit): ⌘N new, ⌘O open, ⌘S save, ⇧⌘S save as, ⌘I add input, ⇧⌘I input settings (the input on PVW), ⌘F find input, ⌘, settings, ⌘M minimize, ⌘Q quit (asks first while recording / streaming or with unsaved changes). The grey keys on the right of the Transition menu come from the shortcut table and are display only — keys are handled by the shortcut table, and the menu follows when you change it.

Editing the table

Settings › Shortcuts (PlusMix › Shortcuts…): one row per binding — Enabled (checkbox), key combination (type it, or click "Record" and press it), action (a one-line summary; click it for the action picker), note, and "Edit JSON… / Duplicate / Remove" at the end of the row.

  • A search field at the top (finds keys, actions and notes); "Add", "Reset to Defaults" and "Save" at the bottom. "Duplicate" inserts a copy of the row below with the key left empty for you to record.
  • Binding the same combination twice among enabled rows shows "n conflicts" next to Save and the table can't be saved; disabled rows are not dispatched and don't count as conflicts.
  • A new row has no action and must get one before saving ("Row n has no action yet") — it never silently becomes some other command.
  • Click "Save" when done; with unsaved changes, closing the window or switching pages asks "Save / Cancel / Discard Changes". The page shows where the table file is.
  • "Edit JSON…": write one command directly (the top-level key is the command name, the same form as the HTTP API's command); it is checked when applied, and a recognised command turns back into the matching action.

The action picker

Opens from a row's action button:

  • A search field at the top (you can type straight away; it searches action names, descriptions and API key names across groups); groups on the left: Switching / Overlays / Audio / Outputs / Inputs / Show / Interface / All / Recent.
  • One line per action on the right: our name, a one-line description and the API key name in small print (compound actions list what they send, e.g. "previewAndTransition → setPreview + autoTransition").
  • Below it a form built from the action's parameters: an input is a menu ("Input 3 “name”") plus "Current PVW / Current PGM" (whatever is on PVW / PGM at the moment of the press); durations are in seconds (0.5 / 1 / 2 + custom); overlay channels 1–4; a transition slot is a menu listing the four slots' current effect and duration ("Transition 3 · Zoom 1 s"); outputs only list the kinds that fit; one of the four buses; switches have three segments: on / off / toggle; optional switches (solo and "Audio follows video" in "Input solo / AFV / routing") have three segments "Keep / On / Off", "Keep" by default; for bus routing, tick "Change bus routing" first, then the buses it feeds (Master / Bus A / Bus B / Headphones) — unticked = routing unchanged.
  • At the bottom "What a press sends now:" — the commands computed from the current show, exactly what goes onto the command bus when the key is pressed.
  • By default only operator actions are listed. Whole-replacement commands (show / input settings / output settings) and adding / removing inputs and outputs need "Show whole-replacement commands (advanced)" or "Advanced: Write JSON…" (checked before saving).

hotkeys.json

The table is stored outside the show file in ~/Library/Application Support/PlusMix/hotkeys.json (it doesn't change with the show):

{
  "version": 1,
  "bindings": [
    {"key": "1", "action": {"command": {"setPreview": {"input": 1}}}, "note": "PVW input 1"},
    {"key": "shift+1", "action": {"command": {"setProgram": {"input": 1}}}, "note": "PGM input 1"},
    {"key": "space", "action": {"command": {"cut": {}}}, "note": "Cut"},
    {"key": "return", "action": {"command": {"autoTransition": {}}}},
    {"key": "f", "action": {"toggleFTB": {}}},
    {"key": "alt+2", "action": {"transitionSlot": {"slot": 2}}, "note": "run transition 2"},
    {"key": "alt+shift+4", "action": {"selectTransitionSlot": {"slot": 4}}, "note": "select transition 4, don't run"},
    {"key": "ctrl+1", "action": {"toggleOverlay": {"channel": 1}}, "note": "overlay 1 on / off"},
    {"key": "g", "action": {"fadeMs": {"durationMs": 750}}, "note": "0.75 s fade"},
    {"key": "alt+shift+3", "action": {"previewAndTransition": {"input": 3}}},
    {"key": "m", "action": {"ui": {"name": "toggleMixer"}}, "note": "show / hide the mixer"},
    {"key": "cmd+alt+r", "action": {"recordAll": {"mode": "toggle"}}, "note": "all recordings (never asks)", "enabled": false}
  ]
}
  • Combination syntax ctrl+alt+shift+cmd+<key> in any order; ⌘⌥⌃⇧ prefixes and the long names command / option / control are accepted. The key is a single letter / digit / symbol or a named key: space, return, escape, tab, delete, forwarddelete, up, down, left, right, home, end, pageup, pagedown, f1 … f20.
  • Actions: {"command": {<command>}} (command JSON is the API's, API reference (repository: docs/api.md), Chinese), or the switch / compound actions below. A switch's mode is "on" / "off" / "toggle" (missing = toggle); an input can be a number or "preview" / "program" (whatever is on PVW / PGM at the moment of the press).
  • "enabled": false is written only on disabled rows; no key = enabled. Old files load unchanged.
  • An unreadable file (bad JSON, conflicts) falls back to the default table with a notice in the status line.

MIDI

Settings › MIDI (PlusMix › MIDI Mapping…): CoreMIDI; all online devices are listened to and the page lists the current MIDI sources. One row per mapping: Enabled, trigger (Note / CC / 14-bit CC, channel, number), "Learn" (fills the trigger from the next fader move or key press), action (the same action picker), note. It also has search, Add, Duplicate, Remove and Edit JSON…; click "Save" when done.

TriggerActions it takes
CC (7-bit, channel 1–16, controller 0–127)Faders only: T-bar (commits at either end and reverses, like a real lever), input gain fader, bus gain fader (0–127 mapped linearly to a dB range)
14-bit CC (controller 0–31 coarse, +32 fine)Same, with a smoother fader
Note (on, velocity > 0)Button actions: the same as shortcuts (commands, switches, compound and interface actions)

Saving checks that every action fits its trigger (Notes take button actions, CCs take faders); otherwise it says "Mapping n's action doesn't fit its trigger" and doesn't save. The map is stored in ~/Library/Application Support/PlusMix/midi.json:

{
  "version": 1,
  "mappings": [
    {"trigger": {"cc14": {"channel": 1, "controller": 1}}, "action": {"tbar": {}}, "note": "fader"},
    {"trigger": {"cc": {"channel": 1, "controller": 7}}, "action": {"busGain": {"bus": 0, "minDb": -60, "maxDb": 0}}},
    {"trigger": {"cc": {"channel": 1, "controller": 16}}, "action": {"inputGain": {"input": 1, "minDb": -60, "maxDb": 12}}},
    {"trigger": {"note": {"channel": 1, "note": 60}}, "action": {"action": {"command": {"cut": {}}}}},
    {"trigger": {"note": {"channel": 1, "note": 61}}, "action": {"action": {"toggleFTB": {}}}}
  ]
}

Inside a Note's "action": {"action": …} goes an action written exactly as in hotkeys.json above. The default map is empty (no factory mappings; restoring defaults empties it); an unreadable midi.json also falls back to the empty map, without a notice. Devices unplugged and plugged back are picked up again; devices connected while the app runs are discovered too.

Stream Deck, Companion, tally, scripts

  • Stream Deck: official-SDK plugin (button = command, button colour = tally; the "Transition 1–4" button runs or just selects a slot and is coloured after the current slot); install and button table in docs/integrations/stream-deck.md (Chinese).
  • Bitfocus Companion: via the local API (Generic HTTP / WebSocket modules) in API examples (repository: docs/api/examples.md); via the third-party compatibility layer with an existing panel configuration in docs/integrations/companion.md. When Companion runs on another machine, set the compatibility layer to "Allow local network" in Settings › Remote Control, apply and restart the engine, and enter the address shown on that page in Companion.
  • External tally lights: a read-only WebSocket / HTTP tally stream, turned on in Settings › Tally (off by default, port 8766 by default), which shows addresses ready to copy; protocol in docs/integrations/tally.md. The local API's GET /api/v1/tally works too.
  • Scripts / automation: the local HTTP + WebSocket API, docs/api/README.md. It listens on 127.0.0.1:8765 by default; Settings › Remote Control switches between "This Mac only / Allow local network" and sets the port and token.
