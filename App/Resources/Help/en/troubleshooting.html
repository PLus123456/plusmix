Troubleshooting

Look in three places first: the one-line message on an input cell (that input's own state, Inputs › Input states), the tooltip of the Record / Stream buttons in the bottom bar (every route's state and why it couldn't start) together with the Stream / Recording Status window (each route's last error and its drops and reconnects), and the notices / reminders at the right of the status line (outputs and system-level events). Cells in error and outputs that couldn't start name the cause and the next step; a "No signal" cell doesn't say what it is waiting for — go through §2. This page groups them by symptom. Input messages come from the engine and are in Chinese in this version; below they are quoted in Chinese with an English gloss.

3. Disk

Status lineBehaviour
"Recording n: x MB free on disk"Warning below 1 GB; still recording
"Recording n: x MB free on disk, below the 200 MB minimum"Without a fallback folder: only that recording stops; streaming and rendering continue. Change the minimum in Settings › Advanced › Free space minimum (or with the launch argument --record-min-free-mb)
"Recording n: disk full (…)"Full: written fragments are kept, that recording stops
"Recording n: disk full, switched to the fallback directory: <file name>"With a fallback folder (Settings › Advanced, or --record-fallback), running full or dropping below the minimum both continue recording there — below the minimum it says the same, although the disk isn't actually full
"Recording n failed to start: …"Folder not writable / missing; fixing the folder retries automatically
"ISO input n does not exist or has no free branch (at most 4 ISO / Aux per input)"The input being ISO-recorded is gone, or it already feeds 4 ISO recordings / Aux uses (external displays and NDI® outputs showing that input): remove some and record again
"Recording n failed to finalize: …"Writing the index at stop failed; the fragmented .mov stays playable
Record in the bottom bar records nothing; notice "No route takes part in recording"Every recording's "Take part in recording" is off, or the PGM row on the ISO page is unchecked and no input is checked: turn on the routes you want

Free space is measured on the recording's own volume. A killed process recovers the .mov up to the last 1 s fragment (E6 allows at most 2 s loss).

4. Streaming

Bottom bar / Streaming page / API stateMeaning
"Stream · Connecting", "Connecting (attempt n)" (the API's state alternates between connecting and backoff; it is backoff while waiting for the next attempt)Never connected yet: server unreachable, wrong address or path. A local MediaMTX only accepts the paths in its configuration (the repository's scripts/mediamtx.yml has s1 / s2 / s3 / srt1, with an empty key); any other path stays connecting. The destination is locked while its switch is on: turn it off before fixing the URL
"Stream · Reconnecting (attempt n)" (state alternates between connecting / backoff too)Was live, then dropped: exponential back-off, retrying forever; the wait between attempts is capped by "Max retry interval n s" (30 s by default); resumes with a keyframe
"Stream · 1 in trouble" (dark red), tooltip "Stream n failed to start: …" / failedCouldn't start: unknown scheme (only rtmp / rtmps / srt), malformed address, no server. The destination's section on the Streaming page shows the reason: fix the URL (Return or leave the field) and it retries automatically, or "Turn Off This Destination"; healthy destinations are not affected, and the main Stream button only retries the ones that couldn't start
"Stream n has no URL"Empty address in the output settings
Stays "Connecting (attempt n)"; the status window's "Last error" says "鉴权失败…" (authentication failed; the same line is in the system log)The user name / password in "Authentication…" on the Streaming page is wrong; in this version it keeps retrying with back-off. The destination is locked while its switch is on: turn it off, correct it, turn it on again
"Authentication…" filled in, connects, rejected as soon as it starts publishing (last error / log: NetStream.Publish.Unauthorized)The server (MediaMTX, SRS, nginx-rtmp and the like) wants a query string after the URL: turn the switch off and in "Authentication…" set "Method" to "Query string (?user=&pass=)", with the parameter names your server expects (Outputs › Stream authentication)
The last error / system log says "鉴权方式不支持：…" (method not supported)The server wants an authentication method this version doesn't support
You want to know how often and when a stream dropped, and whyThe Stream / Recording Status window: the Disconnects / Reconnects columns count them, and the events list "Disconnected: reason → Reconnecting (attempt n) → Reconnected" with times
SRT with a passphrase doesn't connectThe passphrase may only use letters, digits and - . _ ~, 10–79 characters
Frames increase but the player shows nothingCheck stats.encoder[].dropped (network drops): non-keyframes are dropped first when bandwidth is short; lower the bitrate (a lower "Quality" on the Streaming page); keep "Total upload" at the bottom of the page under half your upload bandwidth
Local MediaMTX receives no SRTIts SRT port must bind IPv4 (srtAddress: 0.0.0.0:8890; the repository's scripts/mediamtx.yml already does); RTMP is unaffected

6. Picture and sound

SymptomWhat to check
Status line "Dropped" (missed_render) increasingRendering missed ticks. Usual causes: another app saturating the GPU, thermal throttling, a covered multiview window lowering the refresh. On an idle machine it stays 0
Frames start dropping after nobody touched the Mac for a whileWhen the user is "idle" macOS delays real-time thread wake-ups. While the engine runs PlusMix itself prevents system sleep, App Nap and display sleep (Settings › Performance & Power, both on by default), so normally nothing else is needed. Unattended runs with the lid closed or the screen locked should still run caffeinate -u -i -d -s as well: the app can't prevent sleep on lid-close or a manual lock, and can't declare "user is active" the way -u does
Audio and video out of syncInput Settings › Audio › Audio delay compensation (0–500 ms) for the capture device's own offset; the engine's alignment delay (default 2048 frames = 42.7 ms) is in Settings › Show Audio and takes effect only after "Apply and Restart Engine" (which stops recording / streaming; it asks first)
With a compressor / limiter on Master, the whole picture (monitors, external displays, multiview) runs a few tens of milliseconds lateExpected (monitor sync): the picture is delayed by Master's effect latency (5–35 ms), so speakers / headphones match it; recording / streaming / NDI® follow the same timeline. The status window shows "Video delayed n ms" at the bottom
With a compressor / limiter on Bus A / B, the channels they feed are slightly behind the pictureThe picture follows Master's delay only; the extra delay of Bus A / B is not compensated (this only affects what those two buses send to device channels)
Changing an input's audio effects makes no audible differencePer-input effects do work: check whether "Enabled" is off (= bypassed); an input's Limiter has no effect (only buses get a limiter); a second compressor in the same chain is not installed; EQ bands beyond 16 written through the API are not installed
Sound stays after cutting away / no sound after cutting inFirst the AFV master switch in the mixer header: off by default in a new show, and while it is off no input's "Follow video" has any effect. With it on, check that input's "Follow video": off = always audible, on = only on PGM
The headphones play Master; inputs sent to H can't be heardIn this version the headphone output normally carries Master and switches to the headphone bus (the soloed inputs) only while something is soloed; the Listen menu (headphones icon on the Master strip) isn't wired up yet, Master / Bus A / B are greyed out
While soloing, headphones are ahead of the pictureThe solo monitor point defaults to before the alignment delay (low latency); to align with the picture choose "After the delay line" in Settings › Show Audio › Headphone monitor point, then "Apply and Restart Engine"
Solo / PFL / AFL silent, the mixer header says "This device has no headphone channels"The output device has only 2 channels and Master uses them: turn on "Use the Master channels while monitoring" in Settings › Audio Devices (while soloing, the speakers / headphones play the soloed inputs; applies immediately), or pick a multichannel device and give the headphones a channel pair
No sound from Bus A / BGive Bus A / B a channel pair in Settings › Audio Devices (needs a multichannel device), then Apply and Restart Engine
Reminder "For 30 seconds the Master level has stayed below −50 dBFS (is the mic on?)"Check whether the microphone input is muted, its fader, whether it feeds Master, and whether "Follow video" keeps it out
"Audio device "…" unavailable (…); using the null device"Device unplugged or held exclusively by another app: reselect in Settings › Audio Devices; with the null device picture, recording and streaming keep their audio, only local playback is silent

9. Logs and diagnostics

  • Help › Export Diagnostics…: settings (without the API token), the last second of statistics, the show file with stream keys removed, the shortcut / MIDI tables and system information; with your consent also crash diagnostics and the last two hours of logs. It is saved where you choose in the save panel and selected in Finder afterwards; you can open and check it before sending it. Help › Show Diagnostics Folder opens ~/Library/Application Support/PlusMix/Diagnostics, which holds the crash / hang and other diagnostic records macOS hands over (crash-….json, hang-….json and so on; the latest 100 are kept), not the exported bundles; "Show Logs…" in the Stream / Recording Status window opens the same folder (the streaming / recording logs are not in it — see the system log below).
  • Notices from the engine (recording, streaming, NDI® output, external displays, virtual camera and the like) also go to the system log; notices raised by the bottom bar itself (e.g. "No route takes part in recording…", "Transition in progress…") don't. The last 10 minutes (the full path /usr/bin/log works everywhere: a plain log is fine in Terminal, but in scripts or non-interactive zsh it hits zsh's own built-in of the same name and fails with "too many arguments"):
/usr/bin/log show --predicate 'process == "PlusMix"' --last 10m --style compact
  • One statistics line per second (stats.jsonl, fields in test standard §7 (repository: docs/testing/测试标准.md), Chinese): launch with --stats <file>, or read stats from GET /api/v1/state; the statistics window shows the same data. Attach it when reporting a problem.
  • Reproducing with the headless engine is often easier: switcher-headless run --show <show> --duration 60 --stats /tmp/stats.jsonl (Samples (repository: Samples/README.md), Chinese).
