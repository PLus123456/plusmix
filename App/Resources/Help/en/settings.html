Settings

All settings live in one "Settings" window. Every way in opens that same window:

  • ⌘,, PlusMix › Settings…, and the main Settings button in the toolbar: back to the page you looked at last ("General" the first time).
  • Settings▾ in the toolbar and PlusMix › All Settings Pages ▸: straight to a page; PlusMix › Shortcuts… / MIDI Mapping… go straight to those two.
  • The settings pages listed in the Output menu and the ⚙ of Stream / Multiview in the bottom bar: straight to that output page; the ⚙ of Record / External Display first opens a small menu (Recording Settings… / ISO Recording…; External Display Settings… / NDI® Output Settings…).

The sidebar has two groups; each page's header says where it is stored:

When changes take effect

  • Most changes apply immediately: changes on the output pages go to the engine right away (a stream destination that is live locks its URL and encoding, see Outputs › Streaming); changes on the This Mac pages are stored right away.
  • Settings that only take effect with a new engine (show format, show audio, audio device and each bus's channel pair, local API, compatibility layer, preview all overlays in PVW) are tagged "Restarts engine". A change is kept as pending; the bottom of the window says "n pending: …". "Apply and Restart Engine" at the bottom applies them all at once (while recording / streaming runs it first asks "… will stop n recording(s), m stream(s)"; Cancel changes nothing). Changing a value back removes it from the pending list. The window stays open on the same page after the restart. If you don't click it: the This-Mac items (audio device, local API, compatibility layer, preview all overlays in PVW) are already stored and apply the next time the engine starts (New, Open, reopening the app); pending Show Format and Show Audio changes are lost unless applied — closing the Settings window or creating / opening a show re-reads those two pages from the show.
  • The Shortcuts and MIDI pages need Save: the table is checked as a whole (conflicts, unrecognised keys) before saving. With unsaved changes, closing the window or switching pages asks "Save / Cancel / Discard Changes"; if it can't be saved (a conflict) the window stays and the error is shown under the table.

Audio Devices

  • Device: System default (follows changes) / Null device (silent) / the listed output devices. With the null device picture, recording and streaming carry on with sound; only local playback is silent.
  • Which two channels each bus goes to: Master, Bus A, Bus B and Headphones each pick a channel pair (1/2, 3/4, …) or "Off". Two buses can't share a pair: picking a pair another bus uses switches that bus to "Off" and says so. Changing the device only drops the pairs the new device doesn't have; "Restore device defaults" goes back to the device's default assignment. Recording / streaming / NDI® use Master itself and are not affected by this. The pair given to "Headphones" normally carries the bus picked in the Listen menu (Master in a new show), and the soloed inputs while something is soloed in the mixer ("Headphone output" in Concepts › Audio).
  • 2-channel devices (built-in speakers, plain USB headsets): both channels go to Master, so this page and the mixer header say "This device has no headphone channels" — solo / PFL / AFL live on the headphone bus, which has no channels of its own. The page then offers "Use the Master channels while monitoring" (off by default): when on, these two channels carry the headphone bus (only the soloed inputs) while something is soloed in the mixer, back to Master when solo is off; recording / streaming / NDI® keep getting Master. The switch applies immediately, no engine restart. With it off, solo can't be heard (the speakers keep playing Master).
  • A device change, or changing only a bus's channel pair, is pending and applies with "Apply and Restart Engine" ("Use the Master channels while monitoring" applies at once and doesn't count).

  • The yellow warnings on the page: when the local API allows the local network without a token, "The local network is allowed but no token is set: anyone on the same network can switch the program or stop recordings. Set a token."; whenever the local API allows the local network (token or not) one more line, "The token and the whole state travel as plain HTTP / WebSocket (no TLS): only allow the local network on a network you trust."; and when the compatibility layer allows the local network, that it has no authentication and anyone on the network can control it. Changes need "Apply and Restart Engine".
  • In the state the API hands out, stream keys and passwords in stream URLs are masked (<redacted>); the originals need a token and ?secrets=1 on the request. Web pages (browsers) are refused by the local API and by the compatibility layer's HTTP entry (there is no setting for an allow-list in this version); Stream Deck, Companion, curl and scripts are not affected. Details in local API §1 (repository: docs/api/README.md) (Chinese).
  • "This Mac only, and a token if you open it to the network" is still the advice: the API can change anything (switch the program, stop recordings, change a stream URL).
  • "Change Listen Addresses… (Advanced)" at the bottom jumps to the Advanced page, where a specific host:port can be typed.
  • The first time PlusMix listens on the local network (Allow local network, or the tally stream), macOS asks "Allow incoming connections" if the firewall is on; click Allow.

Tally

"Provide the read-only tally stream" (off by default): for tally lights / prompter displays on the local network; a frame on every PGM / PVW change, and nothing a client sends is treated as a command.

  • Port: unless set separately = the local API port + 1 (8766). When on it listens on the local network (0.0.0.0).
  • Two read-only addresses with "Copy": WebSocket ws://<this Mac's LAN IP>:8766/tally and HTTP polling http://<this Mac's LAN IP>:8766/tally; below them the current number of connections.
  • The switch and port apply immediately, no engine restart; if it can't start (port in use) the status line says so. Protocol in docs/integrations/tally.md (Chinese).

Performance & Power

  • "Prevent system sleep and App Nap while the engine runs" and "Prevent display sleep while the engine runs": both on by default, apply immediately. While the engine runs PlusMix holds these two power assertions itself and releases them when the engine stops (quitting, between shows); a line on the page shows the current state. They can't prevent sleep when the lid is closed or the screen is locked manually: for unattended runs with the lid closed or the screen locked, still run caffeinate -u -i -d -s as well (see Troubleshooting › Picture and sound).
  • Read-only information about this machine: model, chip, memory, GPU, system.

Updates & Diagnostics

  • Updates: signed and notarised release builds check once a day ("Check for updates automatically" can be turned off) and "Check for Updates…" checks now; development / unsigned builds have no update feed and this section is greyed out.
  • Export Diagnostics…: same as Help › Export Diagnostics…; attach it when reporting a problem (Troubleshooting › Logs and diagnostics).

Launch arguments

When starting the app from a terminal (open PlusMix.app --args …, or running PlusMix.app/Contents/MacOS/PlusMix … directly). Launch arguments only apply to that run and are not stored as this Mac's settings; whatever you change in the Settings window during that run is stored as usual, only the item you changed: if only half of a listen address changes (say just "This Mac only / Allow local network"), the other half is taken from what this Mac had stored, not from --api-listen (this run's value is used only if this Mac never stored one); if that change opens the API to the network (turning the API on, or a non-local address) while the page shows a token from --api-token, the token is stored too — so a later launch without arguments isn't an unauthenticated API on the local network:

ArgumentEffect
--show <file>Open this show file (instead of restoring the last one)
--stats <file>Write one statistics line per second to this file (stats.jsonl)
--audio-device <name / default / null>Audio output device; null = the null device
--api-listen <host:port>, --api-token <token>, --no-apiLocal API address, token, or turn it off
--record-min-free-mb <MB>, --record-fallback <folder>Recording free-space minimum (an integer, clamped to 0–16777216 as on the settings page; anything that isn't an integer is ignored), fallback folder
--tally-port <port>Turn on the read-only tally stream on this port (same name as in the headless engine)
