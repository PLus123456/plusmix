## 10. 下一个会话需要知道的坑

1. **zsh 不给 `$var` 分词，这次是 `-only-testing` 整串**：十个类名放在一个变量里传给脚本 / xcodebuild，`"-only-testing:SwitcherTests/A B C …"` 成了一个参数，xcodebuild **`** TEST EXECUTE SUCCEEDED **`、`Executed 0 tests`、退出码 0**——按退出码看是绿的、其实一条没跑；xcresult 的 `totalTestCount` 也是 0。判 App 用例一律数 `Executed N tests` / 每条 `Test Case … passed`，zsh 里用 `${=var}` 分词（G8 / G12 §10 都记过，换个样子又撞）。
2. **`swift test --filter` 只选中一个测试包时，日志末尾的 `Executed 0 tests` 是别的包的那行**（P5-5 §5 第 6 条）：看 `tail` 会误以为筛选没命中；要 `grep Executed` 看全部，或按 `Test Suite '<类名>' passed` 找。
3. **`swift test` 的 stdout 有缓冲、"Test Case … started" 行比实际早**：Outputs 整包时日志停在 `RecorderFirstAudioTests` 某条"started"十分钟没动、xctest 0% CPU（`ps` 的 %cpu 是进程生命期均值，也骗人），`sample <pid>` 一看主线程在 `RecorderTests.testE5_normalStop20Times_fileIntegrity` 的 `PatternFeeder.feed`（`.fastest` 自旋背压 + debug 帧生成 + 同机 xcodebuild 在编）。判卡死用 `sample`，别看日志时间。
