## 10. 下一个会话需要知道的坑

1. **冷缓存的 worktree 第一轮很慢、而且 lint 会和包测试抢编译**：本 worktree 没有 .build，Core 整包 9 min / Audio 8 min / App build-for-testing 1 分钟（包已由 swift test 编过一轮，xcodebuild 自己的 DerivedData 冷编 64 s）；第一次 `make lint` 跑了 5 分钟以上被工具挪到后台——`check-rt-symbols` 要编 CSwitcherAudioRT、`check-deps` 要 `swift package dump-package`，与后台 `swift test` 同时起会互相等。lint 等包测试退了再跑（或先跑 lint 再起包测试）。
2. **链式预演这次 0 冲突、没有任何文件被两路同时改**（`git diff --name-only main..<各路> | sort | uniq -d` 为空）——四路都从同一个 2ec2c05 开、之后 main 没动。下次 main 若在会话期间又动了（像 G9 → G10 那次往提案文末追加），预演一定在最新 main 上重做（G10 §10 第 1 条）。
3. **123 §5 的三个法子都好用**：macOS 没有 `timeout`，会崩 / 卡的探针用 `perl -e 'alarm N; exec @ARGV' swift test …`；修前的树另起 detached worktree（`git worktree add --detach <scratchpad>/x <提交>`），不要在本 worktree 里 stash（栈是所有工作树共用的）；`swift test --filter` 可以写多个 `--filter`（并集），只选中一个测试包时另一个包也打 `Executed 0 tests`、别 `tail -1` 取数。
4. **125 §5**：离线台里第 t 拍的事件在"块尾 ≥ 第 t − 1 拍"那一块到，两次切换隔 1–3 拍时第二条到的那一刻第一条一定还没开始（测"正在走"那一相要按 b mod 8 挑起始拍）；同一个用例里 XCTest 没记全失败（逐样本判据先收集、最后断言一次）；"满 = 与 ISO 逐样本相同"只在淡变走满之后成立（一阶平滑停在 1 − 4.3e-6）；淡变表 8 格、60 fps 每拍按 Cut 最多约 5 条同时排、满了静默丢；快照比事件晚（按快照判"转场进行中"去发混音命令的要想清楚会不会盖掉事件路排好的）。
