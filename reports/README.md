# reports/ —— 会话报告与检查点报告

- `reports/<分支名>.md`：每个会话结束前必写（通用前言铁律 8），分支名里的 `/` 换成 `-`。固定五段：做了什么；每个测试 ID 的数值 / 阈值 / 通过否；没做的和原因；对契约的疑问；下一个会话需要知道的坑。
- `reports/G2.md` … `reports/G5.md`：检查点报告，按测试标准 §7 模板（版本 / 提交号、机器、场景、每个指标数值 · 阈值 · 通过否 · 与上一版本的差、崩溃日志 / Instruments / stats.jsonl 路径、已知问题与放行说明）。
- `reports/issues/`：检查点退回原会话的问题单，见那里的 README。
- 采集数据（`*.jsonl`、`*.trace`、`*.mov`）不入库（.gitignore），报告里写本机路径即可。

用户每次只看报告里的三块：测试表、BLOCKED 项、契约疑问（落地方案 §5）。
