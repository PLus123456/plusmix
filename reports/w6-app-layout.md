## 1. 做了什么

按方案 §2 的规则 1–10 做了主窗口新排布，规则的可执行版本是示意页脚本里的 `layout()` / `pickTier()`，照它写成 `App/Sources/UI/MainLayoutModel.swift`；
示意页里写死的尺寸全部换成从布局里量来的（中间那一列四档用 `fittingSize`、格子大小从输入条拿、调音台宽、头一行高……）。

| 交付 | 做法（文件） |
|---|---|
| 1 监看框 = 画面 | `MonitorView.canvasAspect`：画面区加宽高比约束（= 节目格式宽 : 高，换格式时 `applyCanvas` 更新），贴着标题条、等比放进框里，框外是窗口底色；旧排布 `nil` = 照旧铺满 |
| 2 横屏上 / 下 | 新容器 `MainLayoutView` 按 `MainLayoutModel` 摆（frame），不用 NSSplitView：上边 PVW ｜ 中间那一列 ｜ PGM 横贯窗口，下边一行"输入区 ｜ 调音台"同高；上半区高 = max(贴合高, 这一档的高)（`MainWindowController+Arrangement.swift`） |
| 3 输入区折行 | 输入条的 NSStackView 换成自己排格子的 `InputGridView`：新排布 `.wrap`（一行放不下折行、整块竖向滚动），旧排布 `.row`（一行横向滚动）；三档格子大小不变；`scrollToCell` 滚得到每一路 |
| 4 中间那一列四档 | `TransitionPanelView.ColumnTier`（全 / 不带时钟 / 紧凑 / 最小）+ `setTier` + `fittingHeight(of:)`（四档各摆一次量 `fittingSize`，存着；T-bar 下面那行提示出没时重量、通知主窗口重排）；选法 = `pickTier`；时钟收起时状态行右端小字时间（`StatusBarView.setClockShown`，HH:mm:ss，每秒对齐整秒）；设置 › 常规 › 显示 › 时钟：自动 / 一直显示 / 不显示（存本机，`MainLayoutPreferences`） |
| 5 很宽的画布叠放 | 同一个算法里的叠放分支：PVW 在上、PGM 在下、中间那一列挪到右边；三成门槛、"并排空得超过 24 而叠放更大"、叠放时下边一行至少留两行，都照示意页 |
| 6 竖屏排法 | 监看占满左边整个高度（右边一栏不够 346 时监看让一点），右边一栏输入区在上、调音台在下、同宽，调音台高 240–380；输入格子换成竖的小格 = 缩略图第四档"紧凑"（`ThumbnailSize.compact`，宽 72，标题条 18 + 和画布同形状的缩略图，两行按钮藏起来、动作都在右键菜单里，点 = 选 PVW、⇧ 点 = 直切），横屏也能选；竖屏固定用它（`InputStripView.forcesCompact`），偏好里那一档留给横屏 |
| 7 调音台高度跟着位置走 | `MixerPanelView.adaptiveHeight`：推子 `.frame(minHeight: 60, idealHeight: 60, maxHeight: .infinity)`，整条放得下用整条、放不下用紧凑条（`ViewThatFits`）；紧凑条把声像 / 总线送出 / 跟随视频收进齿轮菜单（总线条收 LUFS / 效果 / 监听 / 响度详情）；收起的组条与分隔线改按可用高度；旧排布照旧推子 170 |
| 8 节目格式页 | 分辨率预设加 1080×1920、720×1280、2160×3840；"横 ⇄ 竖"按钮（换完是预设或还在自定义范围里才让换） |
| 9 旧排布开关 | 窗口 › 排布 ▸ 新排布（默认）/ 旧排布，存本机；旧排布 = 原来那套 NSSplitView，换排布时五块视图在两个容器之间搬，调音台开没开着带过去 |
| 10 旧用例改口径 | 见 §2.4，阈值一个没动 |
| 11 截图 | `App/Tools/layout-shots.sh` + `App/Sources/UI/LayoutShotTour.swift`，见 §2.5 |

另外几处：
- 分隔条（规则 7）：上下之间往上拖让下边一行更高、监看等比变小居中，往下最多拖到贴合高（拖到底 = 按规则排、不存位置），最矮那一档要放得下；输入 ｜ 调音台之间往左拖调音台变宽（宽度存本机）、不窄于 340、拖过 340 的一半收起（同旧排布 NSSplitView 拖到底收起）。竖屏的两条线不拖（§4 第 5 条）。

- `AppTest.freshSession()` 每条用例开头清排布偏好（新排布、时钟自动、按规则排）。

## 4. 对契约的疑问 / 拿不准、等用户定的

没改契约，也没有要停下来的提案。下面是方案定的数、或 prompt 没写死的地方，我照方案 / 示意页做了，量出来和方案不同的照实写，都等检查点 1 / 用户定：

1. **格子高随画布比例变，宽画布的表和方案不同**（§2.2）。方案按"中档格子 153 高"算了三张表，实际缩略图框按多画面格子裁切后的比例（W5-H / V-23），20.5:9 是 130、48:9 和 32:9 是 120。结果对用户是好事（露得更多、宽墙的监看更大），但表里有 9 格对不上。要不要让新排布里的格子统一按 16:9 的框（宽画布时缩略图上下留黑边、和方案表一致）？我没改，等定。
2. **32:9 配最小窗口那处例外在真机上没有了。** 方案写"并排、空 69"，实测叠放、空 0（格子 120 高之后，叠放比并排大、并排又空得超过 24，规则 10 第二句就换了）。prompt 让"按方案写明的 69 断言"——我断言在抄本（方案常数）上，App 的断言是"和抄本喂量出来的常数一致"。
3. **三成门槛没有滞回。** 规则是无状态的（同一尺寸结果相同），压线时会来回跳。示意页算法自己（方案常数）在 3840×1080、对角拉大时在 1408–1420 和 1691–1694 两处来回跳了 5 次（面积比正好在 1.30 上下）；App 默认格子下对角 / 只拉宽都没复现（5760×1080 只拉宽时在 2240–2260 之间换一次，正常）。换大档格子、别的比例可能会碰上。要不要加"换过去要 ≥ 1.3、换回来要 < 1.15"这类滞回（那样就不再是"同一尺寸结果相同"）？

## 5. 下一个会话需要知道的坑

1. **新加的 Swift 文件要重新 `make gen`**（XcodeGen 生成工程时按目录枚举文件，生成物不入库）；不然编译报"找不到类型"。
2. **换节目格式 = 换 session。** 用例里 `AppTest.setCanvas(…)` 之后要用它返回的新 session，旧的那个已经停了（M3 第一次就栽在这：点小格后看的是旧 session 的 PVW）。
