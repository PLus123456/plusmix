# W3C2 → 下一个写 docs/checklists 的检查点：外接屏上的人工项（L2 秒表法、真插拔、Aux 原始画面）

来源：prompt 65"外接屏上的 L2（BLOCKED-硬件，人工步骤写进 docs/checklists 的下一版）"。docs/checklists/ 不归 W3-C2，步骤写在这里和报告 §2，由检查点抄进清单。
本机现在接着一块外接屏（LG ULTRAGEAR 2560×1440 144 Hz），**能自动化的已自动化**：`DisplayStatsTests.testExternal_realSecondDisplay_pgmAndAuxPresentWithoutDrops`
（PGM / Aux 窗口挪到外接屏全屏、按那块屏刷新、Aux 的 drawable = 外接屏像素尺寸、10 s 级别无掉帧）。下面是只能人做的。

## 1. L2 秒表法（测试标准 §3 L2；阈值 UVC ≤ 150 ms，扣掉设备后 ≤ 3 帧）

器材：外接显示器、UVC 摄像头、手机毫秒秒表、能 1/1000 s 快门的相机（或手机相机的专业模式）。
1. App 加一路摄像头输入（对着手机秒表），切到 PGM；输出菜单"外部输出 → 那块外接屏 → PGM"。
2. 相机同时框住手机秒表和外接屏，1/1000 s 快门拍一张，读两个读数之差 = 端到端延迟。连拍 5 次取中位数。
3. 扣除：同一台摄像头直连（系统自带相机 App 全屏放到同一块外接屏），同样拍 5 次取中位数 = 摄像头 + 显示器自身的延迟。
4. 记：中位数、扣除后的值、换算成帧（60 fps：÷ 16.7 ms）；再把第 1 步的源换成"外部输出 → 输入 n（Aux）"重复一遍（Aux 不经拍点与渲染器，预期更短；本会话没有量过，以实测为准）。

## 2. 真插拔（Stats.display[] 的 noDisplay / presenting）

1. 外部输出开在外接屏上（PGM）。App 的 Stats（API 或状态行）里这一项 state = presenting、frames 在涨、dropped 不涨。
2. 拔掉外接屏的线：窗口收起，state = noDisplay（设置里"显示器不在时退回主屏"关着 = 黑着等；开着 = 暂用主屏全屏，state 仍是 noDisplay）。
   这期间 **dropped 不应增加**（拔掉期间的帧不是"没赶上刷新"）。
3. 插回：几秒内窗口回到外接屏全屏，state = presenting，frames 继续涨，dropped 仍不涨。
4. 同样的步骤对"输入 n（Aux）"做一遍。

## 3. Aux = 原始画面、全分辨率（G4 裁定）

1. 一路 1080p（或 4K）摄像头 / 合成源，给它开抠像 / 裁切 / 变换；外部输出选"输入 n"。
2. 外接屏上看到的是**原始画面**（抠像、裁切、变换都不生效），清晰度与原始帧一致（对比同一路的多画面缩略格子：格子是 470×260 放大的，Aux 不是）。
3. 拔掉那路摄像头：几帧之内外接屏显示黑底"无信号"+ 左下角"编号  名字"（与缩略格子同一句文案）；插回恢复画面。

## 4. 主屏上不盖住主界面（包内选项，界面由 App 会话加开关后才可测）

外部输出开在主屏（带菜单栏那块）上，打开"不盖住主界面"：主窗口始终在外部输出上面，点外部输出窗口也不会翻上来；关掉恢复为盖满主屏在最前。外接屏上的外部输出不受这个开关影响。
