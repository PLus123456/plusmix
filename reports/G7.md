2. **冲突预演法**：真合之前 `git -c merge.conflictStyle=zdiff3 merge-tree --write-tree <ours> <theirs>` 拿到带冲突标记的树，解好的文件 `hash-object -w` + 临时 index `write-tree` + `commit-tree -p <ours> -p <theirs>` 造一个临时提交，再对它预演下一路——97 的 11 个文件、98 的 7 个文件都是跑第 5 / 6 轮时提前解好的，真合时逐字一致。解法脚本（strings-merge3.py 按键三路合、resolve-blocks.py 按块选、resolve-98.py）在本会话 scratchpad，不入库；下个检查点可以照写。
3. **strings 按键三路合**：行级 merge 会在相邻新键处冲突，按键合不会；要查的是"两边都改同一键"（这次只有 `addInput.image.hint`）、键集一致、无重复、`plutil -lint`。顺手写的 l10n-scan.py（冲突标记 / `L("…")` 引用的键都在表里 / 键集）比等 xcodebuild 快 6 分钟。
4. **从 main 开的那一路（95）是全部手工活的来源**：4 文件冲突 + 两处胶水 + 两处用例接口；叠分支的六路彼此 0 冲突。下一批并行开工请叠分支（§7.1 第 12 条）。
5. **git 自动合并会把一路对某文件的改动落进另一路重写后的结构里**（97 对 PreferencesModel 的改动大半自动落进 96 拆成页后的文件）——看起来对、实际留下重名（两个 `audioDevice`、两个 `MachineInfo`）或缺 import（`AnyCancellable`）；每合一路都要编一次，别只看冲突标记。
6. **胶水额度 50 行到 48**：check-ownership 把合并后另开的提交里的 +/− 都算（删 8 行也是 8），"删掉重复的一节"比"改名两处"贵；预算紧时先改名。
7. **测试宿主的共用 defaults suite**：98 之前别的 worktree 跑 R7 会把 `apiToken` 写进 `com.plusmix.switcher.tests`，当前会话的 API 用例 401；98 合入后 suite 按构建路径分开且不读存下来的 token。`$TMPDIR/switcher-tests/` 仍共用。
